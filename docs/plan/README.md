## 三个计划的依赖关系（顺序不能倒）

```
计划一（单端口同源） ──► 计划二（fnOS 套件） ──► 计划三（全原生化 S5 收尾）
        │                      │                        │
        │                      └─ 套件必须能托管 SPA      └─ 原生客户端只要 /api，
        └─ 让「一个服务项」成立                            CORS 因此才能整体移除
```

- **计划二强依赖计划一**：飞牛套件是「自带 Node 运行时 + 单端口托管 web/dist」的形态，
  服务端没有静态托管能力就做不出来（只能退化成把 nginx 也塞进包里的伪原生）。
- **计划三不强依赖前两个**，但**顺序上要放最后**：两端的 `platform/*`、Capacitor 依赖、
  `sync-hw.mjs` 这些「壳」代码只有在原生端落地后才能删；先删会让现有壳直接不可用。
- **计划一、二不依赖计划三**：中间任何时刻停下，Web 端都是完整可用的。
