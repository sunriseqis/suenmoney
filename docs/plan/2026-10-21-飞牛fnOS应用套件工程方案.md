# 计划二：飞牛私有云（fnOS）原生应用套件（.fpk）工程方案

> **状态**：已立项（2026-10-21），**未开工**。
> **口径（用户已拍板）**：**只做 x86_64**（与参考实现一致；ARM 机型本期不支持，见 R1）。
> **强前置**：**计划一必须已完成** —— 套件的前提是「服务端自己托管 `web/dist`、单端口全栈承载」。
> 没有它，套件只能把 nginx 一起塞进包里，那就是本方案明令禁止的**伪原生**。
> **参考实现**：`/home/suenmusic/fn/` + `scripts/build-fn.mjs`（已出过 fpk 并装机验证）。

---

## 一、定位与三条硬约束

1. **100% 原生运行，杜绝 Docker 伪应用**：不许把 `docker-compose.yml` 打进包再去拉镜像。
   套件是 Debian 12 上的**普通守护进程**，由飞牛应用中心托管生命周期。
2. **自包含零依赖**：包内自带 Node 运行时二进制（`app/bin/node`），宿主机不需要装 Node、
   不需要包管理器、不需要 C++ 编译工具链（本项目本来就只依赖 `node:sqlite` + 纯 JS）。
3. **数据只放 var，配置只放 etc，升级整替的 target 里不存任何业务数据**。
   这三句是飞牛套件的全部纪律，违反任何一条的后果都是「升级后账本没了」。

## 三、核心配置（suenmoney 版实值）

### 3.1 `manifest`

```ini
appname               = suenmoney
version               = 1.1.6            # 由构建脚本从根 VERSION 注入，不手改
display_name          = SuenMoney
desc                  = 家庭共用记账系统：只记支出，看月度/年度总额与构成
platform              = x86
os_min_version        = 1.1.0
source                = thirdparty
maintainer            = SuenMoney
distributor           = SuenMoney
desktop_uidir         = ui
desktop_applaunchname = suenmoney.Application
service_port          = 5310
checkport             = true
ctl_stop              = true
```

> **不要写 `arch = x86_64`** —— 这是参考实现踩过的坑：飞牛会判字段不识别。
> 正确的是 `platform = x86` + 显式 `os_min_version`。

### 3.2 `config/privilege` / `config/resource`

```json
{ "defaults": { "run-as": "package" } }
```

```json
{ "data-share": { "shares": [ { "name": "suenmoney/backup" } ] } }
```

- `run-as` **必须 `package`**：`root` 会让应用中心在赋权阶段被安全策略拦住，
  表现是安装恒定报「设置目录权限失败」（参考实现为此连改四版才定位）。
- `data-share` **只暴露备份子目录**：数据库留在 `${TRIM_PKGVAR}/data/`（私有），
  只把 `SUENMONEY_BACKUP_DIR` 指向共享目录 —— 用户能在文件管理器里看到并对拷 **VACUUM INTO**
  出来的 `.sqlite` 快照，这正是本项目现有的灾备形态，不需要改造。

### 3.3 `app/ui/config`

```json
{ ".url": { "suenmoney.Application": {
    "title": "SuenMoney", "icon": "images/icon_{0}.png", "type": "url",
    "protocol": "", "port": "5310", "url": "/", "allUsers": false } } }
```

`{0}` 是飞牛按尺寸取 `icon_64/icon_256` 的占位符；`port` 必须与 `manifest.service_port` 一致。

### 3.4 环境变量映射（`cmd/main` 导出，全部 `${用户值:-默认}`）

| 变量 | 套件里的值 | 为什么 |
|---|---|---|
| `SUENMONEY_HOST` | `0.0.0.0` | 默认 `0.0.0.0` 已经是这个值，但**必须显式写死**：参考实现里它默认 `127.0.0.1`，结果「应用中心显示正常、手机连不上」，极隐蔽 |
| `SUENMONEY_PORT` | `${PORT}`（= `service_port`） | 三处必须一致：manifest / ui config / 实际监听 |
| `SUENMONEY_DB_PATH` | `${TRIM_PKGVAR}/data/suenmoney.sqlite` | **必须显式覆盖**。默认是相对路径 `./data/…`，会在 `target/` 里建库，升级整体替换时账本蒸发 |
| `SUENMONEY_BACKUP_DIR` | `${TRIM_DATA_SHARE_PATHS%%:*}`，取不到退 `${TRIM_PKGVAR}/data/backups` | 落进 data-share，用户可见 |
| `SUENMONEY_BACKUP_KEEP` | `14` | 与 compose 一致 |
| `SUENMONEY_WEB_ROOT` | `${TRIM_APPDEST}/web/dist` | 计划一的开关 |
| `SUENMONEY_TRUST_PROXY` | `false` | 套件前面**没有反代**；开 XFF 信任 = 登录限流可被绕过 |
| `SUENMONEY_ALLOW_REGISTRATION` | `false` | 默认仅管理员建号 |
| `SUENMONEY_SESSION_DAYS` | `180` | 家庭自用，不折腾重登 |
| `SUENMONEY_UPDATE_*` | 用户可按需覆盖 | 自动更新源（见计划三 §五，鸿蒙/新 iOS 需要扩展平台白名单） |
| `TZ` | `${TZ:-Asia/Shanghai}` | **必须在脚本早期导出**，否则切换点之前的日志是 UTC |

> **本项目比参考实现少一个坑**：`suenmusic` 必须持久化 `jwt.secret`，否则每次重启令牌全废
> （表现为「升级后原生端被迫重登、正在播的歌 403」）。`suenmoney` 的会话是**库里的行 + 令牌哈希**
> （`server/src/http/auth.ts`，`sessionDays` 默认 180），重启不掉登录 —— **不需要也不应该**在包里生成密钥文件。

### 3.5 `cmd/main` 必须做到（照抄参考实现的形状，逐条都有事故对应）

| 能力 | 具体做法 | 对应事故 |
|---|---|---|
| 路径三段保险 | `TRIM_PKGVAR` 为空 → 从脚本位置反推 `<安装目录>/../var`；`VAR_DIR ∈ ""/"/"/var"/"/usr"/"/tmp` → `[FATAL] exit 1`；拿不到时日志写 `/dev/null` | 曾把日志/PID/库写到根分区 |
| 守护 | `start` → `nohup "$SELF" __supervise &`；`__supervise` 循环起 `node src/index.ts`，异常退出 `sleep 5` 重启，见 `stop.flag` 才退 | 「应用中心显示运行中，其实早崩了」 |
| PID 双校验 | PID 文件写 `"<pid> <starttime>"`，用 `/proc/<pid>/stat` 第 22 字段比对 | PID 复用时 `stop` 杀错进程 |
| stop 幂等 + 真释放端口 | 先 `: >stop.flag` → `TERM` 等 15s → `KILL` → 收子进程 → **端口仍占用就保留 stop.flag 并 return 1** | 「以为停了，其实被守护又拉起来」 |
| `status` 语义 | 进程命中 `exit 0`，否则 `exit 3`（`1` = 用法错） | 应用中心只看这个返回码 |
| 配置来源 | 读 `${TRIM_PKGETC}/.env`（兼容 `${TRIM_PKGVAR}/.env`），`set -a` 加载；首次启动只写 `env.example`，**不自动建 `.env`** | 「改了模板以为生效」 |
| 日志 | `${TRIM_PKGVAR}/info.log`，> 8MB 轮转 `info.log.1`；第一行打印安装/数据/配置/备份四个目录 | 装机后一眼核对路径 |
| 启动方式 | `"$NODE_BIN" --disable-warning=ExperimentalWarning src/index.ts`（**不再套 `node-run.mjs`**，见 R4） | — |

**`node` 版本选型**：内存本机 `v24.18.1`，`node:sqlite` 与 TS 类型剥离都已默认开启。
套件**锁定一个具体版本并校验 sha256**（建议与开发对齐的 24.x），
这样 `main` 里可以直接 `node src/index.ts`，不需要任何实验性旗标。

## 四、构建流水线 `scripts/build-fn.mjs`

七步，每步失败即中止（`set -e` 语义 + 明确报错）：

| 步 | 做什么 | 与参考实现的**改进** |
|---|---|---|
| 1 | 读根 `VERSION`（当前 `1.1.6`）→ 归一化 semver → 正则注入 `fn/manifest` | 不变 |
| 2 | 图标重采样：母版 `web/public/icon-512.png`（或 `docs/design/logo-style3-clean-white.png`）→ `ICON.PNG`(64)、`ICON_256.PNG`(256)、`app/ui/images/icon_{64,256}.png` | **不用 Python + Pillow**（参考实现本机没装 PIL，这一步直接崩）；改用 `sharp` 作根目录 devDependency，纯 npm、无系统依赖 |
| 3 | 取 Node 运行时二进制 → `fn/app/bin/node`（755）：缓存 `~/.cache/suenmoney-fn/`，先 npmmirror 后官方 | **补 sha256 校验**（参考实现裸 `curl` 无校验）；校验失败直接拒绝出包 |
| 4 | 前端：`web/dist/index.html` 缺失**或比 `web/src`+`web/public`+`index.html`+`vite.config.ts`+`package*.json` 旧** → 重建，然后 `cp -r` 到 `fn/app/web/dist` | 陈旧判据要纳入 `web/public`（字体/图标），否则「包里前端还是上一版、体积与校验和都正常」 |
| 5 | 服务端：拷 `server/src`（TS 源码直接拷，不跑 tsc）+ `server/scripts/node-run.mjs`（留作降级）+ `package.json` → `npm ci --omit=dev` → **校验 `node_modules` 里没有 `typescript`/`@types`** → **`rm -rf node_modules/.bin`** | 两条都是血泪：devDeps 混入会让体积与可复现性失控；`.bin` 里的相对软链被打包器改写成自引用死链，**直接导致安装报「设置目录权限失败」** |
| 6 | 权限归一：`umask 022`；目录 755 / 文件 644；`cmd/*` 与 `bin/node` 755 | 构建机 umask 077 会让包里出现 700，装到 NAS 上非 root 读不到 |
| 7 | `assertNoSymlinks()`（`find fn -type l` 非空即 fail）→ `fnpack build -d .`（cwd 必须是 `fn/`）→ 产物改名 `output/suenmoney-v<semver>.fpk` + 打印体积与 sha256，**同时写 `output/suenmoney-v<semver>.fpk.sha256`** | 参考实现只打印哈希不落文件；落文件才能给装机核对 |

`fnpack` 获取顺序：`which fnpack` → 仓库 `node_modules/.bin/fnpack` → 下载
`https://static2.fnnas.com/fnpack/fnpack-<ver>-linux-amd64`（**同样校验 sha256**）。
根 `package.json` 增 `"fn:build": "node scripts/build-fn.mjs"`。

`.gitignore` 增：`fn/app/bin/`、`fn/app/server/`、`fn/app/web/`、`fn/*.fpk`、`fn/app.tgz`、`output/`。

## 六、风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | **只做 x86_64**：飞牛有 ARM 机型，那些用户装不上 | manifest 里如实写 `platform=x86`；README 注明「ARM 机型暂用 Docker 部署」。将来要支持，就是同一脚本第二遍打包 + arm64 版 Node 二进制 |
| R2 | 打包需要联网（`npm ci`、Node tarball、fnpack） | 三者都有缓存位（`~/.cache/suenmoney-fn/`、`node_modules/.bin/fnpack`）；文档写清「首次打包需联网」 |
| R3 | 飞牛网关前缀 `/app/suenmoney` 可能改写静态资源路径 | 计划一保持 Vite `base='/'`；若真机发现 `/app/suenmoney` 下资源 404，改用 `base='/'` + 反向改写（**先真机验证再定**，不要提前猜） |
| R4 | `node-run.mjs` 会再 spawn 一个子进程，PID 管理变三层 | 套件里**直接 `node src/index.ts`**（自带运行时版本已支持），`node-run.mjs` 只作为降级保留；F1 的 `stop` 门禁要求「无残留进程」 |
| R5 | 安装失败后残留目录会让后续安装一直报同样的错 | 文档给出 SSH 清理步骤：`rm -rf /var/apps/suenmoney /vol*/@app{c,data,conf,temp,home}/suenmoney`，并检查「存储空间管理」是否有「权限未适配」 |
| R6 | `checkport=true` 语义很弱（只探 `127.0.0.1`） | 守护 + 自己的 `status` 判据；应用中心显示「运行中」不得作为验收依据，F4-6 用 `curl` 实测 |
| R7 | 包内 Node 与开发 Node 版本漂移 | 版本常量写一处；F2-3 断言 `bin/node -v`；`server/package.json` 的 `engines` 同步 |

## 七、完成定义（DoD）

1. `npm run fn:build` 一条命令产出 `output/suenmoney-v<version>.fpk` + `.sha256`，全过程零手工步骤。
2. F0–F5 门禁全绿，其中 **F4（真机）8 条全过**，含「升级保数据」「卸载保数据」两条。
3. 包内**零软链、零 devDeps**、`cmd/*` 全 755、端口三处一致。
4. `docs/deploy.md` 里那段「命令行必须显式指定 `SUENMONEY_DB_PATH`」的警告存在且经过实测复现。
