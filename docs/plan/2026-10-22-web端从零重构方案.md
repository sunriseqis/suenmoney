# Web 端从零重构方案（2026-10-22）

> 触发：换肤已进行十余轮，旧组件的样式冲突始终修不干净（全局 `button`/`svg`/`.card`
> 规则与原型互相打架，每修一处冒三处）。用户裁决：**备份旧 web，新建干净工程，从头重构**。

## 〇、备份与回退

| 项 | 位置 |
|---|---|
| Git 标签 | `web-legacy-2026-10-22`（已推送远端） |
| 物理备份 | `archive/web-2026-10-22/`（源码，1.6MB，不含 node_modules/dist） |
| 线上回退 | `git checkout web-legacy-2026-10-22 -- web && npm --prefix web install && npm run build:web` |

**旧代码一行都不删**，直到新工程验收通过。

## 一、重构边界（重要）

| 层 | 处理 | 理由 |
|---|---|---|
| `src/views`、`src/components`、`src/styles` | **全部重写** | 问题都在这三层：样式互相覆盖、组件手写类名、页面结构是历代补丁叠加 |
| `src/api`（端点封装 + 类型） | **原样搬** | 64 个端点、类型定义与后端一一对应，重写只会引入字段错配 |
| `src/stores`（数据与同步） | **原样搬** | 离线 Outbox、增量同步、乐观更新是硬逻辑，有 156 项测试兜着 |
| `src/platform`、`src/utils` | **原样搬** | 平台抽象、金额/日期/账期工具，与视觉无关 |

**为什么不连逻辑一起重写**：逻辑层是唯一「改对了」的部分（288 服务端测试 + 156 前端测试
全绿），重写它等于把已经验证过的东西再赌一次。视觉层才是坏掉的，也只重写视觉层。

## 二、新工程结构

```
web-v2/
├── index.html                 主题内联脚本（Vue 挂载前定 candy/cyber）
├── vite.config.ts             构建标记 + 别名 + 反代
├── styles/
│   ├── proto/theme.css        原型设计系统（逐字复制，不改）
│   ├── proto/app.css          外壳与通用组件（逐字复制，不改）
│   ├── proto/views.css        各页样式（逐字复制，不改）
│   └── base.css               只保留：reset、页面过渡、动效降级、滚动条
├── src/
│   ├── api/                   搬旧（端点 + 类型）
│   ├── stores/                搬旧（数据 + 同步）
│   ├── platform/              搬旧（平台抽象）
│   ├── utils/                 搬旧（金额/日期/账期/主题）
│   ├── ui/                    原型组件库（PBtn/PCard/PSeg/PStat/…）
│   ├── components/            业务组件（新建，全部基于 ui/）
│   ├── views/                 六个页面（新建，照原型布局）
│   └── router/
```

**硬约束**：新工程**不引入任何旧 class 名**（`bg-canvas`、`text-ink`、`rounded-md`、
`.card` 自定义版、`.btn-v4`…）。样式只来自两处：原型 CSS + 各组件自己的 `<style>`。

## 四、功能守则（每阶段必查）

以 `docs/feature-inventory.md` 的 138 项为准，每阶段结束时：

1. 列出该阶段对应的条目，逐条确认「看得见、点得动、存得住」
2. `npm run check:vue` 结构体检
3. `npm run check` 全绿
4. 构建标记变化后再让用户看

## 五、不做的事（避免重蹈覆辙）

- **不再给元素级加全局样式**（`button:active`、`svg{stroke}`、`h1{...}`）。
  一切视觉来自原型 CSS 或组件自身。这是前面十几轮打转的根因。
- **不再写「兼容层」**（`[class*='rounded-md']` 重解释之类）。新工程没有旧类名，不需要兼容。
- **不再用字符串索引做大块 DOM 搬迁**。需要挪结构就重写该页模板，并跑结构体检。
- 一次只推进一个阶段，阶段内小步提交。
