## 一、工作流（必须按这个节奏，不许跳步）

```
Agent：开工前读 §二 契约 → 按阶段开发 → 自测 → 提交「验收包」→ 停下等核验
Lead ：按阶段门禁逐条核验 → 放行（进入下一阶段）或 退回（附缺陷编号）
```

1. **一次只做一个阶段**，做完停下等核验，不要连做两个阶段。
2. 每个阶段提交**一个** commit（或一组按逻辑拆分的 commit），推到 `hw-native` 分支。
3. 验收包写在 `docs/reports/hw/H<阶段号>-<主题>.md`，格式见 §五。
4. 任何一条门禁不通过 → 该阶段不过，修完重新提交；**不许把「差不多能用」当通过**。

## 二、三份契约（开发前必须读完，改动需求先问我）

| 文件 | 作用 |
|---|---|
| `docs/api-native-contract.md` | 24 条路径，带 curl 与真实响应样例。**字段名照抄，不许改名** |
| `docs/test-vectors/vectors.json` | 31 条测试向量。**必须写一个 runner 让它全过** |
| `web/styles/proto/theme.css` | 视觉唯一基准（candy / cyber 两套）。颜色、圆角、阴影、字体以它为准 |

**全局口径**（写错会静默算错，不报错）：

- 金额一律**整数分**（`amountCents`），显示时才除 100
- 日期一律 `YYYY-MM-DD` 字符串，**不用时间戳**
- 报表月份归属以 **`repaymentDate`（还款日）** 为准，不是消费日
- 删除是**墓碑**（软删），永不物理删除
- 列表分页用**游标**（`nextCursor`），不是 offset
- 紧急度三档：迟于还款日 = overdue；0–1 天 = due；更远 = later

### H1 · 登录与多服务端

- 屏：登录（账号 / 口令 / 服务器地址 / 探活）
- 门禁：首次启动能连上服务端并进入主框架；口令错误有明确提示；服务器地址可保存多个、按序探活（同源优先 → 内网 → 备用，4s 首试快速失败）
- 证据：录屏或 3 张截图（成功 / 口令错 / 服务端不可达）；探活日志（每条地址的耗时）

### H2 · 流水（列表 + 日历两形态）

- 三档三形态：按月 = 列表（按消费日分组 + 日小计）；按年 = 12 月格；全部 = 一年一格
- 检索：搜索、筛选（分类 / 支付 / 记录人）、排序（日期 / 金额）
- 分页：游标，每段 100 笔，触底加载更多
- **离线 A 档**：断网时用本地库现算列表与合计
- 门禁：与 Web 端同一月份的数据**逐笔一致**（笔数、合计、每行金额）；报告附同一月的 Web 截图 + 鸿蒙截图
- 证据：截图（三档各 1 张 + 筛选展开 1 张）；断网截图（飞行模式下列表仍有数据）；`/api/expenses` 请求日志

### H3 · 记账抽屉（唯一写入入口）

- 半屏抽屉：金额（自绘 5 列键盘：左支付列 + 右数字键）、分类（左一级导航 + 右二级网格）、支付方式、消费日期、备注、退款、分期
- **跨月必须明说**「这笔会记在 2026 年 11 月（还款日 11-28）」——这是本项目的头号误解来源
- 记住上次用的分类与支付方式；键盘上方显示「本月已支出」
- 门禁：新增 / 编辑 / 删除三条路径都通；退款（负数）金额符号正确；分期走计划接口而不是支出接口
- 证据：录屏（记一笔完整流程）+ 数据库查询截图（确认落库字段与符号）

### H4 · 概况

- 主卡：期间分段、大金额、环比、三指标、构成堆叠条与图例
- 待办提醒条目（有则显示、无则隐藏、可展开）
- 月度热力（12 格，点击下钻报表）
- 累计与跨度
- 门禁：数字与 Web 概况页同月一致；待办动作（确认/入账/忽略）生效后列表立即更新

### H5 · 报表 + 年度报告

- 环图（Canvas 自绘）+ 图例、四维切换（分类/支付/记录人/节奏）、涨跌榜（本期 vs 上期）、还款节奏
- 年度报告：12 月走势、年度之最
- 门禁：环图各段占比与图例百分比一致；涨跌榜差值与 Web 一致

### H6 · 设置五区 + 编辑弹层

- 账目（分类树 + 支付方式）、计划、数据（主题/导入导出/危险区）、家庭（成员/设备）
- 编辑弹层：分类（名称/图标；二级不设颜色、可移动）、支付方式（名称/图标/账期/合并）、计划（新建/终止/删除）、成员
- 门禁：分类颜色「二级跟一级走」；停用项不出现在记账抽屉的可选项里

### H7 · 离线写 B 档 + 同步

- Outbox 8 种动作、重试 3 次退避 5/10/30s、死信界面、增量拉取、冲突（只能改自己创建的）
- 触发：本地变更 300ms 防抖、前台恢复、网络恢复
- 门禁：飞行模式记 3 笔 → 恢复网络 30s 内自动上云；死信必须可见（不许静默丢弃）
- 证据：录屏（断网记 → 联网同步 → Web 端刷新可见）+ 死信界面的触发截图

### H8 · 打磨与切换

- 真机验收：冷启动时间、列表滚动、抽屉打开耗时（各记 3 次取中位数）
- 包签名与安装包交付；README 写明安装方式
- 门禁：全量功能核对表（我提供 138 项里的客户端部分）逐条打勾

## 四、禁止事项（都是踩过的坑）

1. **不许自造信息架构**：页面集合就是 §五 的 6 屏 + 3 层 + 5 弹层。要加要减先问我。
2. **不许丢功能**：宁可少一个视觉细节，不许少一个功能入口。
3. **不许改契约**：字段名、路径、金额单位、日期格式一个字都不改。
4. **不许改测试向量的期望值**来让测试通过——那是把契约改歪。
5. **不许用系统数字输入法**代替自绘键盘（金额要固定 5 列布局）。
6. **不许把说明式文字写进界面**：判据是「这句话有没有改变你要做什么」。字段标签、空态指引、约束、后果可以留；机制解释、设计理由、位置指引一律删。
7. **不许静默吞错**：网络错误、死信、同步失败都必须在界面上可见。
