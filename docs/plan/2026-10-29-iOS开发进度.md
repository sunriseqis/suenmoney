## 二之二、复核轮（2026-10-29 晚）发现并修复的 20 处问题

> 上一轮「代码层完成」的判断过于乐观。这轮用 iOS 技能 + 逐条对照鸿蒙源码复核，
> 发现 20 处问题，其中 **4 处会导致编译失败或数据错误**。

### A. 会编译失败（Swift 6 严格并发）

| # | 问题 | 修法 |
|---|---|---|
| A1 | `Db` 非 Sendable，被 `SyncEngine`(actor) 跨隔离域访问 | `@unchecked Sendable` + 内部 `NSRecursiveLock` |
| A2 | `ServerConfig` / `ApiClient` 同上 | `@unchecked Sendable` / `Sendable` |
| A3 | `ServerRouter` 的 `static var` 数据竞争（编译期错误） | `nonisolated(unsafe)` + `NSLock` |
| A4 | `let rootId` 之后又赋值（`-parse` 查不出） | 改 `var`；并加全仓扫描脚本确认无同类 |

### B. 会导致数据错误 / 崩溃

| # | 问题 | 修法 |
|---|---|---|
| B1 | **sqlite3 连接被多线程并发使用**（Apple libsqlite3 是 multi-thread 模式，同连接不能并发）→ `database is locked` 甚至崩溃 | `NSRecursiveLock` 串行化所有 SQL 入口 |
| B2 | `@Observable` 类未标 `@MainActor`：`AuthStore.login` 等 async 方法在非隔离上下文改 UI 状态 | 四个类统一加 `@MainActor` |
| B3 | **分类筛选没做「二级归一级」**：筛选项只列一级，记录挂在二级 → 选了一级却筛不出二级的记录 | 按 `parentId` 归到父级再比 |
| B4 | 离线入队后回调返回了 `id`，但本地并无该记录 → 流水页高亮指向不存在的行 | 返回 `""`（与鸿蒙一致） |
| B5 | **分期离线静默降级**：鸿蒙端会以普通支出入队，补传后用户以为记了分期、实际没记 | iOS 有意收紧：分期离线明确报错（**记录为有意差异**） |

### C. 数值口径与鸿蒙不一致（会看到不同数字）

| # | 问题 | 鸿蒙正确口径 |
|---|---|---|
| C1 | `elapsedDaysOf` 未来月返回 0 | 非当前月一律返回**整月天数** |
| C2 | 流水页 `perDayCents` 用了 `elapsedDaysOf` | 用「**今天是几号**」 |
| C3 | 报表页 `perDayCents` 缺非月档分支 | 非月档 = **总额 / 笔数**（单笔均值） |
| C4 | 年报「月均」用了 `average3YearsCents` | **total / 12**；另有「单笔均值」「空月」两项 |
| C5 | 热力色比例区间 25%~100% | **18%~100%**（`(18+pct*82)/100`） |
| C6 | 分页 `PAGE_SIZE` 写死 50 | **100** |
| C7 | 排序：同日无次序 | **同日按 id 倒序**（避免刷新抖动） |
| C8 | 关键词未 trim 就发服务端 | `keyword.trim()` |

### D. 数据加载不完整（界面会空/错）

| # | 问题 | 修法 |
|---|---|---|
| D1 | 概况页**只拉当前档位**的报表 → 热力格依赖 `monthly.rolling12Months`，切到年档就空 | 三个报表**都拉**（与鸿蒙同构） |
| D2 | 报表页只拉一个 → 缺上月/年报/汇总 | 拉**四个**（本月/上月/年报/汇总） |
| D3 | 流水页双 `onChange`（tier + anchorMonth）→ 切年档 `loadTier` 跑两次，列表闪一下 | 改**显式加载**，去掉双订阅 |

### E. 健壮性

| # | 问题 | 修法 |
|---|---|---|
| E1 | 搜索防抖未取消旧 Task → 连续输入并发多请求，旧结果可能覆盖新结果 | 保存 `Task` 引用并 `cancel()` |
| E2 | 离线 payload **手工拼 JSON**，只转义了双引号 → note 含反斜杠/换行即非法 | 改用 `JSONEncoder` |

## 三、交付时必须说明的三件事

### 1. 没有 macOS，UI 层未过 Xcode 编译

Linux 上 `swiftc -parse` 只能查**语法**，查不了：
- 类型/参数顺序（已发现并修掉一处：`PlanCreateRequest` 的 `purchaseDate` 位置）
- SwiftUI 修饰符是否适用于该 View 类型
- SF Symbol 名是否真实存在
- Keychain / SQLite3 等 Apple 专有模块的链接

**拿到 Mac 后的第一件事**：`xcodebuild` 跑一遍，按报错逐个修。

### 2. `urgencyLabel` 与鸿蒙端的一处已知偏差（不是 bug）

- `vectors.json`（三端共用）与 Web 都是「**已逾期** N 天」
- 鸿蒙端 R49 裁决改成「逾期 N 天」（精简）
- **鸿蒙 UI 不调用这个函数**（待办标签自己拼），所以两边不冲突

iOS 侧处理：**纯函数按向量实现**（保证三端一致），**UI 文案按 R49**（`todoTag()` 自己拼）。

### 3. 图标映射（G6）

鸿蒙 26 条分类 `sys.symbol` → SF Symbols 同名语义（`fork.knife` / `cart.fill` / `tram.fill` …）。
支付品牌（支付宝/微信/云闪付/京东/抖音）**无 SF Symbol** → 沿用随包 SVG
（已建 `Resources/Assets.xcassets/pay_*.imageset`，含 `preserves-vector-representation`
+ `template-rendering-intent`），非品牌 4 种用 SF Symbol。

**兜底**：自建分类名不在表里 → `doc.text`（永不为空）。

## 五、Xcode 工程创建步骤（拿到 Mac 后）

1. Xcode → File → New → Project → **iOS App**
   - Product Name `SuenMoney`
   - Interface **SwiftUI**，Language **Swift**
   - Bundle ID `com.suenmoney.app`（与服务端更新通道一致）
   - Deployment Target **26.0**
2. 把 `ios/SuenMoney/` 下 `App/ Auth/ Contract/ Net/ Store/ Sync/ Theme/ UI/ Resources/`
   **整体拖进**新工程（勾选 *Create groups* + *Copy items if needed*），删掉模板的 `ContentView.swift`
3. Target → Build Settings → `INFOPLIST_FILE` 指向自建 Info.plist
4. Info.plist 需加：
   - `NSAppTransportSecurity` → `NSAllowsArbitraryLoads = true`（局域网 http 服务端）
