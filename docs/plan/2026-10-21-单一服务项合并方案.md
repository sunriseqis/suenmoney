# 计划一：合并 server + web 为单一服务项（单进程 / 单端口 / 单镜像）

> **状态**：**P0–P3 已落地（2026-10-21）**，代码与文档均已收口；剩下的只有需要真机的三条
> （P2-5 旧卷升级核对、P3-1 GHCR 单镜像、DoD-5 回滚演练）。
> 落地记录见 [`../memory/2026-10-21-单一服务项合并落地.md`](../memory/2026-10-21-单一服务项合并落地.md)。
> **口径（用户已拍板）**：**单容器单端口 —— 服务端内置托管 `web/dist`，删掉 nginx 容器**。
> **参考实现**：`/home/suenmusic`（`@fastify/static` + SPA 回退 + `onSend` 缓存头，已跑通）。
> **前置**：无。**后续**：计划二（fnOS 套件）强依赖本计划完成。

## 一、为什么要合

现在「一个系统」对外要起两个容器、两个进程、两套配置，而它们只是同一件事的两半：

| 现状 | 代价 |
|---|---|
| `suenmoney-server`（3310，不映射） + `suenmoney-web`（nginx，5310→80） | 部署要拉两个镜像、改端口要改两处、`BACKEND_URL` 是第三个要配的东西 |
| `web/nginx.conf.template` 靠 `envsubst` 注入后端地址 | 环境变量写错的表现是「页面能开、接口全 502」，比直接挂掉更难查 |
| 两容器一网络 | 家庭 NAS 上多一份故障面（nginx 起不来 = 整个前端没了，但后端还活着，健康检查却都正常） |
| 浏览器同源靠 nginx 反代「凑」出来 | 一旦有人把 nginx 换掉、或直接访问 3310，立刻变成跨源，CORS 悄悄变成必需项 |

合并后：**一个进程同时回答 `/`（SPA）与 `/api/*`（接口），同名同源，一个端口，一个镜像，一个数据卷。**
这条同时是后面两个计划的地基 —— 飞牛套件要求「单端口全栈承载」，原生客户端要求「一个地址就是全部」。

## 三、目标形态

```
┌──────────────────────────── suenmoney（单容器 / 单进程 / 单端口 5310） ────────────────────────────┐
│  Fastify                                                                                          │
│   ├── GET /            ─► web/dist/index.html          (Cache-Control: no-cache)                   │
│   ├── GET /assets/*    ─► web/dist/assets/*            (public, max-age=2592000, immutable)        │
│   ├── GET /ledger 等   ─► index.html（SPA 回退，与 /api 同源）                                      │
│   ├── GET /api/health  ─► {ok, service, version}       （套件/探活/原生端探活共用）                  │
│   ├── /api/* 其余      ─► 业务路由（未命中回 JSON 404，**绝不回 HTML**）                            │
│   └── 调度器：每日 VACUUM INTO 快照 + WebDAV 备份（同进程，不变）                                    │
└───────────────────────────────────────────────────────────────────────────────────────────────────┘
                              ▲                         ▲                              ▲
                        浏览器（同源）            iOS / 鸿蒙原生端（只要 /api）      飞牛套件（计划二）
```

**一条不可回退的判据**：`/api/` 下的未命中**必须是 JSON 404**，其余未命中**必须是 HTML**。
两者混一次（接口 404 回一坨 HTML），前端解析错误会变成「登录失败，请重试」这种假故障。

## 四、改造清单

### 4.1 服务端（3 个文件 + 1 个依赖）

**`server/package.json`**：加 `"@fastify/static": "^8.3.0"`（Fastify 5 对应 v8 线）。

**`server/src/config.ts`**：新增两项，全部有默认值、没有 `webRoot` 也能纯 API 跑。

```ts
  /** 前端产物目录。不存在时自动退化为纯 API 服务（测试/开发/只跑接口时就是这样）。 */
  webRoot: resolve(str('SUENMONEY_WEB_ROOT', '../web/dist')),

  /**
   * 是否信任 X-Forwarded-For。
   * 合并后默认在**最前面**，直连形态下信任 XFF 等于允许伪造来源绕过登录限流 —— 所以默认关。
   * 只有「前面还有一层反代」（用户自己挂 Caddy/nginx TLS）时才显式打开。
   */
  trustProxy: bool('SUENMONEY_TRUST_PROXY', false),
```

**`server/src/http/server.ts`**：三处改动，照抄 suenmusic 的形状（✅ 已跑通）。

```ts
// ① trustProxy 改为可配置
trustProxy: config.trustProxy,

// ② 注册静态托管（index.html 不在就当没这回事）
const hasWeb =
  existsSync(join(config.webRoot, 'index.html')) ? config.webRoot : null;
if (hasWeb) {
  await app.register(fastifyStatic, { root: hasWeb, wildcard: false });
}

// ③ 缓存头用 onSend —— @fastify/static 的 setHeaders 会被 send 覆盖
app.addHook('onSend', async (req, reply) => {
  if (req.url.startsWith('/assets/')) {
    reply.header('Cache-Control', 'public, max-age=2592000, immutable');
  } else if (req.url.endsWith('.html') || req.url === '/' ) {
    reply.header('Cache-Control', 'no-cache');
  }
});

// ④ 404 分流：/api 回 JSON，其余回 SPA 外壳
app.setNotFoundHandler((req, reply) => {
  if (req.url.startsWith('/api/')) {
    reply.code(404).send({ error: '接口不存在' });
    return;
  }
  if (hasWeb) {
    reply.type('text/html').header('Cache-Control', 'no-cache');
    reply.send(readFileSync(join(hasWeb, 'index.html')));   // 启动时读一次即可，热改 dist 需重启
    return;
  }
  reply.code(404).send({ error: '接口不存在' });
});
```

> `hasWeb` 为假时行为与现在**逐字节一致**：这是让 10 个现存集成测试不用改的前提（见 §4.6）。

**`server/src/index.ts`**：启动日志里打印实际使用的 `webRoot`（有/无），装套件时肉眼可核对。

### 4.3 部署（4 个文件，删 2 个）

**`server/Dockerfile` → 改为根目录单镜像多阶段**（`Dockerfile`，或留在 `server/Dockerfile` 但构建上下文改为仓库根）：

> 两处既有经验**必须保留**：① 依赖安装阶段用 `--platform=$BUILDPLATFORM`（见 `server/Dockerfile` 头部注释，
> 否则 arm64 上 QEMU 模拟会触发 V8 JIT 探测崩溃 SIGILL）；② `apk add tzdata wget ca-certificates`
> （快照调度依赖本地时区，`HEALTHCHECK` 依赖 wget）。

```dockerfile
# 1) 前端产物（跑在构建机原生平台，避免 QEMU）
FROM --platform=$BUILDPLATFORM node:22-alpine AS web-builder
WORKDIR /app/web
COPY web/package*.json ./
RUN npm ci && npm cache clean --force
COPY web/ ./
RUN npm run build

# 2) 服务端依赖（同样跑在构建机原生平台）
FROM --platform=$BUILDPLATFORM node:22-alpine AS deps
WORKDIR /app
COPY server/package*.json ./
RUN npm ci --omit=dev --ignore-scripts && npm cache clean --force

# 3) 运行时（目标架构，含 web/dist，单端口 5310）
FROM node:22-alpine AS runner
RUN apk add --no-cache tzdata wget ca-certificates
ENV NODE_ENV=production \
    SUENMONEY_HOST=0.0.0.0 \
    SUENMONEY_PORT=5310 \
    SUENMONEY_DB_PATH=/app/data/suenmoney.sqlite \
    SUENMONEY_BACKUP_DIR=/app/data/backups \
    SUENMONEY_WEB_ROOT=/app/web/dist \
    TZ=Asia/Shanghai
WORKDIR /app/server
COPY --from=deps /app/node_modules ./node_modules
COPY server/package*.json ./
COPY server/scripts ./scripts
COPY server/src ./src
COPY --from=web-builder /app/web/dist /app/web/dist
RUN mkdir -p /app/data /app/data/backups && chown -R node:node /app
USER node
EXPOSE 5310
VOLUME ["/app/data"]
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://127.0.0.1:5310/api/health || exit 1
CMD ["node", "scripts/node-run.mjs", "src/index.ts"]
```

## 五、端口与地址口径（一处写清，免得又出现 3310/5310 混用）

| 场景 | 谁托管静态 | 对外地址 | 后端监听 |
|---|---|---|---|
| 生产（单容器） | Fastify | `http://<NAS IP>:5310` | `0.0.0.0:5310`（`SUENMONEY_PORT=5310`） |
| 本地开发 | Vite（HMR） | `http://127.0.0.1:5310` | `127.0.0.1:3310`（仅 vite 代理用，不对外） |
| 飞牛套件（计划二） | Fastify（包内 `web/dist`） | `http://<NAS IP>:5310` 或 `/app/suenmoney` | `0.0.0.0:5310` |
| 自建反代（可选） | 用户的反代只做 TLS | `https://money.example.com` | `127.0.0.1:5310` + `SUENMONEY_TRUST_PROXY=true` |

> **`SUENMONEY_PORT` 默认值保持 3310 不动**（`server/src/config.ts:37`）：它只影响「没配环境变量时监听哪」，
> 开发/测试都依赖这个默认值。生产与套件一律显式 `SUENMONEY_PORT=5310`。
> 这样**用户书签与 App 里存的 5310 一个都不用改**。

| R1 | **升级路径**：老用户手里是双容器 compose，直接 `pull` 会拉到旧 `suenmoney-web` | `deploy.md` 给一段「替换 compose 后 `docker compose down && docker compose up -d`」，并明确数据卷名不变；旧镜像保留可用（§4.4） |
| R2 | `trustProxy` 从 `true` 改 `false` 后，若用户前面有反代，限流会把所有人算成 `127.0.0.1` | 反代场景必须显式 `SUENMONEY_TRUST_PROXY=true`；`deploy.md` 反代小节给出完整 env |
| R3 | 静态托管与 SPA 回退会让**接口 404 变 HTML**的回归静默发生 | `static.test.ts` 里那条「`/api/nope` 必须是 `application/json`」就是这条的回归断言，不许删 |
| R4 | `client_max_body_size 32m` 那层没了，`bodyLimit 512KB` 才真正生效 —— 批量导入大 CSV 可能 413 | 用真实导入包（3,230 笔账本）走一次导入；若超限，把 `bodyLimit` 提到 4MB（`server/src/http/server.ts:29`），不要退回 nginx |
| R5 | `@fastify/static` 版本与 Fastify 5 不匹配会直接起不来 | 锁 `^8.3.0`；P0-1 的门禁要求 `npm test` 全绿（测试会真起 server） |
| R6 | 单进程 = 单点：SPA 与 API 同时起落 | 这是**要的**（以前 nginx 挂了前端全没了、后端还在，更难排查）；容器 `restart: unless-stopped` + `HEALTHCHECK` |
| R7 | 静态文件缓存 `immutable` 后，用户拿到旧 `index.html` 引用不存在的 hash | `index.html` 一律 `no-cache`；`assets/` 带内容 hash（Vite 默认），两者配套才成立 |

**实测（`SUENMONEY_PORT=5398` + 真实 `web/dist`）**：

```
GET /            -> 200 text/html          cache-control: no-cache
GET /report      -> 200 text/html          （SPA 回退）
GET /api/nope    -> 404 application/json   {"error":"接口不存在"}
GET /api/health  -> {"ok":true,"service":"suenmoney","version":"1.1.6"}
GET /assets/*.js -> 200                    cache-control: public, max-age=2592000, immutable
启动日志         -> 静态资源：/…/web/dist（同一端口同时提供页面与 /api）
```

**一处与原方案的偏离**：原计划把「同源优先」做在 `api/client.ts` 里，
落地时发现该模块**必须能被 Node 测试直接加载**（`@/` 别名只有 Vite 认识），
于是把平台判定收敛成模块内 6 行（只看 Capacitor / 鸿蒙桥在不在），
而不是 `import { getPlatform } from '@/platform'` —— 后者会让整个前端测试套件解析失败。

**本机原生部署已实测通过（2026-10-21，systemd，端口 5310）** —— 这条路不依赖 Docker 任何东西：

| 步骤 | 结果 |
