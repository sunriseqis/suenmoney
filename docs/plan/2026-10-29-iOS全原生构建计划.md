## 一、先摆事实：这件事现在缺的不是代码，是构建环境

| 项 | 现状 |
|---|---|
| 当前 `ios/` | Capacitor 壳（`AppDelegate.swift` / `SceneDelegate.swift` / `CapApp-SPM`），**要废弃** |
| 构建脚本 | `scripts/build-ios.mjs` 第一步就 `if (process.platform !== 'darwin') fail(...)` |
| 本机环境 | Linux 容器（192.168.89.10）+ Windows（100.66.45.14，装的是 DevEco）。**都没有 Xcode** |
| 方案文档 S0-3 | 已记录「⛔ 环境不具备：本机无 `xcodebuild`」 |

**结论：iOS 代码可以照写，但「编译 / 装模拟器 / 出 IPA」必须有 macOS + Xcode。**
这是本计划的**唯一硬阻断**，见 §六决策点 D1。

### S1 · 六条命脉（3–4 天）★ 全绿才进 S2

沿用方案文档 S1 的六条判据：

1. 登录成功，令牌进 Keychain，**杀进程重启不掉登录**
2. 流水列表能出数（月档，至少 20 条）
3. 记一笔成功，且立刻出现在列表顶部并高亮
4. 概况月度总额与 Web 端**同值**（并排截图核对）
5. 断网仍能看列表（A 档离线读本地库）
6. 断网记账进 Outbox，联网后自动补传

附加门禁：冷启动 < 1.5s（真机）、列表 500 条不掉帧、金额键盘与分类面板同屏不遮挡。

### S2 · 五屏 + 抽屉对齐（2 周）

按 `2026-10-27-功能回归验收清单.md` 的 **61 条**逐组实现并打勾：

| D | 记账抽屉（下拉手势、保存键、跨月预览、退款/分期、日历） | 15 |

## 五、与鸿蒙端的差异（不要照搬的地方）

| 关注点 | 鸿蒙（已做） | iOS（要做） |
|---|---|---|
| 网络 | `@kit.NetworkKit` http.request | `URLSession` + async/await |
| 本地库 | `relationalStore` (RDB) | SQLite3 / GRDB |
| 令牌 | `preferences` | **Keychain** |
| 列表 | `List` + `ListItem` | `List` / `ScrollView + LazyVStack` |
| 弹层 | `bindSheet` | `.sheet` / `.presentationDetents` |
| 切角 | `clipShape(new Path(...))` + **vp2px 换算坑** | `.clipShape(Path)`，**坐标即点，无换算坑** |
| 网格 | `Grid`（**不给高度会撑满父容器**） | `LazyVGrid`（无此坑） |
| 图标 | `sys.symbol` + `SymbolGlyph` | **SF Symbols**（数量更多，映射更宽松） |
| 手势 | `PanGesture` | `DragGesture` |
| 返回 | `onBackPress()` | 系统边缘返回手势 + `NavigationStack` |
| 安全区 | `expandSafeArea` + `getWindowAvoidArea` | `safeAreaInset` / `ignoresSafeArea` |

## 七、工期估算

| 阶段 | 工期 | 累计 |
|---|---|---|
| S0 骨架 | 1–2 天 | 2 天 |
| S1 六条命脉 | 3–4 天 | 6 天 |
| S2 五屏对齐 | 10–12 天 | 18 天 |

**对比**：鸿蒙端实际用了 6 天（10-23 → 10-29），但含大量 UI 返工（顶卡裁切、图标三轮、
日历弹窗、计划语义三轮澄清）。iOS 因为**所有裁决都已确定**，返工应该显著减少；
主要风险在 **D1 构建环境**（每次验证要过一次 Mac）和 **SQLite/Outbox 的离线语义**
（鸿蒙端有 `Db/ExpenseDao/Outbox/SyncEngine` 可逐条对照，但 Swift 侧要重写）。
