## 三、两个实跑才发现的事实（比方案文档更准）

1. **`app.tgz` 里没有 `app/` 前缀**：解出来是 `bin/`、`server/`、`web/`、`ui/`、`VERSION` 直接在根。
   我第一版校验脚本按 `app/...` 找，全部落空 —— 差点误判成「payload 没打进去」。
2. **`fnpack` 会往 `manifest` 末尾追加一行 `checksum`**。所以「包里 manifest 与仓库里的逐字节相同」
   这个断言永远失败；校验必须按字段比（`version` / `service_port` / `platform`），不能按文件比。

另外三个坑是**提前规避**的（参考实现踩过，我在脚本里加了硬门禁）：

- `node_modules/.bin` 的相对软链被打包器改写成自引用死链 → 出包前 `rm -rf` + `assertNoSymlinks`
- 构建机 umask 077 → 包里 700/600 → 脚本顶部 `process.umask(0o022)` + 末尾 chmod 整齐
- 图标步骤依赖 Python Pillow（本机没有，参考实现直接挂）→ 改用 `sharp`，纯 npm

## 四、还没验的（必须真机）

| # | 场景 | 通过判据 |
|---|---|---|
| F4-1 | 应用中心上传安装 | 安装成功、无「设置目录权限失败」、桌面出现图标 |
| F4-2 | 点开 | `http://<NAS IP>:5310` 出登录页，能建首个管理员 |
| F4-3 | 记账 + 导出 | 记一笔刷新仍在；数据 tab 能导出 CSV |
| F4-4 | 备份落共享目录 | 文件管理器里 `suenmoney/backup/` 有 `.sqlite`，大小 > 0 |
| F4-5 | 重启 NAS | 开机自动运行、账本完整 |
| F4-6 | 应用中心停/启 | 停止后 `curl :5310` 不通；`status=3`；启动后恢复 |
| F4-7 | **升级保数据** | `info.log` 出现新版本的健康自检；账本条数不变 |
| F4-8 | **卸载保数据** | 卸载后重装，账本仍在 |

> 特别注意 F4-4：`data-share` 声明的是 `suenmoney/backup` 子目录。若飞牛在**已有同名共享目录**
> 或**存储卷 ACL 未适配**的情况下拒绝创建，安装会失败 —— 这是参考实现踩过的第四坑。
> 真机若报错，先把 `fn/config/resource` 退回 `{}`（备份落私有区）再试。
