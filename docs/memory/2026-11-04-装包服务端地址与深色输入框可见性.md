# 装包自带服务端地址 + 深色输入框文字不可见（2026-11-04，用户反馈两条）

## 一、产物里 hardcode 了开发机地址

`hw-native/.../common/net/ServerConfig.ets` 与 `ios/.../Net/ServerConfig.swift` 都写着

```ts
export const DEFAULT_SERVER = 'http://192.168.89.10:5310';   // iOS 同名 defaultServer
```

而且 `servers` / `active` 的初值就是它。后果：任何人装包后，登录页「服务器」里已经填着一串
**别人的内网 IP**；点登录只会得到「连不上服务端」，用户根本无法判断是自己填错还是包有问题
（用户原话：这是错误的）。

修法（两端一致）：
- `DEFAULT_SERVER / defaultServer` 置空，`servers = []`、`active = ''`；
- `init()/load()` 里「没存过生效地址」不再无条件取 `servers[0]`，改为
  「有候选才取首项，否则留空」——鸿蒙原写法在空数组上会取到 `undefined`，
  iOS 的 `servers[0]` 更会**直接下标越界崩溃**；
- 空地址时的行为已有：登录按钮 → 「请填写服务端地址」，「测试」→ 「请先填地址」。
- 装包验证：全新安装（`hwdeploy.sh` 会先卸载）后登录页「服务器」是**空的**，
  显示占位符 `http://主机:端口`。

## 二、深色模式下输入框里的字看不见

用户描述：登录页整个服务端输入框「没有可见性」，并有「整个问题遍布深色模式双端的大多数输入框」。
根因是**两个独立的疏漏**叠加：

1. **原生控件不继承文字颜色**。Web 侧是
   `input, textarea { color: inherit }` + `input::placeholder { color: var(--ink-3) }`
   （`web/styles/proto/theme.css:23-24`），所以只要父级颜色对就行；ArkUI 的 `TextInput`
   和 SwiftUI 的 `TextField` 都不会继承 —— 不给色就用**系统默认色**（深色底上是近黑）。
2. 登录页的「服务端」输入框**一个颜色都没给**（鸿蒙 `.fontColor`/`.placeholderColor` 全缺；
   iOS `.foregroundStyle` 缺失），恰好它又是唯一预填了内容的框，于是那串地址显示成
   深底黑字 = 看起来像空框。其余输入框则普遍缺 `placeholderColor`。

修法：两端各加两个 helper，所有输入框统一走它，**不允许再出现「不给色」的输入框**。

| | 鸿蒙 `common/ui/UiStyle.ets` | iOS `UI/UiStyle.swift` |
|---|---|---|
| 正文 | `fieldTextColor(ink, isCyber)` → cyber `#ffffff` | 同名 |
| 示例 | `fieldHintColor(ink3, ink2, isCyber)` → cyber `ink2` | 同名 |

配色口径：candy 完全照 Web（正文 `--ink`、示例 `--ink-3`）；cyber 按用户要求
「深色底 + 灰白示例 + 纯白正文」，示例从 `#6b7280` 提亮到 `ink2(#8f93ad)`，
正文提到纯白（Web 是 `#e0e0e0`，肉眼差别很小，但用户明确要求纯白）。

覆盖清单（鸿蒙 9 处 / iOS 9 处）：登录名、口令、服务端、流水搜索、记账备注、
设置-服务器行、当前口令、新口令、通用 `fieldInput/plainField`、支付方式账单日数字框。

iOS 顺带把 `TextField("…")` 的标题式占位符统一改成
`TextField("", text:, prompt: Text("…").foregroundColor(…))` —— 标题式占位符吃系统色，
深色底上同样不保证可见。

## 上机实测（鸿蒙 emulator 1320×2848，全新安装）

| 检查 | 结果 |
|---|---|
| 装包后「服务器」字段 | **空的**，占位符 `http://主机:端口` 灰白可见 ✅ |
| 登录名输入 `suen` | 纯白 ✅ |
| 服务端输入 `http://192.168.89.10:5310` | 纯白 ✅（修前是深底黑字，看不出来） |
| 流水搜索输入 `test` | 纯白 + 光标可见 ✅ |
| 设置-服务器行输入 | 纯白 ✅ |
| 当前口令 / 新口令 | 占位符灰白可见 ✅ |

## 备查

- iOS 仍无法在容器里编译（缺 SQLite3 模块、无 Mac），本轮只做到 `swiftc -parse` + 静态核对，
  真机验证需要在 Mac 上做。
- 用户口中「89.10:**3210**」与本轮源码里的 `5310` 不一致；源码从未出现过 3210，
  推测是口述误差或旧产物。现在既然不再内置地址，两种都不成立。
