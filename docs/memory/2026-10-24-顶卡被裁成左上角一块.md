# 2026-10-24 顶卡被裁成「左上角一块」：clipShape 的 Path 用 vp 当 px

## 用户报的现象

> "hero 只显示出来或者说只渲染出来左上角一块，之前还有五分之一，现在五分之一可能都没有了。"

流水页顶卡（`.mobile-hero`）视觉上只剩左上角一小块，右侧提醒列、下半部分三事实全部消失。

## 排查过程（走过的弯路，供后人省时间）

1. **先改错了文件**：以为 hero 在 `DashboardScreen.ets`（概况页），改了几轮字号/字体/宽度都毫无效果。
   实际顶卡在 `LedgerScreen.ets` 的 `topCard()`。
   → **教训：先用 `uitest dumpLayout` 看当前屏有哪些文本，反查是哪个组件，再动手。**

2. **误判为字体度量问题**：dump 里 `Text('2,012.80')` 的 bounds 高 334px（字号 38 应有 ~156px），
   于是怀疑 `Orbitron-700.ttf` 的 hhea/OS-2 度量坏了。实测该字体 asc/desc/gap = 1011/-243/0，行高比 1.25，**完全正常**。
   换 Google Fonts 官方可变字体后 334px 依旧 → 排除字体。

3. **对照实验一次定位**（有效手法）：在顶卡里并排塞 4 个同字号 38 的 Text，分别用 Outfit / Orbitron / 系统 / 未注册族名，
   量各自行盒：
   - Outfit 168px（1.47x）✓
   - **Orbitron 334px** ✗
   - 系统 156px（1.37x）✓
   - 未注册的 'JetBrains Mono' 176px（1.54x）✓（干净回落）
   看起来"只有 Orbitron 坏"，但其实是 **334 = 2×167，Orbitron 数字 0.83em 太宽 → 折成两行**。

4. **决定性证据来自像素扫描，不是布局树**：
   `uitest dumpLayout` 给的 bounds 是**布局值**，看不出实际绘制。把截图 PNG 解出来按行扫 RGB 才发现：
   - `y=440` 处卡片只画到 **x≈401**，右边全是页面底色 `#0A0A0F`
   - 布局树却认为卡片占满 `84..1196`
   → **卡片被 clip 掉了右侧 2/3**，这才是"只渲染左上角一块"的真相。

## 根因

```ts
.onAreaChange((_o: Area, n: Area) => {
  this.cardW = Number(n.width);   // ← 单位 vp
  this.cardH = Number(n.height);
})
.clipShape(this.isCyber() && this.cardW > 0
  ? new Path({ commands: cyberClipCommands(this.cardW, this.cardH, 14) })
  : undefined)
```

`Path` 的 `commands` 坐标单位是 **px**，而 `onAreaChange` 给的是 **vp**（差 3 倍）。
于是裁剪框只有真实卡片的 1/3，整张卡被裁成左上角一块。

## 修法

```ts
.clipShape(this.isCyber() && this.cardW > 0
  ? new Path({ commands: cyberClipCommands(vp2px(this.cardW), vp2px(this.cardH), vp2px(14)) })
  : undefined)
```

验证：`y=440` 卡片恢复 `105..1192`（满宽 1088px）；`y=430` 左边内缩 10px → 切角（左上/右下对角）正常。

## 同一张卡连带修掉的两个真问题

- **大金额折行**：两列态下大金额只有 ~528px 可用，38 号 Orbitron（数字 0.83em）需要 ~570px → 折成两行把卡撑到 334px。
  → 字号按位数自适应（≤8 位 38 / ≤10 位 30 / 更长 24）+ `maxLines(1)`；同时把提醒列 112vp→96vp 把宽度让出来。
- **letterSpacing 没随主题**：web 是 candy `-0.035em` / cyber `+0.01em`，之前一律 `-1.3`。

## 顺手发现的两个基建问题

- **字体族名不匹配**：`fontMonoOf()` / `fontBodyOf()` 返回 CSS 原名（`JetBrains Mono` / `Plus Jakarta Sans`），
  但 `FONT_FILES` 只注册了 `JetBrains` / `PlayJakarta` → **mono/body 字体一直静默回落系统字体**。已在 `FONT_FILES` 补别名。
- **部署脚本只同步了 `entry/src/main/ets`**，没同步 `entry/src/main/resources` → 换字体文件根本不生效。
  已改为同步两者，并对 `.ets` 与字体 TTF 都做 sha256 前后比对（不一致直接失败）。

## 复用结论

1. **看实际绘制要用像素，不要只看 `dumpLayout`**：bounds 是布局值，clip 之后的真实可见区域得解 PNG 才知道。
2. **`Path`/`Canvas` 坐标是 px，布局 API 的宽高是 vp**，混用必出错，一律 `vp2px()`。
3. **改 UI 前先 dump 当前屏文本，反查组件文件**，别凭印象改。
4. 部署脚本必须**断言产物真的落地**（hash 比对），`scp -q` + `BUILD SUCCESSFUL` 不足以保证测的是新包。
