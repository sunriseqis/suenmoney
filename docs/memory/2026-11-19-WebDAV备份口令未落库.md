# WebDAV 备份口令从未落库（2026-11-19，并入 v2.1.1）

用户报障：**「即使我设置了口令，也会显示『请先设置备份口令』」**。

接口级复现（真 `buildServer()` + 临时库，按前端 `saveWebdav()` 的请求体打一遍）：

```
PUT /api/backup/webdav -> 200          ← 界面弹「配置已保存」
落库字段: url, username, password, path, isEnabled
passphrase: <undefined —— 丢了>
POST /run -> 400 请先设置「备份口令」…
```

## 根因：PUT 处理函数没读 `passphrase`

`server/src/http/webdav.ts` 的保存分支只取 `url / username / password / path / isEnabled`，
构造 `newConfig` 时**根本没有 `passphrase` 字段** —— 前端确实发了
（`SettingsView.vue` 的 `saveWebdav`），服务端静默丢弃，于是：

- 界面上「已保存」是真的（200）；
- 库里从来没有口令；
- `runWebdavBackup()` 的门禁读的正是这个字段 → 上传必被拦。

同一个函数里 `password` 有「传 `******` 或空 → 保留旧值」的逻辑，口令连这段都没有。
也就是说**即使当时补上了读字段**，之后任何一次「改地址 / 拨开关」的保存都会把它冲掉。

## 为什么没被测出来

`server/tests/http/webdav.test.ts` 原有 5 个用例**一处没提 passphrase**。
这个功能是 UI 门禁 + 加密库 + 上传三处各自到位，唯独「持久化」这一环没人接、也没人测 ——
典型的「接线断在中间」，两端各自看都正常。

## 修法

1. **服务端 PUT**：读 `passphrase`；空 / `******` → 保留 `existing.passphrase`；
   提供了就校验长度（**< 6 位 → 400**，6 位为 2026-11-19 产品裁决，常量
   `MIN_PASSPHRASE_LENGTH` 前后端各引一份、注释互指）；写进 `newConfig`。
2. **服务端 GET / PUT 响应**：新增 `hasPassphrase: boolean`，**永不回传口令本身**
   （它是加密密钥，回传等于把解钥摊在接口里）。
3. **Web UI**：
   - 门禁判据改成「输入框有值 **或** 服务端已存过」。只看输入框是错的 ——
     口令不回显，用户刷新页面后输入框必然为空，已设过口令的人改个路径就会被自己拦下；
   - 输入框下方显示「已设置 / 尚未设置」，让状态可见；
   - 保存成功后清空口令输入框（与密码一致：写一次、之后不回显）。
4. **不因「启用但没口令」而 400**：保存配置与能否上传是两件事，先填地址、回头设口令是
   合理流程；真上传时由 `runWebdavBackup` 拦下并给出与事实一致的提示。

## 测试

- `备份口令落库（v2.1.1 回归）` 4 条：落库 + `hasPassphrase=true`（且不回明文）、
  二次保存不带口令仍保留、< 6 位 → 400、启用但无口令如实 `hasPassphrase=false`。
- 新增 `server/tests/domain/backup-crypto.test.ts` 4 条：口令往返、错口令抛
  `MnFormatError`、空口令拒绝打包、产物名 `.mn`。这条链路以前在 CI 里**零覆盖**。
- `npm run check` 全绿（tokens / 双端 typecheck / 全部测试 / web 构建）。

## 影响与善后

- 已配过 WebDAV 的实例：库里从来没有口令，**升级后需要重新填一次**（界面会显示「尚未设置」）。
- 之前每天失败的后台备份不会补跑历史，下一次调度即恢复正常。
- 口令一旦丢失，已上传的 `.mn` 无法解密（服务端按设计不保存明文、也无法回显）——
  界面文案里已写明「忘记口令将无法解密备份」。

## 一个未处理的相邻问题（记在这里，不在本次范围）

WebDAV 真实网络/协议错误（地址错、账号错）目前抛的是普通 `Error`，被 Fastify 兜成
`500 服务器内部错误`，前端只能显示这句没信息量的话 —— 用户拿不到「HTTP 401」这种可行动提示。
`runWebdavBackup` 里上传失败那条分支有良好文案（会写进备份状态），但 `ensureRemoteDir`
之前的分支没有。要不要统一成 4xx/502 + 原文，另开一次改。
