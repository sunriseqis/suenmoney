# 2026-10-24 用户三条反馈的定位与修复

用户反馈（原文）：
1. 文字输入框可见性差浅色主题
2. 字体完全一样
3. 跟 web 端完全不是一个东西，客户端应该 1:1 照搬 web 移动端

## ① 输入框可见性

**根因**：我给 TextInput 用的是 `backgroundColor(surface2)` 且**没有边框**。
`surface2`（candy `#F8F7FF`）与页面底 `#FFFDF5` 几乎同色，等于隐形。
原型 `.input` 是 `background: var(--surface)` + `border: 2px solid var(--line)` + `border-radius: var(--r-md)`。

**修法**：输入框统一走原型写法 —— `surface` 底 + `borderW` 边 + `rMd` 圆角 + `fontColor(ink)`。
边色上，candy 用 `--line-2`（`#1E293B`，设计系统里的强线）而不是 `--line`（`#E2E8F0`），
因为 `#E2E8F0` 在白底上对比度太低 —— 这正是用户说"看不见"的直接原因。

## ② 字体完全一样（这是个真 bug）

**根因**：`font.registerFont({ familySrc: 'rawfile/fonts/Outfit.ttf' })` ——
`familySrc` 必须是 **`$rawfile(...)` 资源对象**，传字符串时注册不生效，
而我把它包在 try/catch 里，失败被吞掉，于是**所有文字回落系统字体**。

官方 FAQ（`devecocli docs read` 查得到）的写法是：

```ts
this.getUIContext().getFont().registerFont({
  familyName: 'Gealova',
  familySrc: $rawfile('font/gealova.otf')
})
```

**修法**：新增 `common/theme/FontRegistry.ets`，用 UIContext + `$rawfile`，
在 LoginPage / MainPage 的 `aboutToAppear` 各调一次（静态标记防重复）。

**验证（不靠眼睛）**：同一串 `2026-10` 在两套主题下的实测宽度

| 主题 | 字体族 | 实测宽度 |
|---|---|---|
| candy | Outfit | **143 px** |
| cyber | Orbitron | **195 px** |

宽度不同 ⇒ 字体真的换了。（在此之前两者一定是同一个值。）

## ③ 不像 Web：改成按原型数值搬

之前是"照文档自己画"，只借了令牌颜色，尺寸/边框/阴影全是自己定的。
现在建了 `common/ui/UiStyle.ets`，把原型 CSS 的写法翻译成 ArkUI 参数：

- `parseShadow(css)`：`"6px 6px 0 #E9EEF6"` → `{offsetX:6, offsetY:6, radius:0, color}`
- `cardShadow()` / `btnShadow()`：candy 硬阴影；cyber 无阴影 + 细环
- `radiusOf()`：cyber 一律 0（原型用 clip-path 切角），candy 用 token
- `fontDisplayOf()/fontBodyOf()/fontMonoOf()`：与 `--font-display/--font-body/--font-mono` 对齐

同时修了一个令牌缺口：**`:root` 里的变量没被收进 token**
（`--density-pad: 18px` / `--density-row: 12px`），
导致卡片内边距只能瞎写。生成器已改为「`:root` + 主题块」合并，令牌从 49 → **51**。

已按原型数值落地的部分：

| 原型 | ArkUI |
|---|---|
| `.card` padding `--density-pad`(18) · border `--border-w`(2) · radius `--r-card`(20) · 硬阴影 `6px 6px 0 #E9EEF6` | 已套用到报表/设置/概况/流水卡片 |
| `.input` 2px 边 + rMd(14) + surface 底 | 登录/设置/抽屉输入框 |
| `.m-row` padding `10px 12px` + 2px 边 | 流水行卡 |

## 教训

1. **不要在 try/catch 里静默吞掉框架 API 的错误** —— 字体注册失败被吃掉，
   表现是"字体没变"，而代码看起来是对的。
2. **"1:1 照搬"意味着照抄 CSS 数值**，而不是"理解设计意图后自己实现"。
   后者每次都会漂移，而且漂移得很像样、很难发现。
