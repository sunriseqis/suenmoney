## 二、几个刻意的选择

| 选择 | 理由 |
|---|---|
| 探活**顺序执行**而不是并发取最快 | 家用环境备用地址通常不可达，并发会让每次启动都白等最慢的超时；顺序 + 4s 快失败更可预测 |
| 错误**按类型说人话** | 401 说「登录名或口令不对」，网络错说「连不上服务端」，其余用服务端返回的中文 message —— 把 401 说成「网络不好」会让用户去查路由器 |
| 不缓存用户资料 | 资料随 `/api/auth/me` 取；缓存了会在改显示名后仍显示旧名字 |
| 登出只清本机令牌 | 与 Web 一致（本机先干净），不强制注销服务端会话 |
| 占位页只写「哪一阶段实现」 | 不放假内容 —— 假数据会被当成功能已完成的证据 |

## 三、ArkTS/ArkUI 又踩到的坑

1. **`@State tabIndex` 与基类属性冲突** —— `Property 'tabIndex' in type 'MainPage' is not
   assignable to the same property in base type 'CustomComponent'`。
   按技能里的规则：@State 成员名不能与框架属性/方法重名 → 改 `currentTab`。
2. 顶层 interface/class 不能重名（arkts-no-decl-merging）→ 本项目的类型名统一加业务前缀
   （`CategoryNode` / `PlanItem` / `ExpenseItem`…）。
3. `Button('文案')` 与子组件互斥 → 只用 `Button('文案')` 形式。
