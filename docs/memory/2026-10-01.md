## 一、鸿蒙端（hw/）4 项修复

### 1. 生产包关闭 WebView 调试

`aboutToAppear` 里原来无条件 `webview.WebviewController.setWebDebuggingAccess(true)`。
改为按 `context.applicationInfo.debug` 判断（由 Hvigor 按 buildMode 注入：debug=true / release=false）。
新增 `isDebugPackage()`辅助函数，**取不到时按「非debug」处理** —— 宁可开发时少一个调试入口，
也不能让正式包带上它。

为什么必须改：`setWebDebuggingAccess(true)` 让任何人用 USB 连上设备就能 inspect 本应用
的全部 Web 页面（含用户账本数据、token）。正式包打开等于把线上数据裸奔给任何物理接触设备的人。

### 2. 明文 HTTP 网络安全配置

新增 `hw/entry/src/main/resources/base/profile/network_config.json`，
在 `module.json5` 的 `module` 段引用，允许内网明文 HTTP（本地自建服务走 http://）。

> **⚠️ 字段名未在真机验证。** `network-security-config` 下的
> `base-config.cleartextTrafficPermitted` / `domain-config[].domains[].name`、
> `include-subdomains` 均按安卓语义书写，鸿蒙 NEXT 的网络安全配置 JSON 键名与之**不一定一致**。
> 本机无鸿蒙 SDK，无法编译也无法真机验证。首次上真机若发现明文仍被拦，
> 优先怀疑此处键名，需查 HarmonyOS 官方文档核对（本条为遗留验证项）。

### 3. 避让区变化实时 runJavaScript 推送

`EntryAbility` 已监听 `mainWindow.on('avoidAreaChange')` 并写入 AppStorage
（`topAvoidHeight` / `bottomAvoidHeight`），但壳侧只用了首屏值，旋转/键盘弹出后 Web 拿到的
还是旧值。

改法：`Index.ets` 用 `@StorageProp(...) @Watch('onSafeAreaChange')` 接收变化，
经 `injectSafeArea()` 把 px2vp 后的高度写成 CSS 变量 `--safe-top` / `--safe-bottom`，
**100ms 去抖**（旋转/键盘会连续触发十几次，不合并就是白白重排）。

关键：**首屏注入与后续实时推送共用同一个 `injectSafeArea()`**（`onPageEnd` 里也调它），
避免出现「首屏一个口径、后续另一个口径」的不一致。

单位坑：ArkUI 避让区是 px，`--safe-*` 也按 px 用（`tokens.css` 里是
`calc(var(--safe-bottom) + ...)`），所以 px2vp 后仍以 `'px'` 结尾 ——
Web 只认 CSS px，写 vp 会被当成另一个数。

### 4. 返回键交给 Web 决策+ 补齐壳侧桥对象

`onBackPress()` 现在只做转发：`runJavaScript('window.__suenmoneyOnNativeBack && window.__suenmoneyOnNativeBack()')`，
返回 `true` 表示已被消费。老 Web 包（没注册这个函数）时表达式求值为 `undefined`，
自然落回原生 `accessBackward()` 逻辑，**降级行为与改动前完全一致**。

`onPageEnd` 里注入三个东西（`injectNativeBridge()`，原 `injectExitHandler` 改名扩展）：

```js
window.__suenmoneyExit = function () { SuenHarmony.exitApp() };
window.__HARMONY_NEXT__ = true;
window.__suenmoney = {
  platform: 'harmony',
  version: <bundle 版本对象 或 null>,
  exit: function () { SuenHarmony.exitApp() }
};
```

**为什么 `window.__suenmoney` 必须存在**：Web 层与壳之间只有这一份显式契约，
Web 靠读它决定三件事——

| Web 消费点 | 读什么 | 桥缺席的后果 |
|---|---|---|
| `platform/env.ts` | `window.__suenmoney?.platform === 'harmony'` | 认不出鸿蒙，退回`SuenHarmony`/`__HARMONY_NEXT__` 猜测 |
| `platform/update.ts` | `.version` | 读不到 → `getNativeAppVersion()` 返回 null → **鸿蒙端永远查不到更新** |
| `platform/lifecycle.ts` | `.onAppState` | 拿不到 → 回退 visibilitychange（可接受） |

三个故障**同时出现且都不带日志**，是最难查的一类静默降级。

**必须是赋值注入，不能是裸对象字面量语句。** ArkTS 里 `{platform:'harmony', ...}`
作为独立语句不合法（对象字面量只能出现在赋值右侧或传参位置）——
这正是另一个项目当天踩的编译坑。故统一写成 `window.__suenmoney = {...}`。

**`version` 读失败传 `null`，不伪造 `{versionName:'1.0.0', versionCode:1}`。**
伪造版本号会被前端当真：服务端拿1.0.0 去比对，永远判定「有更新」，
用户反复看到「发现新版本 1.0.0」的假提示，点进去还装不了。宁可说不知道。
为此把 `getAppVersion()` 拆出 `getAppVersionLiteral()`（返回可直接嵌入脚本的 JS 字面量，
失败返回字符串 `'null'`），老接口 `getAppVersion()` 复用同一实现，
于是「壳伪造 1.0.0」在**两条**读取路径上同时消失。

**`onAppState` 键不提供**：壳目前**没有**前后台事件源 —— Ability 的
`onForeground`/`onBackground` 只打了日志，既没写 AppStorage 也没 `runJavaScript` 推送。
塞个空函数等于「假装有」：`lifecycle.ts` 会以为订阅成功，反而**不再回退**
visibilitychange，把现在能用的降级路径也弄坏。少一个键，`bridge.onAppState?.()` 会安全跳过。

**`safeArea` 键不提供**：壳的避让区推送是直接写 CSS 变量（`injectSafeArea`），不经过这个对象；
且 Web 侧**没有任何地方调用** `bridge.safeArea`（只有 `env.ts` 的接口声明），提供了就是死代码。

## 二、跨端契约与三个集成缺口（并行改动留下的坑）

今天有多个改动并行进行，壳侧与Web 侧各自改一半，产生了三处**只有合起来看才发现**的缺口。

### 缺口 ①：原生「一次性探测」+ Web「等桥注入后才注册」的时序冲突

- 原生曾在 `onPageEnd` 做**一次性探测**：读Web 有没有 `__suenmoneyOnNativeBack`，把结果缓存。
- Web 侧 `setupHardwareBack` 当时是 `whenNativeBridgeReady`（等`window.__suenmoney`出现，最多轮询 5 秒）**之后**才注册。
- 两者赛跑：只要 Web 晚一步，探测得到 `false` 并被**永久缓存** →
  「有未提交草稿时按返回键」这个拦截**永远不会生效**，而且不报错。

**最终解法**（两边都改）：
- 原生：删掉一次性探测，`onBackPress` 改为**无条件转发**，
  用 `window.__suenmoneyOnNativeBack && ...` 现场判断——「有没有注册」这件事
  交给壳在**每次**返回键时判断，Web 不必替它预判。
- Web：`setupHardwareBack` 改为**立刻注册**（不等桥），拿到桥后再注册一次以刷新 options。
  注释写清「后注册覆盖先注册」是为了 HMR / 组件重挂载时用最新 options，
  避免拿到上一次的 stale 回调（这正是早期「幂等跳过」写法埋的坑）。

>教训：**探测结果是一次性快照，被探测方的注册时刻不可预知时，快照必然过期。**
> 跨边界的能力握手要么由提供方在每次调用时现场判断，要么就别缓存。

### 缺口 ②：`before-back` 事件无人监听

`hardware.ts` 定义了 `BEFORE_BACK_EVENT = 'suenmoney:before-back'`，
`askBeforeBack()` 会派发这个同步 DOM 事件等业务侧表态 ——
但**没有任何组件监听它**。于是「有没有未保存内容」永远得到「没有」，
返回键在二级页面上直接退到上一页而不是提示用户，脏表单照样丢。

**最终解法**：新建 `web/src/utils/draft.ts`（草稿本地持久化），
`ExpenseSheet.vue` / `PlansPanel.vue` 持有脏数据时挂监听，
在事件上 `preventDefault()` 或写 `detail.shouldIntercept = true`。

为什么用同步 DOM 事件而不是回调：鸿蒙返回键是**同步**回调原生函数的，拿不到 Promise。

### 缺口 ③：idb 写函数改抛错后，4 处 `void saveCachedXxx()` 没有 catch

`utils/idb.ts` 的写函数从「静默吞错」改成「抛错」（见第三节）之后，
调用方的 `void saveCachedXxx()` 因为加了 `void`（显式丢弃 Promise），
产生的 rejection **无人处理** → unhandled rejection。

**最终解法**：**5 处**调用点补 `.catch(() => {})`
（`stores/dictionaries.ts` 的分类/支付方式 2 处、`stores/plans.ts` 的计划/待办 2 处、
`views/LedgerView.vue` 的流水副本 1 处）。
注意这些 catch 吞掉的是**缓存副本**写失败 —— 服务端数据已到手，写不进去最坏结果是
下次打开没有秒开、断网时没有本地兜底，不该把整次 load 变成失败；
**真正不能吞的是离线记账写入（`stores/sync.ts`），那里失败会照实抛给用户**。
两侧的取舍相反，是刻意的：缓存失败降级、账目失败报错。

> 教训：`void promise` 不是「安全丢弃」，它是「明确告诉 lint 我知道我在丢弃」。
> 把一个函数从静默失败改成抛错，等于把它所有调用方都变成新的崩溃点。

## 三、离线数据安全

### idb 写函数改为抛错

原来 IndexedDB 写函数失败时静默 resolve，界面报「保存成功」而账**根本没写进去** ——
最严重的一类丢数据，且无任何提示。

改为 reject，并补`tx.onerror` / `tx.onabort` 两个处理器。

**关键点：配额类错误（`QuotaExceededError`）在事务提交时才抛，必须等 `tx.oncomplete`。**
早期实现只挂了 `oncomplete => resolve()`，请求对象本身不抛错，
于是配额溢出会走到 `oncomplete` 被当成成功 —— 写入其实没生效。
正确做法是三个处理器都挂：`oncomplete` 成功、`onerror` / `onabort` 失败，
失败时带上可读上下文（`storageWriteError('流水本地副本', err)`）。

### stores/sync.ts 冒泡 OfflineWriteError

新增 `OfflineWriteError`（`extends Error`，带 `cause`）与 `toOfflineWriteError(action, err)`，
由 `writeOffline(action, run)` 包裹离线写路径（失败时抛可展示的错误，且**不**触发 `scheduleSync`
—— 队列里根本没这笔操作，调度只会做一次无意义的网络往返并让 UI 误以为已入队）。

**8 个离线操作**现在把 idb 写失败**冒泡**给调用方，而不是吞掉 ——
界面必须能告诉用户「这笔没存上」：离线保存 / 修改 / 删除 / 确认待办 / 跳过待办 /
知晓待办 / 撤销确认 / 恢复待办。

### 死信队列可见

- `deadLetters` / `deadLetterCount`：重试超限的 outbox 记录可以被看到。
- **但死信不计入 `pendingCount`**。理由：把它们算进「待同步」会让人误以为还有 N 笔在排队，
  实际上它们已经失败了、不会自己重试。分开呈现才诚实。

### 不再写伪造的「未知分类 / 未知支付方式」

原来解析不出分类/支付方式时写一个占位名（形如「未知分类」）。
问题：这个占位会被**同步扩散**到所有设备 —— 一台设备解析失败，
占位分类就进了服务端字典库，别的设备再看到这个分类名，
于是「一次解析失败」变成**永久黑洞**，再也回不到正确的分类。

改为写**空串**，让分类留空、用户自己补。空串不参与字典扩散。

## 四、导入与交互

### CSV 导入指纹防重导

服务端 `POST /api/expenses/batch` **没有客户端指纹去重**，每一行都是新 ULID，
同一份 CSV 再导一次就是**再插一遍**。

指纹 = `${文件名}|${字节长度}|${行数}|${金额合计}`，存 localStorage，**只留最近 5 条**
（够覆盖「刚才导过的那份」，又不至于让 localStorage 无限长）。

- 必须在**解析成功后**才算指纹（行数与金额合计来自解析产物）。
- **导入成功（哪怕只成功一部分）才记指纹**：一笔没进的批次不该被标记成「导过了」。
- 命中指纹时弹确认块，未表态前「确认导入」保持禁用；用户可选择「继续导入」或「取消」。
- 已知局限（注释里写明）：复制一份改名再导 → 文件名不同 → 指纹不匹配 → 静默放行。

**并纠正了一处错误注释**：原注释写「CSV 导入幂等」——**错**。
幂等的是 **JSON 合并导入**（按自然键 upsert）；CSV 是纯追加，不幂等。
这条错误注释很可能就是「以为 CSV 重复导入天然安全、于是没做防重」的根本原因。

### 记账草稿本地持久化

新建 `web/src/utils/draft.ts`：
- 分 key：`new:<账期>` / `edit:<id>`（新建与编辑各自的草稿不互相覆盖）。
- **24h过期**：跨天还在的半截账，多半是用户已经放弃了。
- **400ms 防抖**：每次输入都写 localStorage 会造成明显卡顿。

配合缺口 ② 的 `before-back` 监听，鸿蒙返回键在有草稿时会提示而不是直接丢弃现场。

### in-flight 守卫与序号守卫

- 提交与待办动作加 **in-flight 守卫**：连点两次不会发两次请求（ExpenseSheet / PlansPanel）。
- 视图请求加**「只认最新一次」序号守卫**（新建 `web/src/utils/latest-request.ts`）：
  快速切筛选/切tab 时，先发的请求可能后到，把旧结果覆盖到新视图上。
  每次请求领一个自增序号，回来时序号不是最新的就丢弃结果。

## 五、编码与时区

### decodeCsvBuffer：关键词启发式 → 严格 UTF-8 优先

原来用「文件里有没有中文关键词」来**猜**是不是 GBK。这个判据不可靠：
关键词依赖文件内容的词汇（换成「备注」「项目」就失效），
且 GBK 文件若恰好没出现关键词就会被当成 UTF-8，解析出一堆乱码。

改为：**先严格按 UTF-8 解码，只有解码失败才回退 GBK**。
让编码器自己告诉我们答案，而不是靠猜。

### WebDAV 每日备份判定：UTC → 本地日期

原来用 `new Date().toISOString().slice(0, 10)`取「今天」—— 那是 **UTC** 日期。
容器时区固定东八区（`server/Dockerfile` 的 `TZ=Asia/Shanghai`），比 UTC 快 8 小时，
于是**北京时间 00:00–08:00 之间 UTC 还停在前一天**，「今天已备份」的判断会把昨天的成功记录
当成今天的 → 当天的定时备份被**静默跳过**，且不报错（备份列表停在昨天，看起来像正常轮转）。

抽出 `localDateString(d)`（用 `getFullYear`/`getMonth`/`getDate` 本地 getter）
与 `hasBackedUpToday(status, now)`（把UTC 存储的 `lastBackupAt` 也转成本地日期再比，两边同一口径）。

刻意**不把 `Asia/Shanghai` 写死进代码**：本地 getter 读的就是进程 TZ，
与容器 `TZ` 保持同一口径，将来改 `TZ` 不用改代码，
也不会出现「代码写死 +08:00、容器换时区」两处打架。
每日物理快照调度（`snapshots.ts` 的 `todaySnapshotPrefix`）用的是同一套本地 getter，两边一致。

**验证数字**（`TZ=Asia/Shanghai` 下，新增 `server/tests/http/webdav-local-date.test.ts`）：
`2026-10-01T00:30+08:00` === `2026-09-30T16:30Z`，此时
`d.toISOString().slice(0,10)` 返回 `2026-09-30`（UTC，**晚一天** —— 测试里先断言这个前提），
而 `localDateString(d)` 返回 **`2026-10-01`**（本地）。这组对比就是误判的根源。

反向同样成立：`2026-10-01T16:30Z` === `2026-10-02T00:30+08:00` → `localDateString` 返回 `2026-10-02`。

`hasBackedUpToday` 的关键断言（本地 `2026-10-01T00:30+08:00` 为 now）：
- 昨天 23:00 本地（`2026-09-30T15:00Z`）的备份 → `false`，当天备份仍要执行；
- 旧实现在此会误判：`todayStr` 取到 `'2026-09-30'`，`lastBackupAt` 也是 `2026-09-30T…Z`，
  `startsWith` 成立 → 当天备份被静默跳过；
- 今天 00:10 本地（`2026-09-30T16:10Z`，**UTC 日期是 9-30**）的备份 → `true`，
  证明判定用的是本地日期而非 UTC 日期前缀；
- 从未备份 / 上次失败 / 时间戳损坏 → 一律 `false`（宁可多备份一次，不漏）。

每日物理快照调度（`snapshots.ts` 的 `todaySnapshotPrefix`）用的是同一套本地 getter，
测试断言 `todaySnapshotPrefix('2026-10-01T00:30+08:00') === 'suenmoney-snapshot-20261001'`，
保证两处口径一致、凌晨都不退回昨天。

## 七、本轮教训（来源：另一个项目 `/home/suenmusic`` 当天的鸿蒙移植排障）

核心可迁移项：

1. **系统 API 调用前清洗 undefined** —— 把 `undefined` 传进系统 API 得到的是
   「不报错但行为诡异」，比抛错更难查。
2. **关键渲染路径不许有网络 await** —— 首屏渲染被一个网络请求挂住，
   在弱网/内网环境下就是白屏。
3. **异步回填必须带序号守卫** —— 「后到的旧请求覆盖新结果」是前端最隐蔽的一类bug。
4. **缺数据不伪造占位** —— 假数据会被当真、会扩散、会变成永久黑洞
   （「未知分类」扩散成字典库里的常驻项就是活例）。
5. **去掉兜底前确认另一条腿承重** —— 拿掉一个降级路径前，先确认替代路径真的存在；
   本轮缺口 ① 就是「原生探测」与「Web 等待」互相以为对方承重。
6. **平台门控要逐端核对** —— `isHarmony()` 这类门控必须把每个端都单独走一遍，
   漏一个就是该端整条链路静默空跑（鸿蒙端查不到更新就是漏了 version 这一环）。
---

## 八、ArkTS `WebResourceResponse` 导入写法（10505001）

1. `WebResourceResponse` **只能默认导入**：`import WebResourceResponse from '@ohos.web.webview';`。
   具名导入（`import { WebResourceResponse } ...`）与 `webview.WebResourceResponse` 命名空间访问
   都会报 10505001「has no exported member」——编译器给出的默认导入提示是唯一可靠依据。
2. 类型标注 `WebResourceResponse | null` 与 `new WebResourceResponse()` 在默认导入下都成立，
   无需改使用点；`webview` 命名空间仍单独来自 `@kit.ArkWeb`，只用于 `WebviewController`。
3. **ArkTS 只报首个致命错误**：`COMPILE RESULT:FAIL {ERROR:2}` 里只列出 1 条，
   第二条很可能是连带影响。改完一处不能假设就绿，必须靠 CI 复跑确认。
