# iOS 首次真编译：5 类错误 + 鸿蒙 CI 的产物名断链（2026-11-04）

容器里没有 SQLite3 模块、也没有 iOS SDK，iOS 代码从写出来那天起**一次都没编译过**。
这次手动派发 CI 真编译，暴露 5 类错误（全部与「并发隔离 / 结构体字段」有关），
外加发现鸿蒙流水线本身是断的。

## 一、iOS：5 类编译错误（`ad0f920`）

| # | 位置 | 错误 | 修法 |
|---|---|---|---|
| 1 | `PlanActions` 5 处 / `ExpenseActions` 3 处 | `SyncEngine` 是 **actor**，`schedulePush()` 是 actor 隔离方法 | 异步函数补 `await`；同步上下文包 `Task { await … }`（防抖推送本来不用等） |
| 2 | `ExpenseActions.currentOwnerId()` | 读了 `@MainActor` 的 `AuthStore.shared.user` | 改成**只读 meta 的 `current_user_id`**：登录时已写入，与鸿蒙取法一致，「内存优先」那层本来多余 |
| 3 | `Palette.categoryColorOf` | 读 `@MainActor` 的 `ThemeManager.shared.tokens` | 函数标 `@MainActor`（调用点全在 SwiftUI 视图里） |
| 4 | `DictionaryDao.paymentsList` | `PaymentMethodItem` 缺 `monthExpenseCount`（memberwise init 顺序在最前） | 传 `nil`：本地表没有「本月笔数」，那是服务端按当前月算的 |
| 5 | `LedgerScreen.loadLocalDict` | 把 `paymentNames`（`[String: String]`）的 `.values`（String）当对象取 `.id/.name/.icon` | 选项列表改走 `DictionaryDao.paymentsList()`（带 icon、按 sort_order，与鸿蒙一致） |

结论：CI 一次派发就把 5 处全暴露了 —— 说明「静态核对」确实替代不了编译器，
以后 iOS 改动必须走 CI（`workflow_dispatch`，`publish_release=false` 只编译不发布）。

## 二、鸿蒙 CI：构建成功却被判失败（`af2eade`）

`hvigor BUILD SUCCESSFUL` 之后必挂在 **Verify Artifact → exit 1**。原因纯粹是名字对不上：

- 构建步骤 `cp` 成 `app/suenmoney-<VERSION_NAME>.hap`
- 而 Verify Artifact / Upload HAP / Publish Release / 清理白名单认的是
  `app/SuenMoney-v<VER>-unsigned.hap`

**⚠ 这里我第一次修错了方向**：把下游对齐到「老名字」，而产物命名早就裁决成
`suenmoney-<版本>.<ext>`（全小写、不带 v、不带 `-unsigned`/`-release`）。
正确修法（`af2eade` 之后的第二次修）是把**上游**对齐到裁决口径：
构建步骤落名 `app/suenmoney-<版本>.hap`，Verify / Upload / Publish 三处跟着改，
清理白名单只放行 `suenmoney-<版本>.{fpk,fpk.sha256,hap,ipa}` ——
老风格资产出现在同一个 Release 上就该被清掉，不能一个版本两种命名并存。

教训：命名不一致时，**先确认哪一边是裁决口径**，别默认「下游是权威」。
`docs/ci.md` 里的附件清单当时也是老名字，同步改了。

## 三、版本号（`0c9325c`）

`VERSION` 已是 2.1.0（`7cd4951`），但 `ios/SuenMoney.xcodeproj` 的**默认值**还是
`MARKETING_VERSION = 0.4.0` / `CURRENT_PROJECT_VERSION = 1`。脚本构建会覆盖，
但 Xcode 手动 Run/Archive（真机验证就是这条路）产出的包会自称 0.4.0 → 已改成 2.1.0 / 2010000。

## 四、发布状态

- `suenmoney-v2.1.0` Release 已存在，但**只有 `suenmoney-2.1.0.fpk`**
  （鸿蒙卡在名字校验、iOS 从来没编译成功过）。
- 本轮两次派发都用了 `publish_release=false`，只验证编译，没往 Release 塞包。
- 要补 hap / ipa：分别用 `publish_release=true` 重跑两个工作流即可。

## 五、命令备忘

```bash
TOK=$(cat /tmp/.ghtok)
# 只编译不发布
curl -X POST -H "authorization: Bearer $TOK" -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/sunriseqis/suenmoney/actions/workflows/build-ios.yml/dispatches \
  -d '{"ref":"main","inputs":{"publish_release":"false"}}'
# 看运行状态 / 步骤
curl -H "authorization: Bearer $TOK" .../actions/runs?per_page=3
curl -H "authorization: Bearer $TOK" .../actions/runs/<id>/jobs
# 下日志（必须带 -L 跟随 302）
curl -sL -H "authorization: Bearer $TOK" .../actions/jobs/<jobId>/logs -o /tmp/log.txt
```
