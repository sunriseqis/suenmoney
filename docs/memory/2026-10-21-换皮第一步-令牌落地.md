## 一、做了什么

| 交付 | 说明 |
|---|---|
| `scripts/gen-tokens.mjs` | `tokens.json` → **三份产物**：`web/src/styles/tokens.generated.css`、`docs/design/generated/DesignTokens.swift`、`Tokens.ets` |
| `npm run tokens` / `tokens:check` | 生成 / 校验漂移；`tokens:check` 已接进 `npm run check` 的第一道 |
| `web/src/styles/tokens.css` | 重写为「手写四样 + @import 生成产物」：字体栈 / 布局与安全区 / 分类图表色 / 浅色回退 |
| `--border-strong` | 可交互控件的边界从 `#3A3852`（1.64:1）换成 `#706D96`（container 上 3.4:1）—— WCAG 1.4.11 |

**兼容别名**是这次能一天变暗的关键：老组件大量使用 `--bg / --fg / --border / --r-sm / --r-md`，
生成的令牌把它们映射到 v3 值（`--bg → var(--surface)`、`--r-sm → 14px`、`--r-md → 24px`），
所以**不用一次性改两百个类名**就能让全站换底。逐条对照在 `tokens.generated.css` 末尾。

## 二、主题机制反过来了（这一点必须记住）

```
旧：不写 data-theme → 跟随系统（深色走 prefers-color-scheme）
新：不写 data-theme → **深色（v3）**，不看系统偏好
    data-theme="light" → 旧扁平浅色（回退，待裁决是否删除）
```

理由：v3 是一套深色设计，跟随系统会让浅色系统用户看到**两套完全不同语言的界面**。

> **待你裁决**：浅色要不要保留？
> ① 彻底删掉（只留深色，最干净）；
> ② 给一套 M3 浅色（工作量大，但白天可读性更好）；
> ③ 就现在这样：浅色=旧扁平，作为回退。
> 我按 ③ 实现，因为它是唯一不需要你现在做决定的选项。

## 五、补记：用户反馈「和旧版本区别不大」→ 挖出三个真问题

用户这句话是对的。逐层排查（服务端给什么 → 产物里有什么 → 变量级联顺序）后发现：

1. **生成器 bug**：`cssWithExtras`（浅色主题 + chart 槽）组装后**从未写盘** ——
   `outputs` 数组里根本没有 CSS 产物，前面两次"✓ 生成"只写了 Swift 和 Ets。
   也就是说**浅色主题在线上从来没存在过**（`f6f4ef` 0 命中）。
2. **手写 tokens.css 里的旧 16 槽没删**：`chart-1:#3b82f6` 仍在级联里干扰生成块。
   已删 —— 单一真相源的意思就是**手写文件里不许再有同名定义**。
3. chart 槽已在上一轮做进 tokens.json，但因为 1+2，线上一直看不到。

修复后线上实测：默认 `#141222`（深色）、`[data-theme=light]` `#f6f4ef`、
`chart-1` 深色 `#6e9eea` / 浅色 `#2e5fb8`。

**教训（写给生成器作者）**：生成器最大的风险不是生成错，而是**生成完忘了写盘**或
**写盘的对象不是消费的那个文件**。验证手段只有一个：**读回最终产物，断言关键值在里面**
—— `--check` 模式就是为此加的，但它比对的是内存内容与磁盘内容，
所以磁盘上必须有东西可比对。这一轮的问题是「内存里对、磁盘上无」，
`--check` 恰好能抓到（内容 != 磁盘），但前提是先跑过一次生成让磁盘有基线。

## 六、v4 双设计系统落地（同日第二轮返工）

用户裁决：浅色参考 **Playful Geometric**（糖果硬阴影），深色参考 **Cyberpunk**（霓虹辉光+切角+扫描线），
LOGO 加彩色粗边框并做反色浅色版。

### 中间踩的坑（都修了）

1. **别名断层**：v4 重写生成器时丢了 `--bg/--fg` 兼容别名 → body 回退白底。
   「背景不对」的真因是别名，不是令牌。
2. **字体栈没接**：Jakarta/JetBrains 只装包没进栈 → 「字体不对」。
3. **CSS 产物从未写盘**：重构生成器时 outputs 数组丢了 CSS 项 → 浅色主题在线上不存在。
   三个都是「构建链某环节断了但命令仍然 ✓」—— 必须读回最终产物断言关键值。

### 落地内容

- tokens.json v4：双主题完整令牌（含 --el-pop/--el-neon/--chamfer/--scanlines/--circuit-bg）
- LOGO：mark-colored（四色粗环）/ mark-light（反色浅色）两形态，39 项产物
- 字体：Jakarta（浅正文）/ JetBrains Mono（深正文），按主题切栈，中文回落 MiSans
- base.css：panel-v4（深色切角+浅色圆角硬阴影）/ btn-v4（糖果钮 vs 霓虹描边钮）/ input-v4
  —— 全部变量驱动，**组件代码零改动**即可换语言
- 登录页、双抽屉已套；BrandMark 按主题切 mark/mark-light
- 扫描线纹理（仅深色）+ 电路网格背景

### 主题机制（最终版）

不写 data-theme = 深色 Cyberpunk；data-theme="light" = 浅色 Playful。
**两套是两种设计语言**（颜色、字体、圆角、阴影、动效曲线全不同），不是同一配色的明度变体。
