# 2026-10-24 主题全局化：从「各屏存快照」改成 AppStorage 广播

## 怎么发现的（这次不是靠眼睛）

我读不了图，所以用**数值取色**替代目视：

1. `hdc shell snapshot_display` 截图 → scp 回 Linux
2. `jpeg-js`（npm，纯 JS）解码 → 采样页面背景 / 底栏 / 顶栏三个点的 RGB
3. 与 `AppTheme.ets` 里的 token 对比

第一次采样结果：

```
cyber（默认）      背景 #11121a  底栏 #11121a  顶栏 #0b0a0e
candy（点了切换）   背景 #11121a  底栏 #11121a  顶栏 #0b0a0e   ← 没变！
candy（流水页）     背景 #11121a  底栏 #11121a  顶栏 #0b0a0e   ← 没变！
```

**三张完全一样 ⇒ 主题切换根本没生效。**

## 根因

每个屏都写 `@State tokens: ThemeTokens = ThemeManager.get().tokens;` ——
这是**在 `aboutToAppear` 时取的一份对象快照**。在设置页调
`ThemeManager.set('candy')` 只改了单例内部状态和设置页自己那份副本，
其他屏（以及已经建好的 Tab）仍持有旧对象，`build()` 拿到的还是旧色。

`@State` 只代理第一层，换对象引用本来应该触发重绘 —— 但 `tokens` 是普通
interface 对象，各屏之间没有任何联动机制，切主题时没人通知它们。

## 修法：主题名广播 + 每次 build 重新取令牌

```ts
// ThemeManager
export const THEME_STORAGE_KEY = 'themeName';
AppStorage.setOrCreate(THEME_STORAGE_KEY, name);   // init 与 set 都广播

// 每个屏
@StorageLink(THEME_STORAGE_KEY) themeName: string = ThemeManager.get().name;
private tok(): ThemeTokens { return this.themeName === 'candy' ? CANDY : CYBER; }
// build 里一律 this.tok().xxx
```

改到 7 个文件：MainPage / LoginPage / LedgerScreen / DashboardScreen /
ReportScreen / SettingsScreen / ExpenseEditor。

同时补了这两处（之前漏的）：

- **底栏**：原来用 `.tabBar('流水')` 字符串 → 系统默认色，不随主题。
  改成自定义 `@Builder tabBarItem($$: TabItemView)` + `barBackgroundColor` + `divider`
- **状态栏/导航栏**：`setWindowSystemBarProperties({statusBarColor: tokens.bg,
  statusBarContentColor: tokens.ink})`，否则浅色主题下顶部还是深色，
  像被切了一刀

## 教训

**「主题」不是每个屏各自持有的一份颜色，而是一个全局可观察的状态。**
只要有一处写成快照，切换就会「设置页变了、别处没变」——而这种不一致
只靠代码审查很难发现，靠取色一测就露馅。
