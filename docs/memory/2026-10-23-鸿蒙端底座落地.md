## 三、几条做对了的决定

| 决定 | 理由 |
|---|---|
| 主题用**生成器**（`scripts/gen-hw-theme.mjs`）而不是手抄 | 49 个令牌手抄必漏，漏项表现是「某处颜色差一档」，不报错、极难查 |
| 列名用 **snake_case**，与同步快照一致 | 省掉「本地模型 ↔ 传输模型」映射层，而映射层是最容易一边改一边忘的地方 |
| 超时**分开设**：connect 4s / read 10s | 连接慢＝地址不通，要快失败换服务端；读慢＝服务端在算报表，要给时间 |
| 错误**四分类**而不是一句「请求失败」 | 401 要跳登录、网络错要进离线、5xx 可重试、4xx 重试无用——混在一起后续全走错分支 |
| `preferences` 键名与 Web 的 localStorage 同名 | `suenmoney:theme` / `suenmoney:token`，将来互通与排错省一轮猜 |

## 四、ArkTS 踩到的坑（都修了）

1. **对象展开被禁**：`arkts-no-spread` —— `{...a, ...b}` 不行，必须先建对象再逐字段赋值。
   → `ApiClient` 里改成 `const reqOptions: http.HttpRequestOptions = {...}` 再 `reqOptions.extraData = body`。
2. **裸对象字面量被禁**：`arkts-no-untyped-obj-literals` —— `JSON.stringify({a,b})` 不行，
   必须对应显式 interface。→ 新增 `LoginRequest` 接口。
3. **INTERNET 权限**：`http.request` 需要 `ohos.permission.INTERNET`，
   在 `module.json5` 的 `requestPermissions` 里加。
4. `check arkts` 会报「Function may throw exceptions」警告（不是错误）——
   这些是有意向上抛的（让调用方决定），保留了。

## 六、H0-5 向量 runner：为什么用生成器

向量是**三端契约**，不该在鸿蒙端再抄一遍：手抄一份等于契约有了第二份副本，
以后 Web 加用例、鸿蒙没跟上就再也发现不了。

做法：
- `scripts/gen-hw-vectors.mjs` 读 `docs/test-vectors/vectors.json` →
  生成 `common/contract/VectorRunner.ets`（每条用例编译成一个 `r.check(...)`，
  类型全静态，不走反射 —— ArkTS 本来也不允许）
- `common/contract/Contract.ets` 是纯逻辑层，与 Web 的
  money/dates/urgency/donut **逐条同义**（含「禁止 parseFloat×100」「-0.50 不能翻正」
  「分期末期补差」「负 ratio 钳到 0」这些踩过的点）
- 骨架页加了「跑测试向量」按钮，点一下把报告显示出来 —— 截图即证据
- ulid 用例暂未进 runner：鸿蒙端还没有 ulid 实现（H7 同步才需要）

## 七、H0-6 字体：woff2 → ttf 的离线转换

原生端只认 ttf/otf，而 `@fontsource` 只发 woff2。本机没有 pip，
所以用 npm 的 `wawoff2` 在临时目录里转换（`/tmp/fontconv`），产物放进
`entry/src/main/resources/rawfile/fonts/`：

| 逻辑族名 | 文件 | 大小 |
|---|---|---|
| Outfit | Outfit.ttf | 69KB |
| Orbitron | Orbitron-700.ttf | 16KB |
| PlayJakarta | PlusJakartaSans.ttf | 61KB |
| JetBrains | JetBrainsMono.ttf | 95KB |

`Fonts.register()` 在 Ability 启动时注册，失败只记日志不阻塞启动
（字体退化不等于不能用）。`displayFont()/bodyFont()` 按主题给族名，
与 Web 的 `--font-display` / `--font-body` 同义。

> 中文字形暂用系统 HarmonyOS Sans：MiSans 的 npm 包同样是 woff2 且分片极多，
> 转 ttf 体积会很大；留到 H8 打磨期再评估是否需要内置。
