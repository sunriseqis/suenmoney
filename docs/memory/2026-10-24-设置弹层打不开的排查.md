# 2026-10-24 设置页表单弹层打不开（未解决，留档）

## 现象

设置页 7 个入口（新增类别/新增分类/编辑分类/新增支付/新增计划/添加成员…）
点击后**没有任何面板出现**。section 切页（账目/计划与还款/外观/家庭）本身是正常的，
说明点击事件在别处可用。

## 已排除

| 尝试 | 结果 |
|---|---|
| `bindSheet(this.sheetMode !== '', ...)` 挂到设置根 Column | 不弹 |
| 改 `bindSheet($$this.sheetOpen, ...)`（双向绑定）+ 打开时置 true | 不弹 |
| 改成**内联覆盖层**（Stack + 遮罩 + 贴底面板，`position({x:0,y:0})`） | 不弹 |
| 在 `openCategorySheet` 里加 `hilog.info(0x000B,'SetDbg',...)` | `hilog -x -T SetDbg` **无输出** |

`hilog` 无输出有两种可能：① onClick 根本没触发；② 我的 hilog 过滤/落盘方式不对
（之前 `hilog -x | findstr` 也出现过拿不到自己日志的情况）。

## 下一步该验的（按顺序，最省时间）

1. **先证明 hilog 通道可用**：在 `sectionButton`（已知能触发的按钮）里打一条
   `hilog.info(0x000C,'Probe',...)`，点一次页签看是否出现。若不出现 → 是日志读取方式的问题，
   之前所有"没调用"的结论都不成立，要改用 `hdc shell hilog | findstr` 或 `devecocli log`。
2. 若日志通道正常但 `openCategorySheet` 无日志 → 说明按钮确实没触发：
   试把 `Button('新增类别')` 换成 `Row{Text}.onClick`（与三入口同款写法，已验证可触发），
   或给按钮加 `.hitTestBehavior(HitTestMode.Block)` 排除遮挡。
3. 若 `openCategorySheet` 有日志但面板不出现 → 是覆盖层布局问题：
   把覆盖层从根 `Column` 移到 `Stack` 最外层（`Stack{ 内容; if(sheetOpen){ 覆盖层 } }`），
   并去掉 `position()` 改为 `Stack` 的 `alignContent: Bottom`。

## 追加结论（同日第二轮排查，关键发现）

**决定性实验**：把 `sheetOpen` 默认置 `true`、`sheetMode='category'`，重装启动 →
面板**仍然不出现**（dump 里无"保存/名称/图标"）。说明问题不在"点击没触发"，
而在**覆盖层的 DOM 位置**。

**根因**：ArkUI 的 `build()` **只能有一个根组件**。我那次插入把覆盖层写成了
根 `Column` 之后的**第二个根级节点** —— 编译器不报错，但该子树被**静默丢弃**，
所以永远不会渲染。

**正确的做法（下轮按此重写，不要再打补丁）**：
`build()` 的根改为 `Stack({ alignContent: Alignment.Bottom }) { 页面内容; if (sheetOpen) { 面板 } }`。
即：**根组件从 Column 换成 Stack**，而不是"在 Column 后面再加一个"。

**失败记录**：本轮用字符串/括号配对做了 3 次补丁式插入，分别产生 16 / 542 / 574 个
编译错误（把 struct 的右括号吃掉，后续 @Builder 变成顶层函数 → `arkts-no-standalone-this`）。
每次都靠 `git checkout HEAD -- SettingsScreen.ets` 回滚。
教训：这种"整体换根"的改动只能**整段重写 build()**，不能在旧结构上打补丁。
