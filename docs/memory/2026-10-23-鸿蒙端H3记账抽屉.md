## 二、三条硬口径（写错不报错，只算错）

1. **跨月必须明说**：预览从 `/api/expenses/preview` 取，还款日月份 ≠ 消费日月份时
   显示「这笔会记在 2026-11」，强调色加粗。这是本项目头号误解来源
   （信用卡还款日落到下个月，用户以为保存失败）。
2. **金额整数分**：输入是文本，落库前 `parseYuanToCents()`（整数运算），
   全程不出现 `parseFloat*100`。
3. **退款不加负号输入**：用 Toggle 把正值翻成负数 —— 让用户手输「-」很容易出「-¥-50」。

## 三、入口：下拉手势（唯一，不留兜底）

与移动 Web 完全一致：列表顶部向下拖 > 80vp 才唤出抽屉。
实现用 `parallelGesture(PanGesture(Down))` + `Scroller.currentOffset().yOffset <= 0`
判断「确实在顶部」，否则正常滚动优先。

> 这是本计划里唯一「手势即唯一入口」的地方（用户明确裁决过不要兜底按钮），
> 真机验收时要专门测一次失败率。

## 四、键盘：5 列（左支付快捷 + 右 4×4 数字）

左列前 4 个支付方式（2 字缩写），右侧 4×4：`7 8 9 ⌫ / 4 5 6 C / 1 2 3 完成 / 0 00 .`。
按钮全部用 `Button('文案')` 形式（ArkTS 禁止 `Button('x') { ... }` 混用）。
