# 2026-10-24 设备实测发现：多参数 @Builder 不刷新（数值冻结在首帧）

## 症状（模拟器实测，不是猜的）

- 概况页：大金额 `¥2,012.80` 正常，但 **笔数 `0 笔`、日均 `¥0.00`、本月要还 `¥0.00`**
- 报表页：**总支出 `¥0.00`、笔数 `0 笔`、日均空白**，而分类占比 71% / 11% 却正常
- 记账抽屉（同类代码）：分类名/支付方式名在选择后不更新

## 排查过程（值得记住的方法）

1. `uitest dumpLayout` 拿到界面文本 → 确认「部分数字对、部分为 0」
2. 先排除服务端：直接 curl 月报 → `totalCents=201280, count=21` 正常
3. 加临时 `hilog` 打印 `body.report` 的 month/total/count/分类数
   → `month=2026-10 total=201280 count=21 cats=5`，**数据进到组件里是对的**
4. 于是问题只能在渲染层：对的那几个是**内联 Text**，错的那几个都走
   多参数 `@Builder`（`metric(label, value)` / `fact(label, value)` / `fieldRow(label, value, onTap)`）

## 根因

**ArkUI 的多参数 `@Builder` 只在首帧求值一次，之后状态变化不会重绘。**
要让它跟着刷新，必须用**单参数对象 + `$$` 引用传递**：

```ts
// ❌ 首帧后冻结
@Builder metric(label: string, value: string) { ... }

// ✅ 随状态刷新
@Builder metric($$: MetricCell) { Text($$.label); Text($$.value) }
this.metric({ label: '笔数', value: `${this.count} 笔` })
```

修复范围：`DashboardScreen`（metric / tierButton）、`ReportScreen`（fact / tierButton /
dimButton）、`ExpenseEditor`（fieldRow）。

## 修复后实测（同一模拟器、同一账号）

| 界面 | 修复前 | 修复后 |
|---|---|---|
| 概况·笔数 | 0 笔 | **21 笔** |
| 概况·日均 | ¥0.00 | **¥83.87** |
| 概况·本月要还 | ¥0.00 | **¥1,613.00** |
| 报表·总支出 | ¥0.00 | **¥2,012.80** |
| 报表·笔数 | 0 笔 | **21 笔** |
| 报表·日均 | 空白 | **¥83.87** |

与服务端 `count=21 / totalCents=201280` 完全一致，也与流水页「21 笔 · ¥2,012.80」对得上。

## 教训

这类 bug **编译期完全不报错、类型也全对**，靠代码审查很难发现；
device 上跑一次、对一次数字就暴露了。以后凡是「列表/数字走 @Builder 参数」的地方，
一律用单参数对象写法。
