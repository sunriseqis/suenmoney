点一下 = 选中，再点一下（或按「进入」）= 走。 你的原话：「点击日历的年份或月份可以查看该月的相关信息，如展示当年月的概况， 花费多少，分布等等，下方加入进入按钮或者再次点击进入下一层级，年进入月， 月进入正常流水页。」

所以格子上有两个动作，靠点几次分开：

  • 第一次点 → 选中该格，下方那张卡切到这个期间（花多少 / 几笔 / 分布）。 不换页、不滚动、不出现返回栈。

为什么以「均值」为轴，而不是在最大 / 最小之间等分： 你说的是「平均数上下＝普通」—— 这句话要求「普通」这一档跨在均值两侧。 若按最大最小等分，「平均的那个月」会被归进「稍多」或「最少」，与你的原话对不上。 四档的语义就落成：均值附近是普通，一倍半往上是最多，不到均值一半是最少。

为什么「0」要单独一档：没花钱和花得少不是一件事。 把 0 涂成「最浅」，读起来是「那个月花得很少」；实际是「那个月一分没花」。 颜色越淡承担的信息越弱，而 0 是一个很强的信息（断供、换卡、没记账）， 所以它用描边（＝空），而不是最浅的填充（＝少）。

深浅只用在日历上，不许扩散。 页面上现在有两套颜色语义，必须分清：提醒用色相（黄 / 红）说「要不要动手」， 日历用明度（蓝的深浅）说「花了多少」。 把日历的深蓝挪去别处用（比如给「本月支出」的大数字铺底）， 就会把「花得多」误读成「要注意」—— 那正是第六次修正刚拆开的东西。

日历只做骨架，不在格子里塞统计。 格子里只给「一个月 / 一年的量」，一眼看出哪几格深； 统计一律挂在下方那张卡里。往格子里塞环图、排名、涨跌，会做出一张 「什么都想说的日历」—— 而日历的价值恰恰是一眼看出哪几格深。

「下方那张卡」就是你说的「统计卡片」。 未选中时它显示本档（年 / 全部）的统计；一旦选中某格，整组切到那一格。 所以「点一下看该月信息」和「日历下方挂统计卡」是同一件事的两种说法 —— 日历在这儿的作用就是一个期间选择器，它驱动下面同一组卡。

下钻改的是「期间」，不是「页面」： 从年档点进 9 月，是 scope=year & month=9 → scope=month， 组件树与滚动位置都不变。这条必须写死 —— 做成「跳转到另一个页面」就会多一层返回栈， 把 ⑧ 五 刚定干净的「二级页只有一个出口」破坏掉。

窄屏的年档形态是个真约束：一个月的月历是 7 列 × 5~6 行，每格约 44px，放得下； 但12 张迷你月历在 390 宽上放不下（每格只剩约 30px）。所以窄屏退化成 3×4 的月格（只写「9月 / ¥13,860 / 38 笔」），桌面才铺成 6×2 或 4×3。 和热力图从 12 格改 6×2 是同一个手法：装不下就换写法，不硬塞。 年历的价值在「哪几个月有东西」，不在看清每一天 —— 看每一天本来就有两个去处（报表折线、月档流水）。

年度账单页（原 B 级第 2 条）是什么 —— 你问「是指年度报告还是什么」： 是年度报告。参考项目里那种「回顾叙事 + 成就徽章」 （年度总览 / 支出分析 / 月度趋势 / 特别时刻 / 成就），数据大头 yearlyReport 已经有了。
它和上面这个日历不重合：日历是「查」（我想看某个月）， 年度报告是「读」（一年过去了，看看发生了什么）。这一轮不做。

分享（原 B 级第 3 条）：完全不做，已从清单里删掉。 能力上不难，但它会引出一串东西：图片模板、脱敏规则、生成时机、分享渠道 —— 与「重设四页版式」是两条线。

PC 端的大空白 —— 都是「为了对齐把卡片撑高」撑出来的

用来验收的不是眼睛，是一个数字：卡片里最后一行内容，离卡片底边有多远。 四页 × 三个档位全量了一遍，量出三处。

位置卡内底部空白为什么会这样
设置 · 危险区 89px 它和「备份与恢复」并排在 grid--2 里，内容只有「标题 + 一行说明 + 两个按钮」，被拉到 222px 高
报表 · 按记录人 73px 年档 53px 和「本期洞察」并排，洞察有 3 条规则句，比它高一大截
报表 · 涨跌榜 52px 和「还款节奏」并排，还款节奏多一个「下月要还」的块

根因是一个 CSS 默认值：grid 的 align-items 默认是 stretch， 同一行的卡片一律拉到行高。撑高不会消灭空白，只是把空白从「卡片外」搬到「卡片内」 —— 而卡片自己凹进去一块，比旁边空着更像坏了。

两条修法，按这个顺序用：
① 结构性的 —— .grid { align-items: start }：卡片一律按内容高，不为对齐而撑；
② 配对性的 —— 高度差太大的两张，本来就不该并排：危险区因此改成通栏一条放最底。
