> **轮次性质**：第二轮复审（对第一轮 `coverage-spec-vs-docs.md` 的复查）。只比对，不改被核文件。
> **被核对象**：`docs/design/hw-ui-spec.md`（302 行 → 用户称 283 行；实际 `wc -l` = 302，下称"规范"，行号 `spec:NN`）。
> **基准**：`docs/design/audit/docs-ui-rules.md`（1350 行，146 R + 36 F + 必备元素 + 页面集合，行号 `docs:NN`）。
> **辅助**：`docs/design/audit/web-ui-inventory.md`（规范以"细节查 Web 审计"委派，仅作数值补齐，不计入覆盖）、`docs/feature-inventory.md`（FI# 编号核对）。

## 判定口径

| 判定 | 定义 |
|---|---|
| **覆盖** | 规范里有对应 R 编号**或** D 编号，且给了可执行要求（结构 / 数值 / 明确禁止）。§0 的 **D1–D22 视为有效覆盖**（用户已裁决）。规范把某条约束成文到"验收时能判对错"即算覆盖，数值细节可委派 `web-ui-inventory.md`。 |
| **弱覆盖** | 触及了该主题但缺可执行要求：只有 R 编号、只有半条、或只有零星相关文字而无法据此验收。 |
| **未覆盖** | 完全没有对应成文要求。 |

> **总计（146 条）**：**覆盖 100 / 弱覆盖 11 / 未覆盖 35**。
> 不达标 **46 条**（弱 11 + 未 35）。较第一轮（覆盖 31 / 弱 25 / 未 90）大幅改善：§0 D1–D22 与 §4 各屏条款已把主要结构冲突全部收口。
> **剩余缺口集中在四处**：① 流水日历块（R58/R59/R60/R30/R31）② 报表块集合（R84/R85/R86）③ 设置·账目与无障碍（R25/R33/R34/R88/R89）④ 排版宽度纪律与离线写队列（R45/R46/R47/R142）。
