# 用户裁决的偏差（不按 Web 实现，且不算缺陷）

> 这些是**用户当面拍板**的地方，与 Web 移动端现状**故意不同**。
> 对账（`2026-10-27-web-vs-app.md`）时，凡命中本表的差异一律记为「按裁决」，**不得当缺陷上报**。
> 新增条目必须写出裁决时间与用户原话要点。

| 编号 | 项目 | Web 现状 | 本端做法 | 裁决 |
|---|---|---|---|---|
| U01 | 顶部品牌条（logo + `SuenMoney`） | 移动端**显示**（`views.css:114` `.sidebar{padding:8px 14px 6px}`，仅 `.nav` 隐藏） | **整条不渲染** | 2026-10-26「上面的 logo 和标题区域…是完全不要的」 |
| U02 | 顶部标题栏（页面标题 + 子标题 + 主题切换 + `+记一笔`） | 移动端**显示**（`App.vue:210` `.topbar`，`views.css:1118`；`topbar--bare` 只影响返回键） | **整条不渲染**，主题切换移到「设置→设备」，记账走下拉手势 | 同上 |
| U03 | 二级页返回按钮 | `.topbar-back`（`‹`） | **不渲染**，改用系统返回手势（`onBackPress`）：流水→桌面、年度报告→报表、其余二级页→流水 | 2026-10-26「返回键应该由系统返回手势收起」 |

| U05 | 底部手势避让区留白 | 浏览器里不存在这个概念（有 `padding-bottom:64`，`views.css:1121`） | **沉浸式铺到物理底边**，`padding-bottom` 64→12，底部不再为手势条留白 | 2026-10-26「底不贴边，手势避让区过大…本应用没底部 tab」 |

| U07b | 键盘确认键文案 | `完成`（`key--ok`，`@click="save"`，`ExpenseSheet.vue:562`） | `保存`（行为与 Web 一致：都是保存） | 2026-10-26「OK按钮改为保存」 |
| U08 | 记账抽屉的系统关闭按钮 | 需查实 | `showClose: false`（系统 X 会压住内容右上角、和「退款冲销」一起盖住金额） | 2026-10-26「X 和冲销的提示文本全部盖住了金额」 |
| U09 | 设置页 tab 数与内容 | 四个（账目 / 计划与还款 / 外观 / 家庭） | **三个**（账目 / 计划与还款 / **设备**）；设备 = 主题 / 服务器 / 修改密码 / 检查更新 | 2026-10-25 裁决「web 的数据+家庭合并为设备，文件流与成员不渲染」 |

| U12 | 图标实现 | Lucide SVG 组件 | **鸿蒙内置 `sys.symbol`**（`SymbolGlyph`）+ 支付品牌随包 SVG 染色 | 2026-10-26「视觉上所有图标全部是错误切模糊混乱的…直接替换为鸿蒙内置图标」 |
| U13 | 二级分类颜色 | 继承一级（`PCatIcon` 的 `colorName` = 父分类名） | 同（已修） | 2026-10-26「二级分类图标颜色并没有跟随一级分类」 |

## 反例：曾经做过但不成立、已回滚的偏差

| 项目 | 曾经的错误做法 | 结论 |
|---|---|---|
| 换服务器后清 token 跳登录页 | 认为是「换后端要重登」 | **错**。suenmusic 明确：多条路径指向同一套后端（同 DB / 同 JWT），换路径不需要重新登录。已回滚 |
| 键盘 `layoutWeight(1)` 撑满抽屉 | 为了消掉底部空白 | **错**，键盘被拉得过大。已改为固定 210vp + 抽屉 `SheetType.FIT_CONTENT` |
