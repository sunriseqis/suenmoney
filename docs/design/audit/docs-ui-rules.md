## A. 硬性规则（每条都必须能在界面上验证）

### A.1 外壳、断点与平台差异（R01–R12）

#### R01 唯一断点是 1024px，900–1000px 的平板仍走移动布局
- **规则原文摘要**：「≥1024px 换成顶部导航 + 双栏……但断点不选 768px —— 900–1000px 的平板仍是触摸窄屏设备」。
- **来源**：`docs/decisions.md:392`（§七 界面）；`docs/design/flat-design.md:214`（§九）；`docs/design/ui-rework-3.md` §6.6 四（"断点沿用 1024px，与 `App.vue` 的 `lg:` 一致"）。
- **界面判据**：把窗口/设备宽度调到 1000px，若出现桌面顶栏或桌面表格即违反；若 1024px 仍未切桌面形态也违反。
- **适用屏**：全局

#### R02 移动端无底栏、无顶栏（不含页面标题 / 记一笔按钮 / 主题切换）
- **规则原文摘要**：「移动端 无底栏无顶栏；三个入口在流水页控制行的右端」「顶部：**没有**页面标题、**没有**「记一笔」按钮、**没有**主题切换」。
- **来源**：`docs/plan.md:356`（平台差异表）；`docs/plan/2026-10-22-鸿蒙端开发任务书.md:56`（§二·补 对齐基准 #1）；`docs/design/suenmoney-v3-design-system.md` §四「移动端外壳」。
- **界面判据**：手机宽度下屏幕最底部或最顶部出现常驻导航/标题条/主题切换图标即违反；主题只能在设置里切。
- **适用屏**：全局（移动端）

#### R03 移动端只有"流水"这一页是页；概况 / 报表 / 设置是二级页
- **规则原文摘要**：「单页应用：移动端只保留流水页。概况 / 报表 / 设置收纳为控制行右端的三个入口」「移动端只有流水页是「页」；概况 / 报表 / 设置是从控制行进去的二级页」。
- **来源**：`docs/plan.md:328`（第四轮 §五 第 10 条）；`docs/design/ui-rework-3.md` §6.6 一。
- **界面判据**：移动端出现第四/第五个平级页入口（如底栏 4 格、汉堡菜单列出 4 页）即违反；概况/报表/设置必须以"进入→关闭"的方式到达。
- **适用屏**：全局（移动端）

#### R04 移动端落地页是流水页；根路径重定向到流水
- **规则原文摘要**：「`/` 重定向到 `/ledger`」「小屏访问根路径自动重定向 `/ledger`」。
- **来源**：`docs/design/ui-rework-3.md` §十一 M1、§6.6 四；`docs/plan.md:440`（第八步已落地）。
- **界面判据**：手机冷启动后第一屏是流水列表（顶卡 + 控制行 + 列表），不是概况。
- **适用屏**：全局（移动端）

#### R05 同一份内容两端只换外壳，不做两套
- **规则原文摘要**：「块是一样的块，平台只决定「从哪进来」……**同一份内容不做两套，只换外壳**」；「概况 hero 的提醒条：桌面显示 / 移动端不显示」。
- **来源**：`docs/design/ui-rework-3.md` §六引言、§6.6 四；`docs/decisions.md:452-463`（抽屉"不拆成两个组件"）。
- **界面判据**：同一功能在两端出现两套不同字段集、不同校验或不同文案即违反；差异只允许在"入口/容器/是否渲染"。
- **适用屏**：全局

#### R06 桌面端：顶栏导航（概况·流水·报表·设置·记一笔），落地页是概况
- **规则原文摘要**：「导航｜顶栏：概况·流水·报表·设置·记一笔」「落地页｜**概况**（`/`）」。
- **来源**：`docs/plan.md:356-357`；`docs/design/suenmoney-v3-design-system.md` §四「顶栏（仅桌面）」（高 56、logo 34 + 字标 16、中月份切换、右侧导航四项 + 记一笔按钮）。
- **界面判据**：桌面端缺任一导航项、或"记一笔"不在顶栏右侧、或落地页不是概况即违反。
- **适用屏**：全局（桌面端）

#### R07 移动端顶卡与提醒的落点由"落地页"决定：提醒在流水页顶卡右半格，概况 hero 底部不放提醒条
- **规则原文摘要**：「行动层 → 跟着落地页走（桌面：概况 hero 底部一条 chip；移动端：流水页顶卡右半格）」「移动端概况页的 hero 底部**不放提醒条**」。
- **来源**：`docs/plan.md:325`（§五 第 7 条）、`docs/plan.md:358`；`docs/design/ui-rework-3.md` §6.5 三、§6.6 四。
- **界面判据**：移动端概况页出现提醒条，或流水页顶卡没有提醒格，即违反。
- **适用屏**：流水 / 概况

#### R08 安全区：底部留白来自安全区，不来自底栏高度
- **规则原文摘要**：`--bottom-bar-h` 归零后「留白的来源必须换成 `--safe-bottom`，否则最后一行会贴着屏幕底边」；P0-7「数字键盘底部增加 `--safe-bottom` 内边距，避开全面屏手势条」。
- **来源**：`docs/design/ui-rework-3.md` §6.6 七；`docs/plan.md:508`（P0-7）。
- **界面判据**：全面屏设备上最后一行内容/键盘��键被系统手势条压住，或页面底部凭空多出 60px 空白，均违反。
- **适用屏**：全局

#### R09 桌面与移动端的内容块完全一致（顶卡是外壳，不是新内容）
- **规则原文摘要**：「页面内容的块｜完全一致｜完全一致（顶卡是**外壳**，不是新内容）」。
- **来源**：`docs/design/ui-rework-3.md` §6.6 四（平台差异表末行）。
- **界面判据**：某个数据块只在手机或只在桌面存在，且不属于 §D 的"桌面专属/移动端专属"清单，即违反。
- **适用屏**：全局

#### R10 移动端原生实现必须与"移动 Web（≤860px）"逐项对齐
- **规则原文摘要**：「两端原生客户端都是手机应用，所以视觉与交互的**唯一对照物是 Web 的移动形态**（浏览器窗口 ≤ 860px 时看到的那个版本）。桌面 Web 是管理后台形态，**不照抄**」「一句话判据：**手机上看 Web 是什么样，原生端就该是什么样。**」
- **来源**：`docs/plan/2026-10-22-鸿蒙端开发任务书.md:47-81`（§二·补）。
- **界面判据**：任何界面差异无法指回本文件某条规则、且与移动 Web 截图不同，即违反；验收时桌面 Web 截图不算证据。
- **适用屏**：全局

#### R11 6 屏 + 3 层 + 5 弹层之外不许自造信息架构
- **规则原文摘要**：「**不许自造信息架构**：页面集合就是 §五 的 6 屏 + 3 层 + 5 弹层。要加要减先问我」。
- **来源**：`docs/plan/2026-10-22-鸿蒙端开发任务书.md:155`（§四 禁止事项 1）；页面集合见 `docs/plan/2026-10-21-客户端全原生化方案.md:116-132`（详见 §D）。
- **界面判据**：出现清单外的顶栏/侧栏/独立页/新弹层即违反。
- **适用屏**：全局

#### R12 后置项不阻塞主体，但不得当作"没有"
- **规则原文摘要**：「**后置（不阻塞 S1/S2）**：`AnnualSummaryView`（年度报告）、`BillImportModal`（账单导入）、`LedgerImportModal`、`ServerSettingsPanel`（多地址编辑可先做成单地址）」；任务书同列后置项：「年度报告、账单导入（微信/支付宝 CSV）、流水 CSV 导入、多服务端地址编辑面板（可先做单地址）」。
- **来源**：`docs/plan/2026-10-21-客户端全原生化方案.md:131-132`；`docs/plan/2026-10-22-鸿蒙端开发任务书.md:74-77`。
- **界面判据**：后置项在第一版缺失**不判违反**；但清单把某项列为"必须"而实现缺失则违反。
- **适用屏**：全局

### A.2 移动端信息架构与导航（R13–R24）

#### R13 三个入口（概况 / 报表 / 设置）与控制行的期间选择器同一行，靠右
- **规则原文摘要**：「期间靠左 + 三个入口靠右，占同一行（一行里两种语义用**位置**分开，不用行分开）；搜索独占下一行」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 13 条、§6.6 二·补；`docs/plan.md:331`。
- **界面判据**：三个入口单独占一整行（行内右侧大片空白）、或与搜索框混在同一行，即违反。
- **适用屏**：流水（移动端）

#### R14 三个入口的视觉语言必须与导航项不同：一行次要链接、右对齐、不定宽、无选中态
- **规则原文摘要**：「**把三个入口做成等宽 + 图标 + 选中态的一行，就是把底栏原样搬到了顶上**……入口行必须是**一行次要链接**，**右对齐**、不定宽……**没有选中态**」「纯文字（或小图标 + 文字）」。
- **来源**：`docs/design/ui-rework-3.md` §6.6 二（对照表）、§五 第 10 条说明段。
- **界面判据**：三个入口等宽平分、带图标上下排、或当前页有高亮选中态，即违反。
- **适用屏**：流水（移动端）

#### R15 三个入口只在流水页顶部，随内容滚走（不吸顶），二级页里一个字都不重复
- **规则原文摘要**：「**只在流水页顶部**，在控制行右端」「**不吸顶、随内容滚走**」「二级页里还有没有｜**没有**，一个字都不重复」。
- **来源**：`docs/design/ui-rework-3.md` §6.6 二·补二（含"①空间上只在顶部、②层级上只在流水页"两层意思）；`docs/plan.md:568`（追加定的同一条）。
- **界面判据**：滚动后入口行仍贴顶，或在概况/报表/设置页里又出现"还有 概况 · 报表 · 设置"，即违反。
- **适用屏**：流水 / 概况 / 报表 / 设置

#### R16 搜索框独占一行并撑满，筛选按钮与它同行
- **规则原文摘要**：「搜索行：搜索框**独占并撑满** ＋ 筛选」「它是这一条里唯一需要撑开的控件」。
- **来源**：`docs/design/ui-rework-3.md` §6.6 二·补（行数账表第 2 行）；`docs/plan.md:331`。
- **界面判据**：搜索框与期间选择器/入口挤在同一行，或搜索框不撑满可用宽度，即违反。
- **适用屏**：流水（移动端）

#### R17 二级页关闭收进标题行行尾，形如 `设置 ×`，不单独占一行
- **规则原文摘要**：「**收进标题行行尾**（`设置 ×`），**不单独占一行**；只窄屏渲染；触达 40×40；**不吸顶**」「字号 19px、默认 `--fg-muted`」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 15 条、§6.6 六；`docs/plan.md:334`。
- **界面判据**：出现独占一行的返回条（`‹ 流水`）、或关闭按钮放在标题左边、或桌面端也渲染关闭键，即违反。
- **适用屏**：概况 / 报表 / 设置（移动端）

#### R18 用 `×`（关闭）而不是 `‹`（返回）
- **规则原文摘要**：「`‹` 是「返回上一页」，`×` 是「关闭这个页面」—— 我们的场景是后者」。
- **来源**：`docs/design/ui-rework-3.md` §6.6 六、§五 第 15 条说明。
- **界面判据**：二级页标题行出现左尖括号返回箭头即违反。
- **适用屏**：概况 / 报表 / 设置（移动端）

#### R19 标题只在页头出现一次，页面内容里不许重复标题
- **规则原文摘要**：「标题只在页头出现一次｜页面内容里不再重复一遍「设置」二字」。
- **来源**：`docs/design/ui-rework-3.md` §6.6 六（三件事表 #3）；`docs/plan/2026-10-22-web端从零重构方案.md:126`（Web 端标题返回按钮"只在移动端显示"）。
- **界面判据**：页头写"设置"、下方第一张卡标题又写"设置"，即违反。
- **适用屏**：全局

#### R20 提醒格 0 条时：桌面显示「没有待处理」，移动端整格消失
- **规则原文摘要**：「**桌面 0 条时显示 `没有待处理`**（灰），不是把整条藏掉……**但移动端不这样**：顶卡的处理提醒是一整格，0 条时**整格消失**，把宽度换给本月支出」。
- **来源**：`docs/design/ui-rework-3.md` §6.5 六、§6.6 三；`docs/plan.md:329`（第 11 条：不留半格、也不放「没有待处理」占位）。
- **界面判据**：移动端顶卡在无待办时留半格或显示"没有待处理"占位，即违反；桌面端 0 条时整条消失也违反。
- **适用屏**：流水（移动端）/ 概况（桌面端）

#### R21 移动端顶卡两态由数据决定：有未处理→两列，无→本月支出独占整列
- **规则原文摘要**：「有未处理 → 两列，无未处理 → 本月支出独占整列」「**顶卡的形态是数据的结果，不是用户的选择**」；「必须是同一个组件带一个布尔，不能写成两个分支」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 11 条、§6.6 三；`docs/plan.md:329`。
- **界面判据**：无待办时本月支出仍只占半宽（另半空白），或两态由设置开关控制，即违反。
- **适用屏**：流水（移动端）

#### R22 顶卡提醒默认收起；展开是向下的（把列表顶下去），不是浮层；展开态不记忆
- **规则原文摘要**：「处理提醒**默认收起**，点击**向下展开**明细（把列表顶下去，不是浮层）」「默认收起要写在 HTML 属性上，不要在 JS 里初始化」；M5「回到默认收起」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 11 条、§6.6 三、§十一 M5；`docs/plan.md:329`。
- **界面判据**：首次进入即展开、或用弹窗/浮层显示提醒明细，即违反。
- **适用屏**：流水（移动端）

#### R23 只有"逾期"时整张顶卡吸顶；吸顶与颜色解耦
- **规则原文摘要**：「逾期时**整张顶卡吸顶**」「吸顶说的是**位置**，颜色标记说的是**要不要动手**，两者都由「有没有逾期」推出，但互不解释」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 11 条、§6.6 三；`docs/plan.md:329`、`docs/plan.md:440`。
- **界面判据**：非逾期状态下顶卡吸顶（不自然后滚走），或逾期时顶卡不吸顶，即违反。
- **适用屏**：流水（移动端）

#### R24 下拉手势是移动端唯一写入入口，不留兜底出口

- **适用屏**：流水（移动端）

### A.3 颜色、语义与无障碍（R25–R38）

#### R25 五色职责固定（只记支出的重定义，色值不动）
- **规则原文摘要**：「电紫 = 交互 / 选中；荧光薄荷 = **钱回来了**（退款、支出环比下降）；霓虹粉 = **要多花了 / 该处理了**（环比上涨、逾期）；荧光柠 = 进度（计划还款、累计条，**必须带数字**）；电光蓝 = 信息 / 焦点环」。
- **来源**：`docs/decisions.md:636-648`（§十）；`docs/design/suenmoney-v3-design-system.md` §三（映射表）。
- **界面判据**：用粉色表示"进度"、用柠檬色表示"支出"、或同一语义在不同页换色，即违反。
- **适用屏**：全局

#### R26 金额语义色：流水 `−` 与 hero 大数字用霓虹粉（B1 撤回后的现行口径）
- **规则原文摘要**：「B1｜支出金额不染色（`−` 用白、hero 白数字 + 彩色胶囊）｜**撤回**｜流水 `−` = 霓虹粉；hero 大数字 = 霓虹粉；环比胶囊同色 12% 底」。
- **来源**：`docs/decisions.md:653`（§十 已裁决表）；`docs/design/suenmoney-v3-design-system.md` §3.3。
- **界面判据**：流水金额前缀不是 `−` 粉色、或 hero 大数字为白色，即按现行口径算违反。
  （⚠ 与 `decisions.md:387`、`flat-design.md:315` 的"金额不加语义色"直接矛盾，见 §E C01。）
- **适用屏**：流水 / 概况 / 报表

#### R27 语义不只靠颜色：金额永远带 `+` / `−` 前缀与文字标签
- **规则原文摘要**：「你另外写死了两条：**「语义色全局一致，不得换色」**、**「语义不只靠颜色：支出/收入同时用 +/− 前缀与文字标签」**。这两条我照办」。
- **来源**：`docs/design/suenmoney-v3-design-system.md` §3.2（用户原话引用）、§六末。
- **界面判据**：仅用颜色区分退款与支出、金额无 `+`/`−` 前缀，即违反。
- **适用屏**：流水 / 抽屉 / 报表

#### R28 提醒 / 紧急度：容器一律中性色，颜色只落在展开箭头与文字上
- **规则原文摘要**：「**容器永远中性色**（提醒条 / 顶卡那一格**不染色**）；**颜色标记挂在展开箭头上**：自动入账＝中性、需手动确认＝黄、逾期＝红（红优先）；**展开后不再重复标记** —— 每条靠**文字本身的颜色**说紧急度」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 16 条、§6.5 六、§〇.7 第 2 条；`docs/plan.md:333`；`docs/decisions.md:397`（"卡片底色一律中性"）。
- **界面判据**：提醒条/待办卡有黄色或红色底色；或收起态看到多个颜色圆点；或展开后又给每条加圆点标记，均违反。
- **适用屏**：流水 / 概况 / 设置（计划）
  （⚠ 色条位置/粗细在文档间不一致，见 §E C08。）

#### R29 紧急度颜色不借用涨跌红绿，且不许铺成背景
- **规则原文摘要**：「**紧急度的颜色不借用涨跌红绿**……而且**只允许出现在「箭头」和「文字」两个地方，不允许铺成背景**」。
- **来源**：`docs/design/ui-rework-3.md` §6.5 六（末）、§〇.7。
- **界面判据**：出现整片红/琥珀背景卡；或在提醒里用"涨绿跌红"表达紧急度，即违反。
- **适用屏**：流水 / 概况 / 报表

#### R30 日历的深浅只用强调色的明度（四档 + 0 单独一档），不许引入第二色相
- **规则原文摘要**：「除提醒与标志需表示紧急程度外，其余颜色一律沿用强调色……仅需四种状态色，即最多-最深、稍多-略深、平均数上下-普通、最少-最浅」「四档说的是色阶只有四种，0 不占色阶 —— 它没有填充、只有描边」。
- **来源**：`docs/design/ui-rework-3.md` §6.3.3「花销深浅：四档，只用强调色」（含 rgba 值 .42/.24/.12/.05 与阈值 ≥1.5m / 1.15–1.5m / 0.85–1.15m / <0.85m）。
- **界面判据**：日历格出现蓝色以外的色相；或 0 值月份被涂成"最浅"而不是描边空态；或用最大/最小等分而不是均值轴，均违反。
- **适用屏**：流水（年 / 全部档日历）

#### R31 日历选中态用描边，不用填充色
- **规则原文摘要**：「选中态用 **描边 + 一层极淡的底**，**不用填充色** —— 一块填充色在本站的意思是「这块有事要动手」」。
- **来源**：`docs/design/ui-rework-3.md` §6.3.3「选中的样子：描边，不是填充」。
- **界面判据**：选中的日历格被实色填满，即违反。
- **适用屏**：流水（日历）

#### R32 两张颜色语义不许串：提醒用色相说"要不要动手"，日历用明度说"花了多少"
- **规则原文摘要**：「页面上现在有**两套颜色语义，不许串**」「把日历的深蓝挪去别处用（比如给「本月支出」的大数字铺底），就会把「花得多」误读成「要注意」」。
- **来源**：`docs/design/ui-rework-3.md` §6.3.3「颜色纪律（这条最重要）」。
- **界面判据**：日历的深浅蓝出现在提醒条、顶卡或进度条上，即违反。
- **适用屏**：全局

#### R33 任何"文字/底色"组合必须过 WCAG AA；强调色拆三角色不可混用
- **规则原文摘要**：「正文 ≥ 4.5:1，大字号（≥24px，或 ≥18.66px 且粗体）与纯图形 ≥ 3:1」；`--x`（纯图形）/ `--x-fill`（填充）/ `--x-text`（当文字用）三角色不可混用。
- **来源**：`docs/design/flat-design.md:69-85`（§三）；`docs/design/suenmoney-v3-design-system.md` §六（实测对比度全过）。
- **界面判据**：用图形色当正文颜色（如 `--danger` / `--accent` 本体写文字）即违反，需取 `--x-text`。
- **适用屏**：全局

#### R34 可交互控件边界用 `outline-strong`（≥3:1），`outline` 只做分隔线
- **规则原文摘要**：「`outline` 不能当交互边界……WCAG 1.4.11 要求可操作控件的视觉边界 ≥3:1……输入框 / 分段控件 / 开关的边界改用 `outline-strong: #706D96`」。
- **来源**：`docs/design/suenmoney-v3-design-system.md` §六 第 1 条。
- **界面判据**：输入框、分段控件、开关的边界在深色底上"看不见"（弱于分隔线级别的对比），即违反。
- **适用屏**：全局

#### R35 焦点态必须显式给（2px `#5DB8FF` + 2px offset）
- **规则原文摘要**：「焦点态：2px `#5DB8FF` + 2px offset，Tab 可验」；「扁平系统没有阴影，不能靠发光或扩散表达焦点」。
- **来源**：`docs/design/suenmoney-v3-design-system.md` §六末；`docs/design/flat-design.md:158`。
- **界面判据**：键盘/焦点导航时看不到焦点环，即违反。
- **适用屏**：全局

#### R36 计划 / 累计的进度色必须伴随数字
- **规则原文摘要**：「荧光柠｜进度：计划还款、累计条（**必须带数字**）」。
- **来源**：`docs/decisions.md:646`；`docs/design/suenmoney-v3-design-system.md` §六 第 2 条。
- **界面判据**：只有一根进度条而没有任何数值，即违反。
- **适用屏**：概况 / 设置（计划）

#### R37 涨跌榜：涨红 / 跌绿（按变化额），阈值 ±¥50 或 ±3% 取高
- **规则原文摘要**：「涨跌榜｜按**变化额**排序的分类（涨=红 / 跌=绿）」；内容 2「涨跌榜变化额阈值｜**采纳** —— ±¥50 或 ±3% 取较高者」。
- **来源**：`docs/design/ui-rework-3.md` §6.3.2 ⑤、§十一 内容 2。
- **界面判据**：涨跌榜按金额而非变化额排序；或小于阈值的分类仍上榜，即违反。
- **适用屏**：报表（月 / 年档）

#### R38 高对比装饰（扫描线/网格/点阵）不得降低正文对比度；应用内不得引入预览用装饰
- **规则原文摘要**：「背景装饰｜低透明度几何形状可接受（`bg-white/5`），但不得影响正文对比度」；「静态稿装饰（Marquee / confetti / squiggle / 点阵）｜⚠️ **仅预览页有，应用内未接入**」。
- **来源**：`docs/design/flat-design.md:160`；`docs/feature-inventory.md:207`（#124）；`docs/design/v5-design-system.md`「已知未做」。
- **界面判据**：应用界面出现 Marquee/confetti/squiggle 装饰，或扫描线导致文字对比下降，即违反。
- **适用屏**：全局

- **规则原文摘要**：同月：`还款日 9月27日`（低调，次级色）；跨月：**`这笔会记在 2026 年 10 月（还款日 10月28日）`**（醒目，强调色 + 加粗）。
- **来源**：`docs/decisions.md:423-439`（§七）；`docs/plan.md:42`；`docs/plan/2026-10-22-鸿蒙端开发任务书.md:113`（H3"这是本项目的头号误解来源"）；`docs/plan/2026-10-23-鸿蒙端最终验收清单.md:57`。

#### R109 月份预览必须走服务端 `POST /api/expenses/preview`，不在前端重算账单周期
- **规则原文摘要**：「**实现方式刻意选了一次服务端请求**（`POST /api/expenses/preview`），而不是在前端再实现一遍账单周期……两份实现迟早漂移，而漂移的方式是**安静地算错**」。

#### R110 记住上次用的分类与支付方式，且沿用前校验"它现在仍然可选"
- **规则原文摘要**：「存在 `localStorage`，且沿用前会校验「它现在仍然可选」（分类可能已被停用）」。

#### R111 备注输入时折叠数字键盘，并给上方辅助保存条
- **规则原文摘要**：「记账抽屉备注输入时平滑折叠数字键盘，提供上方辅助保存条，彻底消除双重键盘遮挡」。

#### R112 支付方式快捷键名自动精炼 2~3 字；2 项平分跨行；空位给「更多」
- **规则原文摘要**：「引入 `getShortPaymentName` 自然精炼 2~3 字品牌名（如「支付宝」「微信」「招商」「现金」），支持 2 项自适应平分跨行（`row-span-2`）与空位「更多」抽屉入口」。

#### R113 退款 / 分期开关的可用条件：退款仅非分期可用；分期仅信用卡且非退款

### A.10 提醒与计划卡（R116–R128）

#### R116 计划提醒三层归属：行动层跟落地页 / 信息层在概况网格 / 管理层在设置页计划 tab
- **规则原文摘要**：「**行动层**（到提醒日 / 逾期）→ 一条 chip，跟着落地页走；**信息层**（本月要还）→ 概况网格固定卡；**管理层**（新建 / 结束 / 期次 / 撤销）→ **设置页计划 tab**」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 7 条、§6.5 三；`docs/plan.md:325`。
- **界面判据**：在概况里出现"新建计划"按钮；或提醒里出现"改计划"入口，均违反。
- **适用屏**：流水 / 概况 / 设置

#### R117 提醒条/待办明细"一条一行"：金额 → 期次·名称 → 多急 → 状态 → 按钮
- **规则原文摘要**：目标格式 `¥2,800　3期 · 房贷　明天到期　自动入账　[确认]`；一行四类信息「**顺序就是优先级**：金额 → 哪一期 → 多急 → 要不要我动手，按钮接着放最右」，行内 `nowrap`。
- **来源**：`docs/design/ui-rework-3.md` §〇.7 第 4 条、§〇.8、§6.5 三·补。
- **界面判据**：一条提醒占两行；或按钮不在最右；或顺序颠倒，均违反。
- **适用屏**：流水 / 概况（桌面）

#### R118 「自动入账」状态词不能删，且必须可见
- **规则原文摘要**：「**`自动入账` 是这一行里唯一不能删的**：它回答的是「**我不点会怎样**」……删了它，用户就会在「我没确认过」和「怎么多了一笔」之间懵住」。
- **来源**：`docs/design/ui-rework-3.md` §〇.8「然后才是减字」、§6.5 五 第 2 条。
- **界面判据**：自动入账的期次在提醒行里没有任何"自动入账"字样，即违反。
- **适用屏**：流水（提醒）/ 设置（计划）

#### R119 动作判据落在"期"这一级：`willAutoPost = plan.auto_post && !todo.hold_auto_post`
- **规则原文摘要**：「**判据不是「计划有没有开自动入账」，而是「这一期现在还会不会自动入账」**：会 ＝ `plans.auto_post = 1 AND plan_todos.hold_auto_post = 0`」；「只看计划那一级就会判错……那笔账却永远不入，并且不报错」。
- **来源**：`docs/design/ui-rework-3.md` §五 第 14 条说明、§6.5 三·补；`docs/plan.md:332`。
- **界面判据**：同一计划里被撤销过的期次（hold_auto_post=1）显示"确认"而不是"入账/忽略"，即违反。
- **适用屏**：流水 / 概况 / 设置

#### R120 「确认」必须落库（`ack_at`），不能只做本地隐藏
- **规则原文摘要**：「不能放前端：换设备它又冒出来，用户会觉得「点了没用」」；「**撤销与恢复跳过时必须把它清回 `NULL`**」。
- **来源**：`docs/design/ui-rework-3.md` §〇.9 第 3 条、§6.5 三·补、§十一 M7；`docs/plan.md:332`。
- **界面判据**：点"确认"后换设备/重装又出现该提醒；或撤销后该期次再也不提醒，均违反。
- **适用屏**：流水 / 概况 / 设置

#### R121 计划卡必须有身份物：分类图标、期次、分期进度刻度、下次还款日
- **规则原文摘要**：「待办卡补上分类图标、期次、分期进度刻度、下次还款日。之前只有「名字 + 第几期 + 金额」，而同一屏的流水行有图标有日期有备注 —— 两种卡片像两个产品拼在一起」。
- **来源**：`docs/decisions.md:533-544`（§七）；`docs/plan.md:140`；`docs/feature-inventory.md:126`（#76）。
- **界面判据**：计划待办卡没有分类图标或没有进度刻度，即违反。
- **适用屏**：设置（计划）/ 流水（提醒）

#### R122 进度刻度最多画 12 段；超过 12 期压缩成 12 格并按比例取整
- **规则原文摘要**：「**进度刻度最多画 12 段**……30 年的房贷有 360 期，逐期画出来只会变成一片灰点。超过 12 期时压缩成 12 格、按比例取整填充，**精确数字始终由旁边那行文字给出**」。
- **来源**：`docs/decisions.md:537-539`；`docs/plan/2026-10-23-鸿蒙端最终验收清单.md:78`（"12 段进度刻度 + 「3/12 期」文字"）。
- **界面判据**：房贷（360 期）画出 360 个点；或刻度旁没有"3/12 期"文字，均违反。
- **适用屏**：设置（计划）/ 概况

#### R123 危险动作收进「更多」菜单（主按钮 + 更多），主次不同权
- **规则原文摘要**：「动作从「确认入账 + 跳过」两个同权重按钮改为「主按钮 + 更多菜单」：跳过是低频且**不可逆**的」。
- **来源**：`docs/decisions.md:540-542`；`docs/plan.md:140`。
- **界面判据**：确认与跳过并排成两个同尺寸按钮，即违反。
  （⚠ 与第十次修正的窄屏左右滑、§6.4 的"入账/忽略退到行尾更多菜单"三处口径不一，见 §E C11。）
- **适用屏**：设置（计划）/ 概况 / 流水

#### R124 计划卡不能 `overflow-hidden`（否则「更多」菜单被裁）
- **规则原文摘要**：「卡片**不能** `overflow-hidden`。左侧 4px 色条靠它裁圆角，但「更多」菜单会被一起裁掉 —— 圆角改由色条自己带（`rounded-l-md`）」。
- **来源**：`docs/decisions.md:543-544`。
- **界面判据**：展开「更多」菜单后被卡片边缘裁切/看不见，即违反。
- **适用屏**：设置（计划）/ 概况 / 流水

#### R125 撤销入口只在计划的期次列表里；交互两套（左滑 60% + 行内等价按钮）
- **规则原文摘要**：「**撤销入口只在计划的期次列表，交互做两套**……**期次行左滑露出动作**（触屏）+ **行内小按钮**（桌面端没有左滑手势）」。
- **来源**：`docs/decisions.md:196-207`（§二）；`docs/design/ui-rework-2.md` §五 决策 1/2；`docs/feature-inventory.md:123`（#75）。

- **适用屏**：设置（计划）

#### R126 撤销跨月必须警告（带金额与月份）
- **规则原文摘要**：「**跨月要警告**：支出的月份归属锚在还款日，撤销一笔属于上个月的支出会让那个月的合计当场变小。先告知金额与月份再动手」；示例文案「这笔已计入 2026 年 9 月，撤销后 9 月合计将减少 ¥X」。

- **适用屏**：设置（计划）

#### R127 跳过的期次可恢复，且恢复后不被当场自动入账
- **规则原文摘要**：「**跳过要可恢复**（`skipped → pending`）」；「恢复跳过 = `skipped → pending` + 置上「本期不再自动入账」」。

#### R128 「本月要还」是信息层固定卡：信用类 + 还款日 + 紧急度 + 已记 N 笔
- **规则原文摘要**：「② **本月要还**｜信用类 + 还款日 + 紧急度 + **已记 N 笔**｜当期事实」；「「本月要还」属于**信息**而不是**行动**，所以它留在网格里」。

### A.11 主题、字体、品牌与图标（R129–R140）

#### R129 两套主题 = 两种设计语言（深色 Cyberpunk / 浅色 Playful Geometric），不是同一配色的明暗变体
- **规则原文摘要**：「不写 `data-theme` = **深色 Cyberpunk**；`data-theme="light"` = **浅色 Playful Geometric**。不是同一配色的明度变体 —— 颜色、字体、圆角、阴影、动效曲线**全不同**」。
- **来源**：`docs/design/v5-design-system.md`（开头）、`docs/feature-inventory.md:199-200`（#116、#117）；`docs/plan/2026-10-22-鸿蒙端开发任务书.md:89`（H0-2 两套主题可热切换）、`docs/plan/2026-10-23-鸿蒙端最终验收清单.md:32-33`。

- **规则原文摘要**：「`<html data-theme>` 只在用户**显式选择**主题时写入；不写该属性 = 跟随系统」「显式选择 `light` 会锁定浅色，哪怕系统是深色」。
- **来源**：`docs/design/flat-design.md:57-65`（§二）；`docs/feature-inventory.md:136`（#81）。
- **界面判据**：系统切深色时界面不变（且用户未显式选过）；或选了浅色后系统深色仍覆盖，均违反。

#### R131 主题切换入口只在设置里
- **规则原文摘要**：「顶部：**没有**页面标题、**没有**「记一笔」按钮、**没有**主题切换｜一律不要；主题只在设置里切换」。
- **来源**：`docs/plan/2026-10-22-鸿蒙端开发任务书.md:56`（§二·补 #1）。
- **界面判据**：顶栏出现主题切换图标，即违反。

#### R132 圆角 / 阴影 / 动效曲线按 v3 令牌（卡 24 / 抽屉 24 / 输入 14 / 胶囊 999；`cubic-bezier(.2,0,0,1)`，200/350/400ms）
- **规则原文摘要**：「圆角｜卡 24 / 抽屉 24 / 输入 14 / 胶囊 999｜本应用没有 FAB」；「动效｜`cubic-bezier(.2,0,0,1)`，200 / 350 / 400ms｜全站唯一曲线」。

- **界面判据**：出现 6–8px 小圆角卡片、或多种缓动曲线并存，即违反。
  （⚠ 与 flat-design 的 8px 圆角/零阴影矛盾 —— 但该文档已标注作废，见 §E C13。）
- **适用屏**：全局

#### R133 减少动效：尊重 `prefers-reduced-motion`
- **规则原文摘要**：feature #123「减少动效（prefers-reduced-motion）｜✅」。
- **来源**：`docs/feature-inventory.md:206`（#123）。
- **界面判据**：系统开启"减少动态效果"后仍有位移动画/弹跳，即违反。

#### R134 分类图标存 kebab-case 名字；解析优先级 = 显式 icon > 按分类名反查 > 通用图标
- **规则原文摘要**：「存一个稳定的 kebab-case 字符串，解析表放在前端，遇到不认识的名字回落到通用图标 —— **永远不会崩，最差只是不够好看**」；「优先级是 **显式存储的 icon > 按分类名反查 > 通用图标**」。

- **界面判据**：遇到未知图标名时崩溃/显示空白破图；或忽略用户显式选的图标，均违反。

#### R135 支付方式图标按类型推断（cash→banknote、credit→credit-card），不提供自定义
- **规则原文摘要**：「**按类型推断就好**……不给 `payment_methods` 加字段：它只有两种类型，图标完全由类型决定」。
- **来源**：`docs/decisions.md:419-421`；`docs/design/flat-design.md:202-204`。
- **界面判据**：支付方式编辑面板出现图标选择器，即违反。

#### R136 二级分类用自己的图标、颜色跟一级走，统一由字典 `visualOf` 给出
- **规则原文摘要**：「二级分类用**自己的图标**，但**颜色跟一级走**……现在统一由 `dictionaries.visualOf(categoryId)` 给出」。
- **来源**：`docs/decisions.md:546-554`；`docs/plan.md:579`（第十四次）。
- **界面判据**：同一二级分类在流水、报表、设置里颜色不同，即违反。

- **适用屏**：全局
