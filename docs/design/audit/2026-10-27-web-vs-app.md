## 2. 先说结论：我上一轮的三条判断被推翻

| 我之前的说法 | 事实 | 后果 |
|---|---|---|
| 「Web 移动端有品牌条和标题栏（含主题切换、记一笔）」 | **只对了一半**：品牌条有（`.sidebar` sticky）；但 `.topbar-txt`（标题+副标题）与 `.topbar-actions`（主题切换+记一笔）在移动端被 **`!important` 隐藏**（`base.css:106-110`），流水页整条 `.topbar--bare` 不渲染 | 本端「无标题栏 / 无主题切换 / 无记一笔」**本来就和 Web 一致**，不是偏差。只有「品牌条」是真偏差（U01） |
| 「Web 移动端 `.side-foot` 是 display:none，所以我们也不该有页脚」 | **只对了一半**：`.side-foot` 确实隐藏，但 `App.vue:247-251` 在 **正文流末尾还有 `.build-stamp`**（`SuenMoney · 单账本家庭记账 · {stamp}`，随页滚动、**非 fixed**） | 我们**整条删掉是过头的**，应按 Web 加回正文流末尾 |
| 「登录页一个输入口 = 和 Web 对齐」 | ✓ 这条对（Web 也只有 1 个，且 `v-if="isNative"`），但 Web 还带 **测试 + 保存** 两个按钮，且**同一表单有 setup / login 两模式** | 本端只剩「测试」，且**完全没有 setup 模式** → 见 P0 |

## 4. 缺口 P1（建议本轮修）

### P1-1 ★ 没有「初始化账本」流程（其实是 P0，见下）
见 §4.0。

### ~~P1-1 `.build-stamp` 页脚~~ ——**用户裁决：不需要**

> **用户 2026-10-27 原话**：「页脚没有不影响。」
> 结论：**不加回**。以下保留 Web 侧事实备查。
- **Web**：`App.vue:247-251`，正文流末尾 `SuenMoney · 单账本家庭记账 · {buildStamp}`，离线时追加 ` · 离线模式`，有待同步时 ` · 待同步 N`；样式 `base.css:46-54`（10px mono、字距 .06em、opacity .55、居中、`padding-top:18px`）；**随页滚动，不是 fixed**。
- **本端**：完全没有（`MainPage.ets` build 里无对应节点；`stamp()` / `stampText()` 已被删）。
- **建议**：在内容列末尾（`Column({space:12})` 内、屏组件之后）加回，样式按 `base.css:46-54`，文案带离线/待同步后缀。这样既对齐 Web，也不会再占用固定底部空间。

### P1-2 ★ 记账抽屉形态与 Web 不一致
| 项 | Web | 本端 | 建议 |
|---|---|---|---|
| 高度 | `height:93dvh`（`app.css:566-578`） | `SheetSize.FIT_CONTENT`（`LedgerScreen.ets:1651`） | 保留 FIT_CONTENT（用户要求消底部空白，登记 U15）；但确认展开分类/支付面板时不抖动 |
| 圆角 | 移动 `radius:22px 22px 0 0`；cyber `radius:0`（`app.css:762-773`） | 系统 bindSheet 默认 | 用 `SheetOptions` 的 `borderRadius` 对齐 22 |
| 键盘左列宽 | 移动 **54px**（`views.css:899`） | **62px**（`ExpenseEditor.ets:572`） | 改 54，快捷条第 1 格同步 54 |
| 快捷条 | 不参与键盘栅格：跨满宽 + 横向滚动胶囊（最多 6），`≤620px` 高时隐藏（`ExpenseSheet.vue:509-521,723-727`） | 与键盘同列宽 5 格 + 图标 | 保留（用户要求，登记 U14），但列宽跟 54 |

### P1-3 登录页缺品牌块与模式切换
- **Web**：`BrandMark(56)` + `SuenMoney` + `FAMILY LEDGER · 单账本`；卡头 `初始化账本`／`登录` + cap `第一次使用`／`家庭共用`；两模式互切（`已有账号，去登录` / `首次部署？初始化账本`）；页脚 `{PLAYFUL|CYBERPUNK} · SuenMoney`；服务器区 **测试 + 保存** 两个按钮（`LoginView.vue:113-188`）。
- **本端**：只有 `SuenMoney` + `登录` + 两个输入 + 单个「测试」（`LoginPage.ets:129-230`）。
- **建议**：补 BrandMark(56)、cap 文案、页脚；服务器区补回「保存」（Web 有）；模式切换随 P1-1 一起做。

### P1-4 设置弹层 `showClose: true`，与记账抽屉不一致
- 本端 `SettingsScreen.ets:947-952` 是 `SheetSize.LARGE + showClose: true`；记账抽屉已改 `false`（因为系统 X 压住内容右上角，`LedgerScreen.ets:1650-1656`）。
- **风险**：设置弹层右上角同样会压住表单（分类/支付/计划表单的名称行）。
- **建议**：统一 `showClose: false`，关闭走遮罩/下拉/取消按钮。

### P1-5 概况与年度报告的大金额字号偏大
- **Web**：`.hero-amt` 移动端 **34px**（`views.css:775`）。
- **本端**：38（≤8 位）／30／24 自适应（`DashboardScreen.heroAmountSize()`、`AnnualScreen`）。
- **建议**：基数改 34，档位改 34/28/22；流水顶卡 `.mh-amt` 仍是 **38px**（`views.css:1031-1043`）→ 只有流水页用 38。

### P1-6 报表「支出构成」在移动端的布局
- **Web**：`.compose-view` 移动 `flex column; gap:12px`，环图 136px，图例为 4 列栅格 `9px/1fr/64px/32px` 且行间虚线（`views.css:1140-1157`）。
- **本端**：DonutChart ringSize136 ✓，但图例是「dot9 + 名11.5 + 金额11.5(宽64) + 百分比10(宽38)」的自定义行。
- **建议**：对齐 Web 的 4 列栅格与 64/32 定宽（本端 64/38 已接近，主要是 32↔38 与虚线）。

### P1-7 支付列与「更多」入口
- **Web**：支付列取前 4 个 + 固定 `更多`（`ExpenseSheet.vue:546-557`）；本端只在 `payments.length > 4` 时才有「更多」（`ExpenseEditor.ets:551` 附近）。
- **建议**：按 Web 常驻「更多」位（或用当前逻辑但保证 5 项时高度与 Web 一致）。

## 4.0 ~~P0（功能不可用）~~ 无「初始化账本」——**用户裁决：不属于本端范围**

> **用户 2026-10-27 原话**：「初始化本来就是 web 前端的事情。」
> 结论：鸿蒙端**不实现** setup / 初始化流程；空库初始化由 Web 前端完成。
> 本节保留事实记录（服务端接口位置），**不再作为缺口**。

| 事实 | 依据 |
|---|---|
| 服务端有 `GET /api/auth/status` 返回 `{ needsSetup }`、`POST /api/auth/setup` 创建第一个管理员 | `server/src/http/auth.ts:40-50` |
| Web 登录页据此切 setup 模式（`初始化账本` / `创建并进入`），并隐藏手动模式切换 | `LoginView.vue:29,93-101,122,159-164` |
| 本端 `AuthStore` 只有 `login/logout/isAuthenticated`，`Api` 无 `authStatus`/`setup` | `common/auth/AuthStore.ets`、`common/net/Api.ets`（grep 无结果） |

**后果**（记录用）：全新部署（空库）时鸿蒙端无法创建第一个账号 —— 按裁决这是**预期行为**，由 Web 端初始化。
**建议**：`Api.authStatus()` + `Api.setup(username, displayName, password)`；登录页在 `needsSetup === true` 时切成「初始化账本」模式（字段多一个「显示名」），成功后直接进主界面。**这是本轮唯一的功能性阻断。**
