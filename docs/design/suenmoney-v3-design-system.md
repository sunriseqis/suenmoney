## 一、方向

**夜间便利店的霓虹糖果货架**：深靛蓝的中性面 + 五组荧光马卡龙强调色，艳丽但克制，**数字是绝对主角**。

| 要 | 不要 |
|---|---|
| Material 3 语法（tonal surface / state layer / emphasized easing） | 可爱、卡通、贴纸感 |
| 荧光色只在暗面发色，面积小、纯度高 | 手绘描边、超粗圆体 |
| 大号 tabular 数字承重 | 粉嫩低饱和、大面积粉色底 |
| 深色为主推（夜里记账是主场） | 玻璃拟态、滥用模糊 |
| 语义色严格分工（见 §三） | 用颜色当装饰 |

### 与旧系统的关系（一句说清，别让两套规则并存）

`flat-design.md` 的六条铁律里有三条被 v3 明确作废：**零阴影**（M3 用 elevation level1/2）、
**圆角统一 6–8px**（v3 是 24px 卡片）、**分区用色块不用分割线**（v3 有 `outline` 分隔线）。
理由：那三条是「扁平」这一风格的定义，而 v3 换的就是风格。
保留的只有一条精神：**强调色克制**（正文一律 `on-surface`，颜色只上数字、图标、进度、FAB）。

## 三、语义映射（定稿的核心判断）

原规格里「薄荷=收入、霓虹粉=支出、荧光柠=预算、电紫=primary、电光蓝=信息」是按
**收支记账 App** 设计的。但这份账本是**只记支出**（`decisions.md` §一：收入项、预算与超支提醒都明确不做；
`expenses` 没有 `direction` 字段，没有 `budgets` 表）。

如果照规格硬套，会出现两个后果：**① 整页都是警报色**（支出＝粉，而每一笔都是支出）；
**② UI 里出现算不出数的卡片**（预算、结余）。

所以五色的**角色必须重定义**（因为其中三个角色在数据里不存在），色值一个不动；**具体映射方式是我的建议**：

| 色 | 原规格 | 定稿 | 用在哪 |
|---|---|---|---|
| **电紫** `#B388FF` | primary | **交互与选中** | 选中 tab、chip 底、图标、链接式按钮 |
| **荧光薄荷** `#4DFFD2` | 收入 | **「钱回来了」** | 退款/冲销金额（`+`）、支出环比**下降**胶囊、结清/达标状态 |
| **霓虹粉** `#FF7AB8` | 支出 / 警示 | **「要多花了 / 该处理了」** | 支出环比**上涨**、逾期、超支、FAB |
| **荧光柠** `#E5FF41` | 预算 | **进度** | 计划还款进度条、累计条填充（**必须伴随数字**） |
| **电光蓝** `#5DB8FF` | 信息 / 链接 | 不变 | 信息、焦点环（2px）、提示 |

### 3.1 唯一的事实约束（可查，不可协商）

```
docs/decisions.md §一   「收入项、预算与超支提醒」明确不做
server/src/db/migrations/001_init.sql   expenses 无 direction 字段；无 budgets 表
```

因此**结余、收入/支出双数值、预算卡这三样算不出来**。这是数据现实，不是设计偏好。
（要不要为了这三张卡去改数据模型，是另一个议题 —— 那属于 `decisions.md` 里的 C 级改动，不在本轮。）

### 3.2 你的规格是基线（照抄，不改）

| 色 | 规格原文职责 |
|---|---|
| 电紫 `#B388FF` | primary（交互） |
| 荧光薄荷 `#4DFFD2` | 收入；流水中 `+` 前缀 |
| 霓虹粉 `#FF7AB8` | 支出；流水中 `−` 前缀；警示；FAB |
| 荧光柠 `#E5FF41` | 预算高亮 / 进度填充；**超支变霓虹粉** |
| 电光蓝 `#5DB8FF` | 信息 / 链接 / 焦点环 |

你另外写死了两条：**「语义色全局一致，不得换色」**、**「语义不只靠颜色：支出/收入同时用 +/− 前缀与文字标签」**。
这两条我照办。

### 3.3 我的建议（**标注为建议，未采纳前一律按 §3.2 基线执行**）

因为我擅自把这几条写成了「铁律」，特此单列清楚。每条都写了理由**和代价**：

| # | 建议 | 理由 | 代价 / 与你的规格冲突处 |
|---|---|---|---|
| B1 | 支出金额不染色（`−` 用 `on-surface` 白；hero 大数字永远白，只有下面那枚环比胶囊变色） | 只记支出的账本里每笔都是支出，若支出＝粉，则整页常驻警报色；提醒要从背景里跳出来才有效 | **直接覆盖**你写的「支出前缀 − 霓虹粉」；如果粉是品牌识别的主角，这条就不该听 |
| B2 | 逾期/超支的进度条用 45° 条纹，不新增色相 | 粉同时表「上涨」和「逾期」时强度打架；加第六个色会让五色体系崩解 | **覆盖**你写的「超支变霓虹粉」；你也从未定义「逾期」的视觉，条纹是我替它想的出路 |
| B3 | 桌面端导航放顶栏（移动端保留底栏） | 1200px 下底栏与 FAB 争右下角，也不合桌面操作习惯 | 覆盖你第 8 条骨架里的「底部导航」 |

> **未采纳时怎么办**：把 `tokens.json` 与样张里的对应规则回退到 §3.2 ——
> 流水 `−` 恢复霓虹粉、超支恢复霓虹粉、桌面保留底栏。不需要改色值，只是改用法。

对应地，原规格的三张卡换成这三张（数据都算得出来）：

| 原规格 | 定稿 | 数据来源 |
|---|---|---|
| 总资产卡（本期结余） | **本月支出卡**：大数字 + 环比胶囊 + 日均/笔数 | `reports/monthly` |
| 本月收支卡（收入/支出 + 对比条） | **本月构成卡**：分类堆叠条 + Top3 明细 | `reports/monthly` 的 `categories` |
| 预算卡（荧光柠进度 + 超支） | **计划与还款卡**：房贷第 3/12 期柠色进度 + 逾期一期粉条纹 | `plans` + `plan_todos`（已有 `ack_at` / `status`） |

> **不做**：收入、结余、预算。`decisions.md` §一 已定，UI 里也不许出现 ——
> 「界面上有但我们算不出」比「界面上没有」更难解释。

## 五、LOGO 定稿

**判据**：你原版那个 S 是真的字形 —— 4×5 格子矩阵，**11 亮 + 9 空**，
五段五个色（上横薄荷 / 左竖紫 / 中横蓝 / 右竖柠 / 下横粉）。**字形逐格照抄，一格不改。**

只改四件技术问题：

| # | 原版 | 定稿 | 理由 |
|---|---|---|---|
| 1 | 240×320 竖画布 | **1024×1024 方形** | 图标全要 1:1；竖版只能硬裁，一裁就切掉上横或下横 |
| 2 | 三层描边 | **零描边**，靠 `container` 色阶 | 32px 时三层线糊成灰框；也与「靠 surface 分层」一致 |
| 3 | 每格两次绘制 + 逐个 GaussianBlur | **分组模糊一次 + 实色一次** | 32 rect → 2 次 `<use>`；消除模糊层渗进实色格的灰边 |
| 4 | 圆角 36/28/12/10 四套 | **两档**：卡 224 / 格 52（≈格宽 30%，与原版 10/36 一致） | 四套在小尺寸互相抵消成方角 |

### 四个形态与阈值

| 形态 | 文件 | 何时用 |
|---|---|---|
| 母版（11 亮 + 9 空） | `brand/mark.svg` | **≥32px**：iOS/鸿蒙/fnOS 图标、启动图、桌面、顶栏 logo |
| 简化（只留 11 个笔画） | `brand/mark-small.svg` | **<32px**：favicon 16/24、通知栏、标签页。空格在 16px 与底色差几乎没有，只会让笔画变细 |
| 单色（实心 S 剪影） | `brand/mark-mono.svg` | 安卓 monochrome、鸿蒙分层前景、系统强调色染色态 |
| header 变体 | `brand/mark-header.svg` | **≥48px**：header 条 + 薄荷状态点（它让图形像「一台收银机」）。**<48px 不出现** —— 会退化成一条噪点 |

### 配色与纪律

```
底板 #141222 · 卡片 #1E1D2E · 空格 #282740 · 字形 = 五色原值
安全区 0.78（网格 796/1024，四周留 114）
```

- **不许换色相**：五个格子颜色就是 UI 的五色，换一个等于品牌与界面脱钩。
- **不许加字**：字标单独用字体排，不进图标。
- **不许加圆角描边、内阴影、外发光以外的效果**：发光只有一层分组模糊（opacity .40）。

## 六、无障碍与三处规格修订

实测（WCAG 公式，非估算）：`on-surface` **16.24:1**、`on-surface-variant` **9.25:1**、
薄荷 **14.53**、柠 **16.42**、蓝 **8.57**、粉 **7.66**、紫 **6.92**；
`on-` 深字压各自强调色：薄荷 10.69 / 柠 11.68 / 蓝 6.09 / 紫 5.79 / 粉 5.44 —— 全部达标。

三处必须修的地方（已写进令牌与组件规范）：

1. **`outline` 不能当交互边界。** `#3A3852` 只有 1.64:1。分隔线可用（装饰），
   输入框/分段控件/开关的边界要求 ≥3:1 → 新增 `outline-strong: #706D96`（container 上 3.4:1）。
2. **薄荷与荧光柠在红绿色盲下几乎同色**，而它们职责不同（「钱回来了」vs「进度」）。
   → 硬规则：**柠只出现在进度条填充与预算/进度百分比上，且永远带数字**；
   薄荷只出现在 `+` 金额与下降胶囊上。
3. **霓虹粉同时表「上涨」与「逾期」** 强度会打架 → 逾期/超支**不新增颜色**，
   改用 **45° 条纹填充**（`repeating-linear-gradient(115deg, #FF7AB8 0 8px, #FF7AB8@55% 8px 14px)`）。
   色彩语义不变，「这一条在报警」一眼可分。

焦点态：2px `#5DB8FF` + 2px offset，Tab 可验。语义不只靠颜色：金额永远带 `+`/`−` 与文字标签。
