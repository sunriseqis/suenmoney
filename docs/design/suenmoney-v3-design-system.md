## 一、方向

**夜间便利店的霓虹糖果货架**：深靛蓝的中性面 + 五组荧光马卡龙强调色，艳丽但克制，**数字是绝对主角**。

| 要 | 不要 |
|---|---|
| Material 3 语法（tonal surface / state layer / emphasized easing） | 可爱、卡通、贴纸感 |
| 荧光色只在暗面发色，面积小、纯度高 | 手绘描边、超粗圆体 |
| 大号 tabular 数字承重 | 粉嫩低饱和、大面积粉色底 |
| 深色为主推（夜里记账是主场） | 玻璃拟态、滥用模糊 |
| 语义色严格分工（见 §三） | 用颜色当装饰 |

### 与旧系统的关系（一句说清，别让两套规则并存）

`flat-design.md` 的六条铁律里有三条被 v3 明确作废：**零阴影**（M3 用 elevation level1/2）、
**圆角统一 6–8px**（v3 是 24px 卡片）、**分区用色块不用分割线**（v3 有 `outline` 分隔线）。
理由：那三条是「扁平」这一风格的定义，而 v3 换的就是风格。
保留的只有一条精神：**强调色克制**（正文一律 `on-surface`，颜色只上数字、图标、进度条）。

## 三、语义映射（定稿的核心判断）

原规格里「薄荷=收入、霓虹粉=支出、荧光柠=预算、电紫=primary、电光蓝=信息」是按
**收支记账 App** 设计的。但这份账本是**只记支出**（`decisions.md` §一：收入项、预算与超支提醒都明确不做；
`expenses` 没有 `direction` 字段，没有 `budgets` 表）。

如果照规格硬套，会出现两个后果：**① 整页都是警报色**（支出＝粉，而每一笔都是支出）；
**② UI 里出现算不出数的卡片**（预算、结余）。

所以五色的**角色必须重定义**（因为其中三个角色在数据里不存在），色值一个不动；**具体映射方式是我的建议**：

| 色 | 原规格 | 定稿 | 用在哪 |
|---|---|---|---|
| **电紫** `#B388FF` | primary | **交互与选中** | 选中 tab、chip 底、图标、链接式按钮 |
| **荧光薄荷** `#4DFFD2` | 收入 | **「钱回来了」** | 退款/冲销金额（`+`）、支出环比**下降**胶囊、结清/达标状态 |
| **霓虹粉** `#FF7AB8` | 支出 / 警示 | **支出金额**与警示 | 流水 `−`、hero 数字、环比上涨胶囊、超支 |
| **荧光柠** `#E5FF41` | 预算 | **进度** | 计划还款进度条、累计条填充（**必须伴随数字**） |
| **电光蓝** `#5DB8FF` | 信息 / 链接 | 不变 | 信息、焦点环（2px）、提示 |

### 3.1 唯一的事实约束（可查，不可协商）

```
docs/decisions.md §一   「收入项、预算与超支提醒」明确不做
server/src/db/migrations/001_init.sql   expenses 无 direction 字段；无 budgets 表
```

因此**结余、收入/支出双数值、预算卡这三样算不出来**。这是数据现实，不是设计偏好。
（要不要为了这三张卡去改数据模型，是另一个议题 —— 那属于 `decisions.md` 里的 C 级改动，不在本轮。）

### 3.2 你的规格是基线（照抄，不改）

| 色 | 规格原文职责 |
|---|---|
| 电紫 `#B388FF` | primary（交互） |
| 荧光薄荷 `#4DFFD2` | 收入；流水中 `+` 前缀 |
| 霓虹粉 `#FF7AB8` | 支出；流水中 `−` 前缀；警示 |
| 荧光柠 `#E5FF41` | 预算高亮 / 进度填充；**超支变霓虹粉** |
| 电光蓝 `#5DB8FF` | 信息 / 链接 / 焦点环 |

你另外写死了两条：**「语义色全局一致，不得换色」**、**「语义不只靠颜色：支出/收入同时用 +/− 前缀与文字标签」**。
这两条我照办。

### 3.3 裁决记录：三条建议全部撤回（2026-10-21）

我提过三条改法，用户全部否决。**当前实现按 §3.2 规格执行**，这三条只留作记录。

| # | 我曾建议 | 裁决 | 现在的做法 |
|---|---|---|---|
| B1 | 支出金额不染色（`−` 用白；hero 白数字 + 彩色胶囊） | **撤回** | 流水 `−` = 霓虹粉；hero 大数字 = 霓虹粉；环比胶囊用同色 12% 底 |
| B2 | 逾期 / 超支用 45° 条纹，不新增色相 | **撤回** | 超支 = 霓虹粉实心；逾期无独立定义，暂按超支同一处理，靠文字「逾期 2 天」区分 |
| B3 | 桌面导航移顶栏、移动端保留底栏 | **撤回，且我判断错了产品** | 本应用**没有导航栏**：桌面顶栏导航；移动端无顶栏无底栏 |

**B3 的真实 IA（有出处的原文，设计前必须先读）**

```
docs/plan.md:356   「桌面 顶栏：概况·流水·报表·设置·记一笔 ｜ 移动端 无底栏无顶栏；
                    三个入口在流水页控制行的右端」
docs/plan.md:363   「记一笔：桌面 顶栏按钮 ｜ 移动端 下拉手势（唯一入口，不留兜底）」
docs/plan.md:440   第四轮已落地：彻底移除移动底栏（--bottom-bar-h: 0）、顶卡（本月支出与
                    处理提醒同行，逾期吸顶）、控制行收纳三个入口、下拉 >60px 唤出记账
```

> **教训（写给下一个设计与实现的人）**：
> ① 用户规格里与产品既有 IA 冲突的部分（底部导航、FAB），**先查 `docs/plan.md` 与 `ui-rework-3.md` 再动手**；
> ② 我自己的取舍一律写成「建议 + 代价」，不进「规格」「约束」「铁律」；
> ③ 「设计智能体不知道应用详情」这件事的解法不是猜，是**读仓库里的 IA 文档**。

对应地，原规格的三张卡换成这三张（数据都算得出来）：

| 原规格 | 定稿 | 数据来源 |
|---|---|---|
| 总资产卡（本期结余） | **本月支出卡**：大数字 + 环比胶囊 + 日均/笔数 | `reports/monthly` |
| 本月收支卡（收入/支出 + 对比条） | **本月构成卡**：分类堆叠条 + Top3 明细 | `reports/monthly` 的 `categories` |
| 预算卡（荧光柠进度 + 超支） | **计划与还款卡**：房贷第 3/12 期柠色进度 + 逾期一期粉条纹 | `plans` + `plan_todos`（已有 `ack_at` / `status`） |

> **不做**：收入、结余、预算。`decisions.md` §一 已定，UI 里也不许出现 ——
> 「界面上有但我们算不出」比「界面上没有」更难解释。

## 五、LOGO 定稿

**这个标记是一台计算器**：机身 + 显示屏（带指示灯）+ 4×5 键盘，**亮起的键位拼出 S**。

> 我曾两次把它改坏，记在这里免得第三次：
> ① 把键位矩阵换成「4×3 + 金额柱」——另画了一个图形；
> ② 把**显示屏删掉**（还臆造了「header 变体只在 ≥48px 出现」）——它是语义主体，
> 删掉之后只剩一片发光点阵，不再像任何东西。
> 现在：结构照抄，键位一格不动。

### 结构（1024 坐标）

| 部件 | 几何 | 作用 |
|---|---|---|
| 机身 | `48,48 → 928×928 rx 220`，`#1E1D2E` | 「这是一个物件」 |
| 显示屏 | `212,112 → 600×176 rx 48`，`#141222`（比机身暗＝凹陷） | **计算器的脸**；不描边，靠明度差 |
| 指示灯 | 圆点 `r20 @ (758,152)`，薄荷 | 「正在显示数字」而不是一块空灰条 |
| 键盘 | 4×5，格 `135×108 rx 34`，间距 `20/20`，起点 `(212,328)` | 与屏**同宽 600**（原版 168/168）——键盘比屏宽就不像计算器了 |
| 亮键 | 11 亮 / 9 暗 | S：上横薄荷 → 左竖紫 → 中横蓝 → 右竖柠 → 下横粉 |

只改四件技术问题：方形画布 / 去描边 / 分组发光 / 圆角收敛。**键位与色序不许动。**

### 三形态（没有第四种）

| 形态 | 文件 | 何时用 |
|---|---|---|
| 完整 | `brand/mark.svg` | **≥32px**：iOS / 鸿蒙 / fnOS 图标、启动图、桌面、顶栏 |
| 小尺寸 | `brand/mark-small.svg` | **<32px**：favicon 16/24、通知栏。键位改圆点，**屏与灯保留** |
| 单色 | `brand/mark-mono.svg` | 安卓 monochrome、鸿蒙分层前景、系统染色。屏 85% 白 + 亮键白 + 暗键 30% 白 |

|---|---|
| Web | `favicon.png`(32)、`icon.png`(180)、`icon-512.png`、`logo.png`、**真矢量 `logo.svg`**（2.6KB，替掉原来那个 280KB 位图壳） |

## 六、无障碍与三处规格修订

实测（WCAG 公式，非估算）：`on-surface` **16.24:1**、`on-surface-variant` **9.25:1**、
薄荷 **14.53**、柠 **16.42**、蓝 **8.57**、粉 **7.66**、紫 **6.92**；
`on-` 深字压各自强调色：薄荷 10.69 / 柠 11.68 / 蓝 6.09 / 紫 5.79 / 粉 5.44 —— 全部达标。

**唯一必须改的一处（无障碍硬线，不是偏好）**：

1. **`outline` 不能当交互边界。** `#3A3852` 在 `#1E1D2E` 上只有 **1.47:1**（在 `#141222` 上 1.64:1）。
   WCAG 1.4.11 要求可操作控件的视觉边界 ≥3:1。分隔线（装饰）可以用它，
   输入框 / 分段控件 / 开关的边界改用 `outline-strong: #706D96`（container 上 **3.4:1**）。
   这是唯一一条我坚持的改动 —— 它是标准，不是审美。

**一条建议（未采纳也成立）**：

2. 薄荷 `#4DFFD2` 与荧光柠 `#E5FF41` 在红绿色盲模拟下都落成浅黄绿。二者职责不同（`+` 退款 vs 进度），
   建议柠**只用于进度填充且旁边永远有数字**，靠形状与文字而不是颜色区分 —— 这也符合你第 7 条。

**已撤回**：逾期 / 超支的 45° 条纹（见 §3.3 B2）。

焦点态：2px `#5DB8FF` + 2px offset，Tab 可验。语义不只靠颜色：金额永远带 `+`/`−` 与文字标签。
