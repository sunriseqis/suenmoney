## 一、先说三个会决定做法的事实

### 1. 现在的「logo」不是矢量，是套了 SVG 壳的位图

```
docs/design/SuenMoney-sky-blue.svg   280KB   ← 里面是一张 base64 PNG
docs/design/SuenMoney.svg            280KB   ← 同上
web/public/logo.svg                  280KB   ← 同上
```

四个「SVG」全是 `<image xlink:href="data:image/png;base64,...">`。后果很具体：

- **放大就糊**：fnOS 桌面图标 256、iOS 1024、发布会大图都是从位图放大；
- **无法做单色/分层**：安卓 adaptive 前景、鸿蒙分层图标、安卓 monochrome 都需要**纯路径**；
- **换色要重导一次位图**，而不是改一个变量。

所以「翻新 LOGO」的第一件事不是画图，是**建一个真正的矢量母版**（一份路径，1024 坐标，
零位图、零渐变），再让脚本从它生成全端。

### 2. 现在的视觉已经有一套**成文且不错**的骨架，缺的不是规则，是「脸」

`tokens.css` 里那六条铁律（零阴影、6–8px 圆角、分区用色块、200ms snappy、强调色克制、
WCAG AA 分三角色）是**有纪律的**，而且颜色三角色（`--x` / `--x-fill` / `--x-text`）
和 8 个图表色相是**用脚本算过对比度的**（`scripts/palette-calc.mjs`）。这些不用推翻。

这四轮返工的教训我读出来是同一句：

> **前三轮一直在修「做得对不对」，第四轮在修「信息够不够」。**
> 但一个记账 App 让人「一眼觉得好」，靠的从来不是版式，是**数字排得好不好看**。

所以这次翻新的重心建议放在**排版系统**（尤其金额）与**一个贯穿全局的记号**上，
而不是第五轮版式重构。

### 3. 上层品牌已有家族记号，但两个产品会长得像

同门 `SuenMusic` 定稿的是「实心折角 S + 段 0 染琥珀 + 深哑光底 `#17181B` + 蚀刻边 `#2A2C30`」。
如果 SuenMoney 直接沿用同一个 S 只换颜色，两个 App 在任务栏里会互换身份（见对照页第四节）。

## 二、五条建议（按杠杆从高到低）

### 建议 1｜把设计令牌做成「三端唯一真相源」（最高优先）

计划三要**手写两套原生 UI**（SwiftUI + ArkUI）。如果令牌还是只活在 `tokens.css` 里，
两端各抄一遍数字，半年后必然三份不一致，而且不一致的表现是「iPad 上金额比手机大 2px」这种没人会报的 bug。

做法：

```
docs/design/tokens.json          ← 唯一真相源（颜色 / 字号 / 间距 / 圆角 / 动效 / 图标色）
        ├─ scripts/gen-tokens.mjs → web/src/styles/tokens.generated.css
        ├─                        → ios/SuenMoney/UI/DesignTokens.swift
        └─                        → hw/entry/src/main/ets/common/Tokens.ets
```

CI 里加一条：生成产物与仓库里的文件 **diff 必须为空**（改了 json 忘了重跑 → 红）。

这条现在做只要半天，等 S0 之后做要改三个平台。

### 建议 2｜做一套**金额排版系统**（这是记账产品的脸）

现在的金额是「字号特别大」。建议升级成有规矩的三级：

| 层级 | 用法 | 规格 |
|---|---|---|
| **符号级** | `¥` | 比数字小 2 档、垂直上移 0.18em、颜色取 `--fg-muted` |
| **整数级** | 1,234 | 主字号；**必须** `font-variant-numeric: tabular-nums` |
| **角分级** | `.00` | 小 1 档、`--fg-muted`；为零时**可隐藏**（设置项，默认显示） |

配套三条硬规则（都可机械验收）：

1. **同一页里所有金额右对齐到同一列**（列表、报表、卡片摘要）—— 这是「像账本」的物理来源。
2. **金额永不换行、永不缩写**（`1.2万` 只允许出现在热力格与图表轴，且必须带 `≈`）。
3. **正负色只用于语义**：支出用正文色，退款/冲销用 `--danger-text`，从不给「支出」染红。

顺带一个便宜但效果很大的改动：**列表行里的日期用 `29` 大 + `日` 小**（现在混在一个字符串里），
数字对齐后整列会自然形成一条竖直的「日」轴。

### 建议 3｜一个贯穿全局的**签名记号：折角**

Logo 只是记号出现的一个地方。真正让产品「有脸」的是：**同一个 45° 折角在界面里反复出现**，
但每次只出现在一个位置：

| 位置 | 折角怎么用 |
|---|---|
| Logo / 图标 | 底板四角切两刀（见候选 A/B） |
| 卡片 | **右上角切 8px 一刀**，只在「一级卡片」上用（二级卡不切，层级就此区分） |
| 记账键盘的「入账」键 | 右下角切一刀，替代强调色底 |
| 图表的「Top 1」弧段 | 末端斜切，不用圆头 |
| 空态插画 | 就画那一个折角形状，不画插画 |

**唯一性纪律**：一屏里折角出现 **≤2 次**。多了就变成廉价装饰，少了不成记号。

### 建议 4｜把记账键盘当「产品主界面」重做（每天用 20 次的地方）

现在键盘是「4 列数字 + 左列支付方式」。建议三处升级，都是低风险纯前端：

1. **金额带（casing）**：键盘正上方一条 40px 的窄带，左「本月已支出 ¥3,089」，右「这笔后 ¥3,121」。
   —— 记账时人真正想知道的不是「我敲了几位」，是「我这个月到哪了」。
2. **一次操作可回退**：长按退格 = 清空；左滑金额带 = 撤销上一笔（8 秒窗口已有实现可复用）。
3. **常用分类不再靠猜**：键盘上方保留 2 个最高频分类为「一键入账」胶囊（现在要先开分类面板）。

> 这一条之所以排第 4：它是**唯一一个「用户每天都会碰到、且改动不影响数据口径」**的地方。

### 建议 5｜统一「数据墨」：图表只用 4 档深浅 + 一套表格数字

现在图表有 8 个分类色相（没问题，分类要色相）。但**同一个量级的不同深浅**（热力格、
日历格、进度条）目前是各处自己算透明度。建议统一成 4 档固定值：

```
--ink-1 ~ --ink-4   （强调色的 22% / 45% / 70% / 100%，都已经在 tokens 里算过对比度）
```

凡是「用深浅表达大小」的地方（月度热力、日历格、进度条、堆叠条）**只准用这四档**，
不许再出现 `opacity-30`、`bg-primary/40` 这种临时值。这一条能让整站的「数据质感」突然统一。

## 三、Logo：三个方向与推荐

对照页：[`candidates/index.html`](candidates/index.html)（含 16/24/32/48/64/96 尺寸梯度、
iOS 圆角遮罩、favicon、单色态、与 SuenMusic 并排）。

| 方向 | 一句话 | 家族感 | 16px 可读 | 语义直给 | 结论 |
|---|---|---|---|---|---|
| **A 家族折角 S** | 与 SuenMusic 同一剪影，段 0 换成账目蓝 | ★★★ | ★☆ | ☆ | 若坚持「同一个 App 家族」可用，但两个图标易认错 |
| **B 账本折页** | 一页折起一角的账纸，折角 = 家族记号 | ★★☆ | ★★ | ★★★ | **推荐** |
| **C 切角 ¥** | 切角方框里的 ¥，竖笔染色 | ★ | ★★★ | ★★☆ | 语义最稳，但它不像「你家的产品」 |

**为什么推荐 B**：

1. **家族感靠形状不靠字母** —— A 复用同一个 S，代价是两个 App 互换身份；
   B 复用的是「45° 折角 + 蚀刻边 + 深哑光底」这套记号，既能认出是一家，又不会认错是哪个。
2. **它把产品的核心动作画了出来**：账本 + 一页被翻起（还没结清）。已有的「计划 / 待办 / 账期」
   全部能挂在这个隐喻上，而不需要一个抽象符号去硬解释。
3. **小尺寸成立**：折角在 16px 仍然是一个可辨识的缺口；S 的三条横带在 16px 会糊成一条白杠。

**配套规范（无论选哪个都要定）**：

```
底板        #17181B（深哑光，与 SuenMusic 同）
蚀刻边      #2A2C30，内缩 96/1024，只做线不做色块（这样单色态还读得出来）
字形        #E9E7E2
强调        #4C8DFF（账目蓝；替代 SuenMusic 的琥珀 #E8A33D）
安全区      0.82 —— 字形不越出中心 84% 的方框
最小尺寸    16px（favicon / 通知栏）；<20px 用「简化版字形」（删掉账线，只留折页轮廓）
```

**iOS 26 起要交三态**：浅色 / 深色 / **着色（tinted）**。也就是说图标要有
「浅底深字形、深底浅字形、单色被系统染色」三种可用形态 —— 这也是为什么底板不能依赖渐变。

## 四、资产管线：一个母版，脚本出全端

现在的 `scripts/generate_all_assets.py` 是从位图母版切图的（Pillow）。
建议改成：**母版 = 手写 SVG 路径（`brand/mark.svg` + `brand/mark-mono.svg`）→ 脚本渲染全端**。

| 目标 | 产物 | 说明 |
|---|---|---|
| Web | `favicon.ico`(16/32)、`favicon-192/512.png`、`apple-touch-icon.png`、`logo.svg`（**真矢量**替换现在那个 280KB 位图壳） | 顺带修掉 `logo.svg` 这个假矢量 |
| iOS | `AppIcon-1024.png` + iOS 26 的 dark / tinted 变体、启动图 | 1024 无 alpha、无圆角（系统自己遮） |
| 鸿蒙 | 分层图标（`foreground` / `background`）+ `layered_image.json` | 现在只有单张 `app_icon.png` |
| 安卓（冻结版） | adaptive icon 前景/背景 + monochrome | 只生成一次，不再维护 |
| fnOS 套件 | `ICON.PNG`(64) / `ICON_256.PNG`(256) / `app/ui/images/icon_{64,256}.png` | 计划二直接从这套取 |

技术上建议用 `sharp`（纯 npm，无系统依赖）替代 Pillow —— 参考实现那边因为本机没装 PIL，
图标这一步直接把打包流程打挂了。

## 五、明确**不**做的事（这是前四轮的教训）

| 不做 | 理由 |
|---|---|
| 不引入 UI 框架（Element/Naive/Radix…） | 现在这套是手写的、可控的；换框架等于把四轮打磨全部作废 |
| 不改信息架构 | 第四轮刚定案（概况看量 / 报表看结构 / 流水三档三形态），这轮只换皮 |
| 不加阴影、不加模糊、不加玻璃态 | 六条铁律第 1 条；而且原生端两端都要重写，越简单越省 |
| 不加 emoji、不加插画库 | 上一轮已全局禁用 emoji；插画只画「折角」一个形状 |
| 不做主题市场 | 只保留 浅 / 深 / 跟随系统 三档（已实现），不加配色皮肤 |
| 不做手势换皮 | 下拉记账、左右滑确认这些是功能，不是视觉；这轮不动 |

## 六、排期：品牌与令牌必须走在计划三前面

```
计划一（单端口合并）  ✅ 已完成
        │
        ├──► 品牌与令牌定案（本轮）  ← 2～3 天：选向 → 母版 → 生成脚本 → 三端令牌
        │             │
        │             ▼
        └──► 计划二（fnOS 套件） —— 直接用新图标母版出 64/256
                      │
                      ▼
              计划三（全原生化）S0 起 —— 两端都从 tokens.json 生成 UI 令牌
```

**为什么不能等**：计划三 S0 一开始就要写 `DesignTokens.swift` 与 `Tokens.ets`。
如果那时还没有单一真相源，两端就会各写一套数字，之后再改要同时动三个平台 —— 而这三处
不一致的表现是「看着差不多但就是不舒服」，最难发现也最难修。

**本轮的具体交付建议（2–3 天）**：

| # | 交付 | 验收 |
|---|---|---|
| 1 | 方向选定 + 精修字形（对齐安全区、光学重心、<20px 简化版） | 16px 眯眼可辨；单色态可辨 |
| 2 | `brand/mark.svg` + `mark-mono.svg` + 生成脚本 | `npm run icons` 一条命令出全端资产，零 Python 依赖 |
| 3 | `docs/design/tokens.json` + 生成脚本（css/swift/ets） | CI diff 为空；三端文件名固定 |
| 4 | 金额排版系统落进 `tokens.css` + 一个「金额组件」 | 列表/报表/卡片三处金额右对齐成一条线 |
| 5 | 折角记号规范（≤2 次/屏）落进 `flat-design.md` | 一级卡片右上切角；键盘入账键右下切角 |
| 6 | 一份「改前 / 改后」对照页（3 个关键屏） | 你打开就能说「这版对了」 |

## 七、可机械验收的五条（写进 CI 或脚本）

1. **16px 可辨**：favicon 缩到 16px 后，与上一版不相似（人工过一眼，不留证）。
2. **单色可辨**：`filter: grayscale(1)` 后折角/字形仍能区分 —— 对照页第四节已可看。
3. **AA 对比度**：任何新增的「字色 / 底色」组合用 `scripts/palette-calc.mjs` 跑一遍，正文 ≥4.5。
4. **令牌一致**：`gen-tokens` 产物 `git diff --exit-code`。
5. **金额对齐**：流水 / 报表 / 卡片的金额列 `getBoundingClientRect().right` 三处一致（±1px）。
