## 一、PC 端

### P1. 双栏布局是偷懒的做法，不是正确处理方式

**原话**：「双栏布局非常偷懒，这不是一个正确的处理方式。举例说明当首页计划为空的时候，
只有单边的流水记录。」

**核查结果 —— 确实如此，而且是结构性的**：

`DashboardView` 是固定的 `lg:grid lg:grid-cols-2`：

| 栏 | 内容 |
|---|---|
| 左 | 该处理了（`v-if="dueTodos.length > 0"`）、本月待还（`v-if="creditDue.length > 0"`） |
| 右 | 支出构成（`v-if="categories.length > 0"`）、最近流水 |

两个 `v-if` 都不成立时，左栏 `<div>` 仍然占据第 1 列，右栏照旧落在右半边 ——
**左边整片空白，内容孤零零贴在右侧**。而"没有待办"恰恰是最常见的正常状态。

同一个毛病出现在另外三页：

| 页面 | 左栏 | 右栏 | 空态后果 |
|---|---|---|---|
| 首页 | 该处理了 + 本月待还 | 支出构成 + 最近流水 | 无待办时左空右满 |
| 计划 | 该处理了 | 我的计划 | 无待办时左空右满 |
| 报表 | 分类构成 | 按支付方式 + 按记录人 | 按年时右栏少一节 |
| 设置 | 账号 + 成员 + 支付方式 | 分类 + 设备 | 无管理员时左栏很矮 |

**结论**：把"手机上本来就上下堆叠的两块"直接并排，只是把窄栏摊开，
没有做任何真正的桌面信息架构。这不是布局，是排版偷懒。

### P2. 记录详情页没有做适配

**核查结果 —— 属实**：

`web/src/components/ExpenseSheet.vue`

```
容器  fixed inset-0 z-[var(--z-sheet)]
面板  absolute inset-x-0 bottom-0 top-[6vh] rounded-t-md
```

**通栏、无 `max-width`**。1440px 的桌面上，它就是一个 1440×846 的贴底大抽屉 ——
和手机上是同一个东西被拉宽，输入框横跨整个屏幕宽度。

**待确认**：这里说的"记录详情页"是否就是点流水条目打开的这个抽屉？
（当前项目没有独立的记录详情页面，只有这一个抽屉兼做新增与编辑。）

## 二、双端问题（PC 与移动端都存在）

### D1. 页面构建过于简略

**原话**：「当前页面的构建过于简略。」

### D2. 支出构成可以重新设计

**原话**：「支出构成的统计可以重新设计。」

**核查结果**：目前是「分类名 + 笔数 + 百分比 + 金额 + 一条蓝色横条」的列表，
六项以上时一屏放不下，且所有分类用同一个蓝色 —— `categories.color` 和
`--chart-1..8` 都已存在但**没人用**（见 `docs/plan.md` 待决事项）。

### D3. 计划的呈现方式与流水极度割裂

**原话**：「计划的呈现方式与流水极度割裂。」

**核查结果**：计划的待办卡是「中性底 + 左侧 4px 色条 + 两行文字 + 两个按钮」，
而流水行是「日期 + 图标 + 两行文字 + 右对齐金额」，两者：

- 都没有图标（流水有分类图标，计划待办没有对应图标）
- 金额位置不同（待办在文字右侧，流水在最右）
- 交互不同（待办是卡内按钮，流水是整行可点）
- 卡片形状不同（待办是圆角色块，流水是无底色行）

同屏并排时确实是两套语言。

### D4. 流水的呈现方式可以更好看一点

**原话**：「流水的呈现方式也可以做的更好看一点。」

**核查结果**：每行是「日期 + 分类图标 + 分类名/备注 + 右对齐金额」，
部分行额外挂一个灰色「9月28日 还款」药丸。已知问题：

- 那个还款日药丸重复出现在大量行上，是噪音，且它承载的信息在列表语境里价值很低
- 桌面版收窄到 768px 只是绕开了"分类名与金额之间空 600px"，没有真正解决
- 行高不一致（有无药丸、有无备注）

### D5. 设置卡片需要重新规划

**原话**：「设置卡片需要重新规划，比如分类，现在极其冗长，为什么不能做一级目录 tab 页的
形式然后列表展开，去做一行一内容，完全不考虑用户需要翻多久到底。」

**核查结果 —— 属实，分类区确实极长**：

分类区当前把**所有一级分类与其所有二级分类一次性全部平铺**，
每个二级分类占一行（图标 + 名称 + 笔数 + 停用按钮）。
演示数据里 9 个一级 × 若干二级，实测在手机上需要滚过 40 屏左右才能到「登录设备」。

**用户提出的方向**（记录原话，不评价）：一级目录 tab 页 + 列表展开，一行一内容。

### D6. 计划应该放进设置入口

**原话**：「计划应该放进设置入口。」

**核查结果**：目前「计划」在桌面顶部导航里与「设置」平级；手机端首页右上角有入口，
底部栏没有。用户认为它属于设置。

## 三、移动端

### M1. 「记一笔」的位置与显示方式不优秀，与底部其他图标割裂

**原话**：「记一笔的位置和显示方式并不优秀，和其他底部图标完全割裂。」

**核查结果**：底部栏是三个 `RouterLink`（首页 / 流水 / 报表，图标 + 文字竖排）
后面跟一个 `<button>`（`+ 记一笔`，横向填充胶囊按钮）。
两者字号、图标尺寸、排列方向、激活态逻辑都不同 —— 它看起来像被塞进导航栏的
一个陌生控件，而不是第四个 tab。

**背景**：用户早期明确要求「不要 +，底部入口」，所以悬浮球方案已被否决，
但当前这个"填充按钮挤在 tab 之间"也不是答案。

## 五、开工前的待确认点 —— 已全部确认

这五个问题在出设计稿时一次性回答了，答案就是 `mockup.html` 里对应页面画的东西。
留在这里是为了对照「当时在犹豫什么」。

| # | 当时的疑问 | 结论 |
|---|---|---|
| 1 | P2 的「记录详情页」= 点流水条目打开的抽屉吗 | **是**。项目里只有这一个抽屉组件，兼做新增与编辑，没有独立详情页 |
| 2 | P1 的空栏：收成一栏，还是换一种桌面信息架构 | **收成一栏**：整页改为单列堆叠的区块流，宽度只在**区块内部**用（构成图例两栏、待办卡自动换行）。空态就是整块不出现，不会留洞 |
| 3 | D6「计划放进设置」：移动端也一起搬，还是只改桌面导航 | **一起搬**。`/plans` 路由删除，计划成为设置里的一个 tab；手机首页头部不再有「计划」入口，底栏格子也不用重新分配 |
| 4 | M1「记一笔」希望它长什么样 | **做成普通 tab**（Actual Budget 的做法）。加号图标本身已经说明它是主操作，不需要比别的 tab 更重的形态 |
| 5 | D2 支出构成：换图表形态，还是先解决配色未启用 | **两件一起做**。首页用堆叠条（回答「这个月怎么花的」），报表用环图 + 明细（回答「构成比例」）；配色接上 `--chart-1..8` |
