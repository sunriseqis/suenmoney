## 二、P0 清单（按影响排序）

### P0-1 CSV 导入既不写 changes、也不走事务
- **位置**：`server/src/db/repo/transfer.ts:921-1027`（`importExpensesCsv`）
- **现象**：直接 `INSERT INTO expenses`，**没有 `recordChange`**，也**没有 `inTransaction`**。
- **后果**：导入的流水在服务端"存在"，但其他设备 `/api/sync/pull` **永远同步不到** —— 症状是"手机看不到导入的账"，与已知同步丢失问题同源但更隐蔽。且整批非原子，中途失败留下半截数据。
- **修复**：每行 INSERT + `recordChange` 包进 `inTransaction`（可复用 `expenses.ts` 的 `insertBatchItem`）。

### P0-2 WebDAV 备份轮转正则匹配 `.sqlite`，实际文件是 `.mn` —— 备份无限堆积
- **位置**：`server/src/db/repo/webdav.ts:381`
- **现象**：上传文件名是 `suenmoney-backup-YYYY-MM-DD.mn`，但清理正则是 `/^suenmoney-(?:backup|snapshot)-[\w.-]+\.sqlite$/`。
- **后果**：`backupNames` 恒为空数组 → "只保留最近 3 份"**从未生效**，远端 `.mn` 备份无限堆积，最终占满用户网盘。
- **修复**：正则改 `\.mn$`（保留 `.sqlite` 分支清旧档）+ 补轮转测试（当前测试**零覆盖**）。

### P0-3 备份恢复的用户覆盖在事务之外
- **位置**：`server/src/db/repo/transfer.ts:799-802`（`restoreUsers`）
- **现象**：`restoreUsers` 在 `inTransaction` **之前**执行，且不走 `recordChange`。
- **后果**：若后续事务回滚，账号已被改/软删、账目却回滚到旧状态 —— 半截态。且 users 写入同步口径不一致。
- **修复**：`restoreUsers` 移入同一 `inTransaction`，补 `recordChange`。

### P0-4 iOS 增量拉取 `bucketOf` 漏用双键兼容
- **位置**：`ios/SuenMoney/Sync/SyncEngine.swift:521-541`
- **现象**：`category`/`payment_method` 分支只读 camelCase，没用 `pick()` 双键（`expense` 分支已正确）。
- **后果**：服务端一旦改字段名，本地会把 `sort_order=0`、`is_enabled` 丢失、`billing_day=0` **静默冲成默认值**。
- **修复**：`category`/`payment_method` 分支统一改用 `str2/int2/bool2`。

### P0-5 Web 离线"修改/删除"对仅存在于队列的记录产生孤儿操作
- **位置**：`web/src/stores/sync.ts:355-421` + `web/src/stores/idb.ts:366`
- **现象**：目标记录若只在 outbox 不在本地缓存，update/delete **本地不生效、服务端也静默丢弃**（服务端逐条 catch 忽略），队列被当成功清空。
- **后果**：操作静默丢失，用户以为改/删了某笔账。
- **修复**：① update/delete 前校验目标存在；② 服务端回传失败 id 列表；③ 三端统一 update 字段口径。

### P0-6 Web `pullChanges` 只应用 expense，字典/计划/用户变更不落地
- **位置**：`web/src/stores/sync.ts:733-777`
- **现象**：`user` 实体变更**完全无处理**，`ownerName` 硬写 `''`（流水"记录人"长期为空）；字典/计划靠 `dict.load(true)` 全量重拉，与 iOS/hw 的 payload upsert **口径分叉**。
- **后果**：三端报表口径不一致；断网时更严重。
- **修复**：Web 按 payload 落地字典/计划/待办/用户实体，与 iOS/hw 对齐。

### P0-7 CI Release body 读-改-写无原子性，并发发布吞掉别的平台 SECTION
- **位置**：`scripts/prepare-release-notes.mjs:176` + 各 workflow 的 `softprops/action-gh-release`
- **现象**：四个 workflow 并发/重跑时，后 PUT 者用只含自己那节的 body 覆盖先 PUT 者（已实测复现）。
- **后果**：别的平台在发行页**静默消失，流程全绿无报错**。
- **修复**：加 `concurrency` 串行化（`group: suenapp-release-${tag}`）或 CAS（`If-Match`）。

### P0-8 build-hw 的"清理冗余资产"步骤是四重失效死代码
- **位置**：`.github/workflows/build-hw.yml:200-256`
- **现象**：条件恒假（`refs/tags/v*` 在 workflow_dispatch 下永不成立）+ 查错仓库 + 错 token + 错 tag。
- **后果**：给人"有资产清理兜底"的假安全感，实际从不执行。
- **修复**：删掉或修好（条件改 `inputs.publish_release`、repo 硬编码 suenapp、tag 用 `suenmoney-v*`、token 用 `GH_RELEASE_TOKEN`）。

### P0-9 WebDAV 备份无限堆积（与 P0-2 同源，agent-8 独立确认）
- **位置**：`server/src/db/repo/webdav.ts:381`
- **现象**：同 P0-2，独立确认根因。
- **修复**：同 P0-2。

## 三、P1 清单（20 条）

### 服务端（agent-1）
1. `updateExpense`/`softDeleteExpense` 读后写非原子，delete 后 upsert 会**复活**已删记录
2. `pushChanges` 批量推送把逐条错误全部吞掉，幂等命中与真失败不可分辨
3. CSV 导入金额 `Math.round(Number()*100)` 可产生 0/超大值，绕过 `validateAmount` 上限
4. `inTransaction` 全局深度计数依赖单连接假设，脆弱
5. 待办删除语义混用（pending 物理删、confirmed 软删）

### 鉴权与安全（agent-2）
6. `transferExpenses` 成员可重分类**全家**支出（越权写，突破"写仅限创建者"）
7. `/api/update/check` 无鉴权签发下载令牌，抵消令牌防护意义
8. 登录限流按 `IP+用户名`，换用户名即绕过；`/api/auth/setup` 无限流

### 客户端同步（agent-7）
9. iOS/鸿蒙 `pendingCount` 排除死信 → 死信仍在表时快照"先清后灌"会**清掉未上云数据**
10. Web 死信阈值三处不一致（off-by-one）
11. 401 被计入 outbox 重试次数，长期未登录把好账推死信

### CI/CD（agent-6）
12. `fetchExistingReleaseBody` 拉取失败当"全新 Release"，其它三节被整体覆盖清空
13. `titleRegex` 合并吞掉历史段落之后的尾部正文
14. `build-hw`/`build-ios` tag 分支解析裸 `v*`，与 `suenmoney-v*` 契约不符（潜伏）

### 部署/契约（agent-8）
15. `docs/deploy.md` 第六节"VACUUM INTO 物理快照 + 冷恢复"整章描述的功能**已在代码中删除**
16. FAQ 缺 bind-mount 权限 → 登录 500 的最典型故障
17. `docs/api.md` 缺整个备份/导出/导入/WebDAV 契约面
18. `SUENMONEY_CORS_ORIGINS` 空值语义描述与实现相反
19. `deploy.md` 缺 6 个更新/运维环境变量；fnOS 产物名 `suenmoney-v*.fpk` 通配符匹配不到实际产物

### 前端 UI（agent-9 卡死后由主代理补完）

20. `web/src/stores/sync.ts:216` — 静默 `catch {}` 吞掉本地元信息读取失败（`last_sync_version`/`last_synced_at`），元信息损坏时用户无感知
21. `ios/SuenMoney/UI/Settings/SettingsScreen.swift:1443-1444` — 下载 URL 用字符串拼接（`+ r.downloadPath + "/" + fileName + "?token=" + downloadToken`），未做 URL 编码；若 `downloadPath` 含空格/特殊字符会构造出无效 URL
22. 版本号显示 `__BUILD_STAMP__`（`SettingsView.vue:59`）来自 Vite 构建期注入 —— **Web 端随每次 `npm run build` 更新**，但 Docker 镜像里的 `web/dist` 是构建期烙入的；若镜像未重建，界面角落仍显示旧版本（已修 Dockerfile 但需重新出包才生效）

## 四、P2 清单（14 条）

### 服务端
- 幂等命中时 `createdCount` 语义偏乐观
- `localToday` 依赖进程 TZ，与 billing-cycle 的 UTC 纯函数口径不一致
- WebDAV 目录拼接无路径规范化（`..` 段未拒绝）

### 安全
- WebDAV/备份口令明文落库（数据库文件等同备份密钥）
- CORS 默认放行任意 Origin（Bearer-only 下经典 CSRF 不成立，但放大 XSS 危害）
- 计划待办共享写的产品张力（设计裁决，需文档化权限矩阵）

### 客户端
- Web `pullChanges` 无 `maxPullPages` 上限（iOS/hw 有）
- iOS `applyChange` 单条抛错会误判空页停止翻页
- iOS 建表后 `migrations` 用 `try? execute` 吞错

### CI
- `VERSION_CODE` 三处独立计算不稳定
- `build-fn.mjs` sha256 校验静默跳过；fnpack 无校验
- `custom_version` 非纯数字输入不设防（当前正则兜底有效）

### 部署
- `SUENMONEY_PORT` 默认 3310 与全项目 5310 不一致（文档已如实记录）
- `fn/app/VERSION` 构建产物陈旧（2.0.0 vs 2.1.1）
- `build-fn.mjs:325` typo `--skip-fnpck`

## 七、系统性观察

1. **"备份/导入/恢复"这条边缘链路是重灾区**：3 个 P0 全在这里（CSV 导入绕过同步、轮转正则错、恢复事务外）。核心记账链路本身很扎实。
2. **"静默失败"是贯穿性主题**：CI 的死代码/并发覆盖、同步的孤儿操作、备份的永不清理 —— 都是"流程全绿但实际没生效"，用户和 CI 都发现不了。
3. **文档与实现脱节**：deploy.md 描述了已删除的 VACUUM 快照、缺 bind-mount 权限排查、CORS 语义相反、环境变量缺 6 个。文档滞后是隐患放大器。
4. **三端字段口径分叉**：iOS `bucketOf` 漏双键、Web 只应用 expense、Web update 部分字段 vs iOS/hw 整字段 —— "同名不同义"是最易悄悄错位的地方。
